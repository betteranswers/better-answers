# Outside the shell

Sign in, display name, no workspace, account, second factor, recovery, workspace picker, invitation, Claude's consent, the not-found page.

`<stamp>` is `date +%s`, taken once for this file. `<email%>` is an address with `@` written as `%40`.

## Sign in by hand

For `<address>`, client address `198.19.3.<n>` and landing page `<landing>`. Use a new `<n>` for each sign-in, because one client address may send only five codes in ten minutes. `sign-in.sh` passes through `/confirm` and `/setup` itself, so the recipes that need those pages sign in by hand.

1. `.claude/skills/verify/scripts/browse.sh <port> cookies clear`, `.claude/skills/verify/scripts/browse.sh <port> set headers '{"cf-connecting-ip":"198.19.3.<n>"}'`, `.claude/skills/verify/scripts/browse.sh <port> open http://localhost:<port>/sign-in`, `.claude/skills/verify/scripts/browse.sh <port> wait --fn "document.querySelector('input[type=email]') !== null"`, `.claude/skills/verify/scripts/browse.sh <port> find label "Email Address" fill "<address>"`, `.claude/skills/verify/scripts/browse.sh <port> find role button click --name "Send Code"`, `.claude/skills/verify/scripts/browse.sh <port> wait --text "Verification Code"`.
2. `.claude/skills/verify/scripts/harness.sh <port> GET "/codes?email=<email%>"` answers `code`. Then `.claude/skills/verify/scripts/browse.sh <port> find label "Verification Code" fill "<code>" --exact`, `.claude/skills/verify/scripts/browse.sh <port> wait --fn "location.pathname === '<landing>'"`.

Make an authenticator code from a key by running `node --input-type=module -e "import { authenticatorCodeAt } from './packages/schema/test/people/authenticator-code.ts'; console.log(authenticatorCodeAt(process.argv[1], new Date()));" <key>` as a command of its own, and type the code within the same half minute.

## A first-time person: sign-in, display-name, no-workspace, account

The address `first-<stamp>@example.test` must be one the harness never made.

1. Sign in by hand as `first-<stamp>@example.test` with `<n>` 1 and `<landing>` `/display-name`, then `.claude/skills/verify/scripts/browse.sh <port> wait --text "Your Name"`. Expect the textbox *Display Name* and the button *Save and Continue*.
2. `.claude/skills/verify/scripts/browse.sh <port> find label "Display Name" fill "Theo Approver"`, `.claude/skills/verify/scripts/browse.sh <port> find role button click --name "Save and Continue"`, `.claude/skills/verify/scripts/browse.sh <port> wait --fn "location.pathname === '/no-workspace'"`, `.claude/skills/verify/scripts/browse.sh <port> wait --text "No Workspace Yet"`. Expect the region *Ask to Join a Workspace*, the link *Account* and the button *Sign Out*.
3. `.claude/skills/verify/scripts/harness.sh <port> POST /workspaces '{"name":"Calder Joinery"}'` answers `shortName`. Then `.claude/skills/verify/scripts/browse.sh <port> find label "Workspace Short Name" fill "<shortName>"`, `.claude/skills/verify/scripts/browse.sh <port> find label "Reason" fill "I run the joinery team."`, `.claude/skills/verify/scripts/browse.sh <port> find role button click --name "Ask to Join"`, `.claude/skills/verify/scripts/browse.sh <port> wait --text "Request sent"`.
4. `.claude/skills/verify/scripts/browse.sh <port> find role link click --name "Account"`, `.claude/skills/verify/scripts/browse.sh <port> wait --fn "location.pathname === '/account'"`, `.claude/skills/verify/scripts/browse.sh <port> wait --text "No authenticator set up."`. Expect the button *Set Up an Authenticator*.
5. `.claude/skills/verify/scripts/browse.sh <port> find role button click --name "Set Up an Authenticator"`, `.claude/skills/verify/scripts/browse.sh <port> wait --text "QR code"`. Read the key printed under `Or enter this key:` in `.claude/skills/verify/scripts/browse.sh <port> snapshot` and drop its spaces. Make a code, then `.claude/skills/verify/scripts/browse.sh <port> find label "Authenticator Code" fill "<code>" --exact` (six digits submit on their own), `.claude/skills/verify/scripts/browse.sh <port> wait --text "Save Your Recovery Codes"`, `.claude/skills/verify/scripts/browse.sh <port> find role checkbox check --name "I have saved these codes"`, `.claude/skills/verify/scripts/browse.sh <port> find role button click --name "Done" --exact`, `.claude/skills/verify/scripts/browse.sh <port> wait --text "of 10 unused"`.
6. Second view: `.claude/skills/verify/scripts/browse.sh <port> reload`, `.claude/skills/verify/scripts/browse.sh <port> wait --text "Authenticator set up."`, `.claude/skills/verify/scripts/browse.sh <port> wait --text "Active now"`. Expect the region *Recovery Codes* to hold `10 of 10 unused` and the region *Sessions* to list this device.

## An Admin's first sign-in: setup

1. `.claude/skills/verify/scripts/harness.sh <port> POST /workspaces '{"name":"Skipton Setups"}'` answers `admin.email`.
2. Sign in by hand as `<admin.email>` with `<n>` 2 and `<landing>` `/setup`, then `.claude/skills/verify/scripts/browse.sh <port> wait --text "Set Up an Authenticator Instead"`. Expect the heading *Set Up a Second Factor* over the textbox *Passkey Name* and the buttons *Add a Passkey* and *Set Up an Authenticator Instead*. A passkey cannot finish here, because agent-browser has no virtual authenticator.
3. `.claude/skills/verify/scripts/browse.sh <port> find role button click --name "Set Up an Authenticator Instead"`, `.claude/skills/verify/scripts/browse.sh <port> wait --text "QR code"`. Read the key under `Or enter this key:` in `.claude/skills/verify/scripts/browse.sh <port> snapshot`, drop its spaces and make a code. `.claude/skills/verify/scripts/browse.sh <port> find label "Authenticator Code" fill "<code>" --exact`, `.claude/skills/verify/scripts/browse.sh <port> wait --text "I have saved these codes"`. Expect the region *Save Your Recovery Codes* to list ten codes, still at `/setup`.
4. `.claude/skills/verify/scripts/browse.sh <port> find role checkbox check --name "I have saved these codes"`, `.claude/skills/verify/scripts/browse.sh <port> find role button click --name "Finish Setup"`, `.claude/skills/verify/scripts/browse.sh <port> wait --fn "location.pathname === '/people/members'"`.

## An Admin holding an authenticator: confirm, recovery-codes, recovery

1. `.claude/skills/verify/scripts/harness.sh <port> POST /workspaces '{"name":"Calder Confirmations"}'` answers `admin.email`. Then `.claude/skills/verify/scripts/harness.sh <port> POST /authenticators '{"email":"<admin.email>","codes":"none"}'` answers the `key` and no recovery codes.
2. Sign in by hand as `<admin.email>` with `<n>` 3 and `<landing>` `/confirm`, then `.claude/skills/verify/scripts/browse.sh <port> wait --text "Use a Recovery Code"`. Expect the heading *Confirm It’s You* over the textbox *Authenticator Code*, the button *Confirm* and the link *Use a Recovery Code*.
3. Make a code from the `key`. `.claude/skills/verify/scripts/browse.sh <port> find label "Authenticator Code" fill "<code>" --exact`, `.claude/skills/verify/scripts/browse.sh <port> wait --fn "location.pathname === '/recovery-codes'"`, `.claude/skills/verify/scripts/browse.sh <port> wait --text "I have saved these codes"`. Expect the region *Save Your Recovery Codes* to list ten codes, which only the full `.claude/skills/verify/scripts/browse.sh <port> snapshot` shows. Note the first one.
4. `.claude/skills/verify/scripts/browse.sh <port> find role checkbox check --name "I have saved these codes"`, `.claude/skills/verify/scripts/browse.sh <port> find role button click --name "Finish Setup"`, `.claude/skills/verify/scripts/browse.sh <port> wait --fn "location.pathname === '/people/members'"`.
5. Sign in by hand as `<admin.email>` with `<n>` 4 and `<landing>` `/confirm`, then `.claude/skills/verify/scripts/browse.sh <port> wait --text "Use a Recovery Code"`.
6. `.claude/skills/verify/scripts/browse.sh <port> find role link click --name "Use a Recovery Code"`, `.claude/skills/verify/scripts/browse.sh <port> wait --fn "location.pathname === '/recovery'"`, `.claude/skills/verify/scripts/browse.sh <port> wait --text "Each code works once"`. Expect the textbox *Recovery Code* and the button *Use Code*.
7. `.claude/skills/verify/scripts/browse.sh <port> find label "Recovery Code" fill "<the first code>"`, `.claude/skills/verify/scripts/browse.sh <port> find role button click --name "Use Code"`, `.claude/skills/verify/scripts/browse.sh <port> wait --text "Set Up a New Second Factor"`. Expect `/setup`.

## A Viewer in two workspaces: choose-workspace, not-found

1. `.claude/skills/verify/scripts/harness.sh <port> POST /people '{"displayName":"Vera Viewer"}'` answers her `id` and `email`. `.claude/skills/verify/scripts/harness.sh <port> POST /workspaces '{"name":"Acme Joinery"}'` and `.claude/skills/verify/scripts/harness.sh <port> POST /workspaces '{"name":"Wharfedale Castings"}'` answer a `workspaceId` each. For each, `.claude/skills/verify/scripts/harness.sh <port> POST /members '{"workspaceId":"<workspaceId>","userId":"<her id>","role":"Viewer"}'`.
2. `.claude/skills/verify/scripts/sign-in.sh <port> <her email>` lands on `/choose-workspace`. `.claude/skills/verify/scripts/browse.sh <port> wait --text "Wharfedale Castings"`. Expect the heading *Your Workspaces* over one button for each workspace.
3. `.claude/skills/verify/scripts/browse.sh <port> find role button click --name "Wharfedale Castings"`, `.claude/skills/verify/scripts/browse.sh <port> wait --fn "location.pathname === '/ask/new-question'"`. Expect the banner's workspace button to read *Wharfedale Castings*.
4. `.claude/skills/verify/scripts/browse.sh <port> open http://localhost:<port>/no-such-page`, `.claude/skills/verify/scripts/browse.sh <port> wait --text "Page Not Found"`. Expect the link *Go to New Question*. Then `.claude/skills/verify/scripts/browse.sh <port> find role link click --name "Go to New Question"`, `.claude/skills/verify/scripts/browse.sh <port> wait --fn "location.pathname === '/ask/new-question'"`.

## An invited Editor: invitation, consent, sign-in-link

1. `.claude/skills/verify/scripts/harness.sh <port> POST /workspaces '{"name":"Holme Joinery"}'` answers `workspaceId` and `admin.id`. `.claude/skills/verify/scripts/harness.sh <port> POST /people '{"displayName":"Ines Invitee"}'` answers her `email`. `.claude/skills/verify/scripts/harness.sh <port> POST /invitations '{"workspaceId":"<workspaceId>","email":"<her email>","inviterId":"<admin.id>","role":"Editor"}'` answers the invitation's `id`.
2. `.claude/skills/verify/scripts/sign-in.sh <port> <her email> /invitations/<id>`, `.claude/skills/verify/scripts/browse.sh <port> wait --text "Join Workspace"`. Expect the heading *Your Invitation to Holme Joinery* over the button *Join Workspace*.
3. `.claude/skills/verify/scripts/browse.sh <port> find role button click --name "Join Workspace"`, `.claude/skills/verify/scripts/browse.sh <port> wait --fn "location.pathname === '/ask/new-question'"`. Expect the banner to show the buttons *Holme Joinery* and *Ines Invitee*.
4. Catch Claude's callback first, so *Connect* does not send a live code to claude.ai: `.claude/skills/verify/scripts/browse.sh <port> network route "https://claude.ai/api/mcp/auth_callback**" --body '{"caught":"the callback stayed in the browser"}'`.
5. `.claude/skills/verify/scripts/browse.sh <port> open "http://localhost:<port>/oauth2/authorize?client_id=https%3A%2F%2Fclaude.ai%2Foauth%2Fmcp-oauth-client-metadata&redirect_uri=https%3A%2F%2Fclaude.ai%2Fapi%2Fmcp%2Fauth_callback&response_type=code&code_challenge=E9Melhoa2OwvFrEMTJguCHaoeK1t8URWbuGJSstw-cM&code_challenge_method=S256&resource=http%3A%2F%2Flocalhost%3A<port>%2Fmcp&scope=knowledge%3Aread+feedback%3Awrite+offline_access&state=state-from-the-host&prompt=consent"`, `.claude/skills/verify/scripts/browse.sh <port> wait --fn "location.pathname === '/consent'"`, `.claude/skills/verify/scripts/browse.sh <port> wait --text "Claude will act as you, at Holme Joinery."`. Expect the heading *Connect Claude* over the buttons *Connect* and *Cancel*.
6. `.claude/skills/verify/scripts/browse.sh <port> find role button click --name "Connect" --exact`, `.claude/skills/verify/scripts/browse.sh <port> wait --fn "location.href.startsWith('https://claude.ai/api/mcp/auth_callback?code=')"`, `.claude/skills/verify/scripts/browse.sh <port> get url`. Expect the address to carry a `code`, the `state` `state-from-the-host` and the `iss` of this origin. Then `.claude/skills/verify/scripts/browse.sh <port> network unroute`.
7. Run step 1 of the sign in by hand as her address with `<n>` 5, then `.claude/skills/verify/scripts/harness.sh <port> GET "/links?email=<email%>"` answers `token`.
8. `.claude/skills/verify/scripts/browse.sh <port> open "http://localhost:<port>/sign-in/link#<token>"`, `.claude/skills/verify/scripts/browse.sh <port> wait --text "Signing in as"`. Expect the heading *Sign In* over the status `Signing in as <her email>.` and the button *Sign In*, and the address to drop its fragment.
9. `.claude/skills/verify/scripts/browse.sh <port> find role button click --name "Sign In" --exact`, `.claude/skills/verify/scripts/browse.sh <port> wait --fn "location.pathname === '/ask/new-question'"`.
