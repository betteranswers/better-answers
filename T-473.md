## Goal

PR #456 (27/09/2026) made Stryker run core's tests in a new order: the file that failed last time first, then the shortest (`packages/core/vitest.stryker.config.ts`). Forced run 36346460309 (`force: true`, `ceiling-minutes: 350`) then re-tested every mutant, including 202 pure-static Timeouts left stale from before #430.

Timeouts count as killed. A measured sample (shard 9, run 36342188075) found 42% of static Timeouts were hidden survivors: the whole related suite passes, but in 173–434s, past the ~420s budget. So this run's summary will list **new survivors**, mutants that went from Timeout to Survived. Each is a hypothesis until a probe answers it (`docs/agents/mutation-triage.md`).

## What to do

1. From run 36346460309's summary (core and api legs), list every new survivor with its file, line and mutator.
2. For each, run a whole-suite `pnpm mutant-probe` (no `--suite`) with both controls:
   - a positive control: a mutant the report calls Killed, which must come back `killed`;
   - a negative control: a report survivor, which must come back `survived`.

   Check that `testsCompleted` is above 0.
3. Classify each one:
   - **a real gap:** write the test that kills it, test first (`/tdd`);
   - **an equivalent mutant:** record why;
   - **a harness fault:** name it.
4. Land the killing tests in one PR per file or seam, through the queue.
