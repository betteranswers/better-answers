## Agent Brief

> *This was generated by AI during triage.*

**Category:** bug
**Summary:** Return the pane's total and its readable rows from one SQL statement.

**Current behavior (verified on main 9fdf00b7, 27/09/2026):**
`evidencePaneOf` counts the concept's `concept_evidence` rows in one statement, then selects the readable rows (evidence joined to source document and binding) in a second. `paneOf` computes `withheld = cited − readable.length` with no clamp. Transactions open with a plain `BEGIN`, so they run at READ COMMITTED, where each statement takes its own snapshot. A citation re-write that commits between the two statements can give a negative `withheld`. The pane then shows `partly-included`, and the sharer lookup, which runs only when `withheld > 0`, names nobody.

**Desired behavior:**
One statement returns both the total and the readable rows, for example a window `count(*) over ()` on the cited set with a readable flag, or a CTE, so both come from one snapshot. `paneOf`'s arithmetic is then always consistent.

**Key interfaces:**
- `evidencePaneOf`: it takes `tx` from its caller, so the act cannot raise the isolation level itself. Do not change the transaction helper or its isolation level.
- The pane's returned shape (`access`, `withheld`, rows, sharer) is unchanged.

**Out of scope:**
- A `Math.max(0, …)` clamp in place of the snapshot fix. A clamp hides the disagreement instead of removing it.
- Changing the transaction helper's isolation level anywhere.
- Wiring the pane into an api procedure. It has no caller in `apps/` yet.
