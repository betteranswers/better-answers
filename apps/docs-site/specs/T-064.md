# T-064 — Dev tooling as gates: knip, jscpd, lefthook, the oxlint gaps, the browser-suite skill and the suite's silent-pass vectors

*Spec written 5 September 2026 by /to-spec over the dev-tooling audit run in this session — knip 6.34.0 and jscpd 5.1.2 run against the tree, a throwaway test file probed against the live oxlint config, assertions counted per test across every suite, every `catch` in source read, the local Bulletproof React clone's lint config compared line by line, the Onyx Playwright skill and Dust's lefthook file read — and the owner's decisions in the same session: keep the fourteen unused registry components; lefthook in; Grit out; folder naming and error boundaries in; the throwaway-tree runner and the two oxlint plugins move to a new devtools package. Decisions recorded here are taken; do not re-open them.*

## Problem Statement

The stack and repo constitution (discovery ticket 13, 25 August 2026) locked knip and jscpd into `lint` beside oxlint. When the map became tasks they fell through: nothing in the repository names either tool, and no ticket carries them. The owner does not read code, so the tooling *is* the reviewer they rely on to catch what a session leaves behind — and today it catches less than the constitution says it does.

Run against the tree on 5 September, knip found eighteen unused files, four unused dependencies, a dev dependency listed in the wrong workspace, an unlisted one, and twenty-four unused exports; jscpd found seven clones, one of them the same twenty-line test helper written three times, only one copy of which is hardened against the very failure the copies exist to catch. Nothing reports any of it.

The test suite is honest in its tests — every one of roughly three hundred asserts, every title names behaviour, no test is skipped or focused — but five things in configuration let it go green while running less than it claims: two workspaces pass with no tests at all if a glob rots; a focused browser test would run alone in CI and pass; the root `check` silently skips any workspace that forgot its `check` script, and one has; two of the three lint-rule tests swallow a tool that failed to run into "the rule stayed silent"; and pytest tolerates a mistyped marker and a passing expected-failure.

oxlint is stronger than assumed — a probe against the live config fails a focused test, a disabled one, an assertion-free one, an unawaited async assertion, a conditional assertion and a missing hook dependency — but two identically titled tests pass, an empty `catch` in a test passes, and a floating promise passes. Playwright specs are invisible to those rules entirely.

There is no pre-commit hook, so the first word on a mistake is CI, minutes later. The browser suite's conventions — the served-build seam, the per-test client address, the harness, roles over test ids — live in the heads of the sessions that wrote them and nowhere an agent can load. Bulletproof React was adopted as the SPA's shape, and two of its enforcements never landed: kebab-case folders, and an error boundary so a throwing screen does not blank the shell.

And the two oxlint plugins — Onyx's anti-slop lift and the repository's own rules — were placed under the api workspace at setup. Nothing in the api deploys them; ADR 0029 says what is imported lives in `packages/`.

## Solution

Every tool the constitution named runs as a gate inside the one `check`, never as a report: dead code, a dropped dependency, a copied block, a focused or skipped or assertion-free test, a suite that would run nothing — each fails the branch before a reviewer sees it. A pre-commit hook answers in seconds on the file just staged, so the owner's first feedback is local. A project skill teaches the next session how this repository drives a browser, in this repository's words. The SPA gains the two Bulletproof React enforcements it lacked. Tooling that is imported moves to a package that is imported.

Every gate is *run, not remembered*: each tool and each new rule lands with a functional test that runs it over a throwaway tree and asserts where it fires and where it stays silent — the pattern three tests already use, now written once.

## User Stories

### Dead code and dependencies

1. As the owner, I want a file no code reaches to fail `check`, so that a session that leaves a stub or a superseded module behind is caught before the branch merges.
2. As the owner, I want a dependency no workspace imports to fail `check`, so that the lockfile carries only what the product uses and Renovate is not maintaining dead weight.
3. As the owner, I want a dependency used but not declared in its workspace to fail `check`, so that a workspace never works only by accident of hoisting.
4. As a build agent, I want an export nothing imports to fail `check`, so that a module's interface is exactly what its callers need and no wider ([DESIGN1]).
5. As a build agent, I want registry source under the SPA's shared UI directory treated as an entry point, so that a component ADR 0033 installed for the answer surface is never reported as dead before that surface exists.
6. As a reviewer, I want the three empty store doors held by a named, reasoned exception rather than silence, so that the day a door gains an implementation the exception is a one-line deletion.
7. As the owner, I want the findings knip makes today fixed before it becomes a gate, so that the gate starts green and the first red is a real regression.

### Copies

8. As the owner, I want a block of code copied between two files to fail `check`, so that two versions of one helper cannot drift apart the way Dust's did.
9. As a reviewer, I want every deliberate copy named in the tool's configuration with its reason, so that an exception is a decision someone can read rather than a threshold someone tuned.
10. As a build agent, I want the one helper that writes a throwaway tree and runs a tool over it written once, so that its hardening — refusing to read a tool that failed to run as a tool that stayed silent — is everyone's.

### The suite cannot pass by running less

11. As the owner, I want a workspace whose test glob matches nothing to fail, so that a renamed directory cannot turn a suite into a green nothing.
12. As the owner, I want a browser spec left focused to fail in CI, so that a session's debugging aid cannot narrow the suite to one test and report success.
13. As the owner, I want every pnpm workspace either to carry a `check` script or to be named, with a reason, in a test that fails when the list and the tree disagree, so that a new package cannot silently opt out of the gate.
14. As a build agent, I want a lint-rule test to throw when the linter could not run, so that "the rule stayed silent" is never the reading of an empty output.
15. As the worker's builder, I want a mistyped pytest marker and a passing expected-failure to fail, so that a skip cannot hide behind a typo and an xfail cannot outlive its bug.

### The oxlint gaps

16. As a build agent, I want two tests with one title to fail lint, so that a copied test cannot shadow the one it was copied from.
17. As a build agent, I want an empty `catch` to fail lint everywhere, so that a swallowed error is always a commented decision and never an accident.
18. As a build agent, I want a promise nobody awaits to fail lint where the toolchain can see it, with `void` as the sanctioned fire-and-forget, so that a navigation call is honest and a forgotten `await` is caught.
19. As a reviewer, I want each new rule proved by a throwaway-tree test, so that a rule nobody has run is never mistaken for a convention.

### Pre-commit

20. As the owner, I want a commit on `main` refused, so that the one-branch-per-task rule is held by the hook rather than by memory.
21. As a build agent, I want the files I stage formatted and linted before the commit lands, with the formatter's fixes re-staged, so that a formatting-only CI failure never happens.
22. As the worker's builder, I want staged Python formatted and linted the same way, so that the two tiers get the same first word.
23. As the owner, I want the hook to finish in seconds and run no tests, so that it is never the reason a commit is skipped with the escape hatch.
24. As anyone committing, I want the escape hatches documented at the top of the hook's own file, so that a deliberate skip is one environment variable and never a deleted hook.
25. As the owner, I want the hook installed by `pnpm install`, so that a fresh clone has it without a step to remember.

### The browser suite has a skill

26. As the next session, I want a project skill that says how this repository drives a browser — the served build over a Testcontainers Postgres, the fixture that gives each test its own client address, the harness that provisions a workspace and signs a person in with a captured code, roles and names over test ids, auto-retrying matchers over waits, axe as the accessibility gate — so that a new spec is written the way the existing ones are without reading them all first.
27. As the owner, I want the parts of Onyx's skill that fit carried and the parts that do not — storage-state global setup, a worker-user pool, visual regression, themes — named as not carried, so that a session does not reintroduce them from the donor.
28. As a build agent, I want the skill to say how to run one spec and one project, so that a debugging loop is fast.

### Bulletproof React, the remainder

29. As a build agent, I want a folder under the SPA's source that is not kebab-case to fail `check`, so that folders hold the same convention files already do.
30. As a reader of the SPA, I want a screen that throws to leave the frame, its landmarks and its navigation standing, with words that say the screen could not be shown and one action, so that one broken screen never blanks the product.
31. As a screen-reader user, I want that outcome announced, so that the failure is not a silent visual change ([A11Y1]).
32. As the owner, I want the boundary to show a Viewer nothing of the error's internals, so that a stack trace is never a reader-facing surface.

### The devtools package

33. As the owner, I want the anti-slop lift and the repository's own lint rules to live in a package that is imported rather than under the api that deploys, so that the tree says what ADR 0029 says.
34. As a build agent, I want the throwaway-tree runner exported from that package, so that the api, core and web suites import one helper and none imports another workspace's tests.
35. As a reviewer, I want the api's image to carry no tooling source, so that the runtime image is the runtime.

### The constitution

36. As the owner, I want the constitution to state that every gate is run rather than remembered and that a suite that can run nothing fails, so that the next session inherits the rule and not only the configuration.
37. As a reviewer, I want knip and jscpd named beside oxlint as gates in `check`, so that a finding from either is a rule citation and not a matter of taste.

## Implementation Decisions

**A devtools package is founded** as a workspace under `packages/`, imported and never deployed (ADR 0029). It holds two things. First, the throwaway-tree runner: write a map of paths to sources into a temporary directory, run a named tool's CLI over it, tolerate only the tool's own "I found something" exit code, re-throw any other exit with what the tool wrote to stderr, and smoke-check the reporter's output shape before any test is allowed to read a silence as "the rule stayed quiet" — the hardened shape the web workspace's lint-rule test already has, lifted rather than rewritten. Second, the two oxlint plugins — Onyx's anti-slop lift and the repository's own `better-answers` rules — moved from under the api workspace, with every reference re-pointed: the root oxlint config's plugin specifiers and ignore patterns, the formatter's ignore, Cubic's ignore, the api's TypeScript include. The anti-slop lift's third-party obligation travels with it; if no notices file exists today, one is written under the lift rule. The wiki is regenerated, not edited. The api's runtime image is unchanged in behaviour and smaller in content.

**Knip runs at the root over the pnpm workspace** as a `check` step and fails on any finding. Its configuration names the entries knip's own plugins do not infer — the api's process entry points, the SPA's mount, the e2e server and the local server the api's tests expose, the schema's scripts, the oxlint plugins — and treats **the SPA's shared UI directory as entry points**, so registry source installed under ADR 0033 and the dependencies only it imports are never reported; the configuration's comment cites the ADR and the answer-surface calibration as the reason. The worker's `uv` binary is ignored as not npm's. **Before the gate lands, today's findings are fixed**: the dead tRPC barrel in the api is deleted; the unused exports are removed where nothing names them and consumed where a test should; the Postgres container package leaves the api's dev dependencies, which the schema package's testing export already owns; the Stryker API type package is listed where the two mutation configs reference it; the three empty store doors are carried as a named exception citing ADR 0029 until a door has an implementation — exporting an empty door from the store barrel would widen an interface for nothing ([DESIGN1]); the one orphaned test fixture is deleted or referenced.

**jscpd runs at the root** as a `check` step over TypeScript, TSX and Python source and tests, at five lines or fifty tokens, with a threshold of zero so any clone fails. Its configuration is a JavaScript file, not JSON, so each exclusion carries its reason in a comment: registry source, lifts, the anti-slop lift, the generated worker schema view and the lockfiles are excluded as not ours; the caller-side reading of a Better Auth redirect in the api's test flow is named as a deliberate copy of the server-side one, because the two must be able to disagree (the reason is already in that file). The near-duplicate test set-ups the audit found are folded into helpers where they exceed eight lines and carried as inline exceptions with a reason where they do not. The three oxlint runners are replaced by the devtools runner, which removes the largest clone.

**The five silent-pass vectors are closed.** The pass-with-no-tests flag leaves the web and schema workspaces' test scripts. Playwright's configuration forbids a focused test when CI is set. The root `check` keeps its skip-if-absent behaviour, and a both-ways test ([TEST7]) names every pnpm workspace that carries no `check` script with a reason — the design system is on it today, holding tokens and guideline cards and nothing executable — and fails when the list and the tree disagree in either direction. pytest gains strict markers and strict expected-failures. The api and core lint-rule tests lose their swallowing shape with the runner.

**Three oxlint rules are added**, each with a throwaway-tree test. Identical titles fail. An empty block fails everywhere, with empty `catch` no longer allowed — a `catch` holding a comment is not empty, so the one deliberate swallow in the Postgres door keeps its comment and passes. Floating promises fail with `void` as the sanctioned fire-and-forget **if oxlint's type-aware mode is production-ready on the day it is read** ([DEPS1]); if it is not, the ticket records the gap and the rule as a follow-on rather than enabling a preview. Everything the probe showed already firing stays as it is.

**lefthook is adopted** at the version read from the registry on 5 September 2026 (2.1.12) as a root dev dependency, installed by a root `prepare` script because pnpm 11's build allow-list blocks the package's own postinstall. One hook, pre-commit, commands in parallel: refuse a commit on `main`; format staged files with the repository's formatter and re-stage the result; lint staged TypeScript with oxlint; format and lint staged Python with ruff through uv in the worker; run actionlint over workflow files when it is installed and skip with a warning when it is not. No tests and no typecheck in the hook. The file's header documents the whole-hook and per-command escape hatches. Dust's image optimisers, Rust and Swift formatters, secret scanning and frozen-migration guards are not carried.

**A browser-suite skill is written** as a project skill, with the writing-for-agents skill, describing this repository's shape: the served-build seam from [TEST1]; the fixture that issues each test a client address so the per-IP counters never couple tests; the harness's acts — provision a workspace, make a person, add and remove a member, revoke credentials, seed routes, mint an address, sign in with the captured code; roles and accessible names as the locator, test ids never; auto-retrying matchers and no timed waits; axe as the accessibility gate; one Chromium project; the web server that starts the api's harness over Testcontainers; how to run one spec; the focused-test rule. Carried from Onyx: API-first set-up with the browser reserved for the behaviour under test, parallel isolation, extracted helpers with a comment saying why. Named as not carried: storage-state global set-up, a worker-user pool, visual regression, themes. AGENTS.md's skills line names it.

**Folder naming** under the SPA's source is kebab-case, held by a test over directory names because oxlint has no folder rule; the Bulletproof exception for a tests folder is moot here, where tests live beside the source tree rather than inside it.

**The router gains a default error component** rendering inside the outlet, so the frame, its landmarks and its navigation survive a screen that throws. Its words are the glossary's and [UX1]-shaped: what happened, then one action — try the screen again, or go to System. The outcome is announced to assistive technology ([A11Y1]). Nothing of the error's internals reaches a reader. The not-found component stands. No browser-side logger exists to receive the error; that is a separate decision and not this ticket's.

**The constitution gains two rules and one sentence**, their tags settled at build against the coding-rules audit running in parallel with this spec: a rule that every gate is run rather than remembered — a lint rule, a tool in `check`, a hook command each lands with a functional test of where it fires and where it stays silent; a rule that a suite that can run nothing fails — no pass-with-no-tests, no focused test in CI, every workspace in `check` or named out of it with a reason; and, beside oxlint, knip and jscpd named as gates. [TEST6]'s line naming the web workspace for Stryker is T-009's to change, not this ticket's. AGENTS.md's layout table gains the devtools package.

**No new ADR.** Everything here enacts discovery ticket 13's lock, ADR 0029's placement rule and ADR 0033's registry decision; the knip entry-point treatment of registry source is recorded where it is configured, citing the ADR.

## Testing Decisions

A good test crosses the seam a caller does and states behaviour: for a tool, the seam is its command line over a tree; for a config, the value the config resolves to; for the boundary, the screen a reader sees. Four seams, three of them existing:

- **The root `check` command.** knip, jscpd and the workspace-coverage guard are steps of it, so CI gates them with no workflow change; the proof that a step is wired is the same test that proves the tool fires.
- **The throwaway-tree runner** in the devtools package. Every tool and every new rule is proved by a Vitest test that writes a tree, runs the tool and asserts both where it fires and where it stays silent: knip over a tree with an unused export and one with none; jscpd over a tree with a clone and one with a named exception; each oxlint rule with a firing case and a silent case; the runner's own smoke check that a tool which cannot run throws rather than returns nothing. Prior art: the three existing lint-rule tests, which this replaces.
- **Config modules read as values.** Playwright's configuration is imported and its focused-test setting asserted under CI; the two test scripts are read and asserted to carry no pass-with-no-tests flag; lefthook's file is parsed and each command's binary asserted to resolve, with the main-branch guard present; pytest's options are read. Prior art: the workflow-pins, deploy-tree and ADR-index tests, and the both-ways shape [TEST7] requires.
- **The router render seam.** The error boundary is proved by rendering a throwing screen through the app router with Testing Library and asserting the frame's landmarks remain, the words appear, the action is reachable and the region is announced; plus one browser check over the served build. Prior art: the frame test and the routes browser spec. Folder naming is a test over the SPA's directory names.

The hook itself is not run under test; its commands are proved by the tools' own tests and its wiring by the config test.

## Further Notes

**Sequencing.** Independent of the T-048 and T-006 slices in code, but it touches root configuration every branch reads, so it should land early and in small commits: the devtools package with the plugin move and the runner first, as its own commit, then each gate. `/to-tickets` will split this; the natural slices are the devtools package, knip, jscpd, the vectors and oxlint rules, lefthook, the skill, and the two SPA enforcements.

**The audit's numbers on 5 September**, for the ticket that fixes them: knip — 18 unused files (14 registry components, 3 empty store doors, 1 test fixture), 4 unused dependencies in the web workspace, 1 misplaced dev dependency in the api, 1 unlisted dependency in both mutation configs, 12 unused exports and 12 unused exported types; jscpd — 7 clones, 6 in tests. The oxlint probe showed nine rules already firing; the three gaps above are the whole difference.

**Playwright specs and the vitest rules.** The specs import `test` and `expect` from the suite's own fixture module, so oxlint's test-file detection does not see them; the focused-test setting in Playwright's config is the only fence, which is why it is a vector and not a lint change.

**lefthook and pnpm 11.** The build allow-list in the workspace file governs dependencies' lifecycle scripts, so lefthook's own hook installation never runs on install; the root `prepare` script is the wiring, and the config test proves the hook file exists and parses.

**The registry decision, for the record.** Blocks 1, 2 and 4 of the external People UI consume dialog, dropdown-menu, select, tabs, collapsible, popover and table from the fourteen; carousel, command, hover-card, the Kibo combobox and snippet, and the AI Elements sources and inline-citation have no ticket yet and are the answer surface and the command palette [UX2] promises. Once T-027 uses dialog, the lucide-react finding disappears of its own accord.

## Amendment — 2026-09-05, after the coding-rules audit

The same session audited the three `CODING_RULES.md` files against the tree (`.scratch/coding-rules-audit-2026-09-05.md`; the record is T-078 and T-079). Four of its findings sit on this spec's path and were absorbed into the slices `/to-tickets` had already cut, by the owner's decision:

- **The rule that a lint rule carries a rule line and a test** — today a JSON comment at the top of the root oxlint config, obeyed by both plugin rules — becomes the lint half of the "run, not remembered" rule (T-065).
- **The TypeScript `check` contract.** The worker's `[WRK3]` promises every step runs and one run names every failure; the four TypeScript manifests chain steps with `&&`, which stops at the first. The rule is stated once for both tiers and each workspace's `check` takes the worker's shape (T-068).
- **`[TEST3]`'s Python half becomes true rather than narrowed.** The rule bans `monkeypatch` of our own modules and claims lint enforcement that exists only for TypeScript; the owner reads the gap as an oversight of the same kind as knip and jscpd. A pytest guard refuses a patch whose target is the worker's own package and leaves third-party attributes patchable (T-068).
- **`apps/web/CODING_RULES.md` is founded** with one rule per enforcement that exists today — the zones and direction, the identity feature, filenames and folders, the type-only api seam, the error boundary — and the api tier file's preamble shrinks to a pointer at it; the fuller write-up waits for T-063's identity vocabulary (T-072).

Everything else the audit found is T-078 (the constitution sweep) and T-079 (the audit family, ahead of T-059).
