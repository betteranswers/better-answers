# T-046 — The platform's own hooks over the better-auth client

*Spec written 5 September 2026 from the T-046 ticket body, the 2026-09-03 tsconfig review (`.scratch/session-audit-2026-09-03/tsconfig-review.md` §4), ADR 0033 and its 2026-09-03 amendment, the 2026-09-05 grill that re-cut T-027, and a read of every file in the tree that names `@better-auth-ui`. The seam decision and the provider deletion were confirmed with the owner on 5 September 2026. Decisions recorded here are taken; do not re-open them.*

## Problem Statement

The SPA's auth feature is about 750 lines, and 70 of them face `@better-auth-ui/*`. For those 70 lines the workspace carries two npm packages (`@better-auth-ui/core` and `@better-auth-ui/react` at 1.7.19), a vendored registry item with three files, and two `declare module` augmentations of a library outside the auth module — and pays for them continuously. The package has shipped 66 releases since 15 April 2026, 12 of them in the 12 days before the pin, so Renovate knocks daily. Its declaration emit is broken (extensionless re-exports, T-042's upstream issue), which is the reason `apps/web` sits on `moduleResolution: "bundler"`. Its peer list demands react-email, passkey and api-key packages the product will never use, so every install prints warnings a reader has to learn to ignore. And it is a second library surface: a reviewer of the auth feature has to know better-auth-ui's hook contracts as well as `better-auth`'s own client, when the client already exposes everything the hooks wrap and TanStack Query is already the SPA's data layer (T-036).

The cost is about to compound: T-027 (the People screen) is written against the post-T-046 world. Built on better-auth-ui first, the surface grows from nine imported names to roughly fifteen, and the ticket's own stop-and-re-estimate clause trips. The order is forced: this ticket before T-027.

## Solution

The auth module writes its own thin hooks over the `better-auth` client it already constructs, as TanStack Query `queryOptions`/`mutationOptions` factories — the same shape the library's hooks had underneath, minus the library. The screens keep calling hooks with the same names, so the diff inside the module is import lines and hook-call sites, and no screen outside the module changes at all.

Everything better-auth-ui supplied dissolves into things the platform already owns. The provider goes entirely: hooks read the module's own `authClient` constant and the app's one query cache, so there is nothing left to provide and the router root mounts its outlet directly. The localisation table stops being a library `localization` parameter and becomes what it already almost is — the module's own plain word map, read directly by the screens that render its words. The two module augmentations, the vendored registry item and the orphaned plugin-type file die with the package. The dependency rows, the notices entries, the lint-fence carve-out and the `[DESIGN5]` exemption sentence all come out, and ADR 0033 gains a dated paragraph recording the reversal.

To a person signing in, nothing changes: the same two-step email code, the same picker, the same refusal, the same sign-out, the same OAuth resume — proven by the existing browser suite staying green unchanged.

## User Stories

### The person at the screens (behaviour unchanged)

1. As a person signing in, I want to enter my work email and receive a six-digit code, so that I can sign in without a password.
2. As a person who mistyped a code, I want the screen to say the code did not work, in a live region, so that I know to check it or ask for a new one.
3. As a person who asked for too many codes, I want the screen to say so in the platform's own words, so that I know to wait rather than retry.
4. As a person signing in during a host's OAuth flow, I want the carried flow to follow me to the picker, so that the authorization resumes where it should.
5. As a member of several workspaces, I want to pick one and have everything after scoped to it, so that the workspace I meant is the workspace I get.
6. As a member of exactly one workspace, I want to be carried through without seeing a picker, so that I am never asked a question with one answer.
7. As a member of no workspace, I want to land on the refused screen with sign-out as my one act, so that I am told the truth rather than shown an empty picker.
8. As a person whose pick was refused, I want the screen to say so rather than go quiet, so that I am not left at buttons that stopped working.
9. As a person whose OAuth resume answered with nowhere to go, I want to be told I am still signed in and offered the shell, so that I am not told to wait for something that will not happen.
10. As a person signing out at a shared machine, I want the session ended and the cache cleared even when the server call fails, so that the next person sees none of what I read.
11. As a screen-reader user, I want every outcome announced in a live region and every choice a named button in DOM order, so that the screens meet WCAG 2.2 AA as they did before.
12. As a person anywhere in the product, I want to read the word *workspace* and never *organization*, so that the platform speaks its own language.

### The people who carry the code

13. As a reviewer of the auth feature, I want one library surface — `better-auth`'s own client — so that reading the module requires knowing one contract, not two.
14. As a reviewer, I want the nine library-facing lines replaced by hooks I can read in the same directory, so that what a hook does is never a question about a dependency's internals.
15. As the owner watching Renovate, I want the daily-release dependency gone from the lockfile, so that the update queue stops carrying a package we use 70 lines of.
16. As a builder running `pnpm install`, I want no peer-dependency warnings for react-email, passkey or api-key, so that a clean install reads clean.
17. As a maintainer of the type setup, I want no module augmentation of any library outside the module, and none anywhere of a deleted library, so that the tree's `declare module` blocks all augment things it actually depends on.
18. As the builder of T-027, I want the module's hooks and its word map ready to extend — People's hooks beside these, People's eight keys beside these four — so that the People screen builds on platform code, not on a package it would have to grow.
19. As a reader of ADR 0033, I want the reversal recorded with its date and reason next to the amendment that took the dependency, so that the record explains itself without archaeology.
20. As a reader of the notices file, I want vendored-source entries only for source actually in the tree, so that provenance rows never name deleted files.
21. As a reader of `CODING_RULES.md`, I want the `[DESIGN5]` rule to need no exemption sentence, so that the rule is exactly its own statement: one directory owns the library on each side of the wire.
22. As any builder in the workspace, I want `pnpm check` green from the root with `exactOptionalPropertyTypes` still on in web, so that the flags T-042 restored stay restored.

## Implementation Decisions

- **The count stands at nine, and nine is the ceiling.** The imported names, enumerated from the tree on 5 September 2026: `useSession`, `useSignOut`, `useAuthPlugin`, `useOAuthContinue`, `useListOrganizations`, `useSetActiveOrganization`, `useSendVerificationOtp`, `useSignInEmailOtp`, and the `organizationPlugin` descriptor. That matches the audit's count; the ticket's stop-and-re-estimate clause does not trip.
- **Seven hooks are rebuilt; two names dissolve.** The seven that wrap client calls are rewritten as the module's own `queryOptions`/`mutationOptions` factories with thin hooks over them, keeping their names so every call site inside the module reads the same. `useAuthPlugin` existed only to reach the localisation table through the provider; its one call site reads the module's word map directly instead. `organizationPlugin` existed only to configure the provider and key `useAuthPlugin`; with both gone it has no successor.
- **Hooks close over the module's client.** The library's hooks took `authClient` as an argument; the module's hooks do not — they close over the one `authClient` constant the module already exports. Names are preserved, signatures are the module's own. All call sites are inside the module, so nothing outside it notices.
- **The provider is deleted, not shimmed.** The configuration component at the router root and the vendored provider wrapper existed to supply the client, the query cache, navigation, a Link slot and the plugin list to library hooks. The module's hooks need none of that supplied: the client is a module constant, the cache is the app's one cache reached the way every other query reaches it, and navigation stays in the screens where it already lives. The router root mounts its outlet directly. Reviewed against T-027's re-cut before deciding: People's screens are the external UI's blocks over tRPC through a members slice, and its one Better Auth touchpoint (invitation accept) is a client call, not a provider — nothing downstream expects a provider to exist.
- **The orphaned plugin-type file dies with the package.** The vendored file under the shared library directory that augments the package's plugin registry is imported by nothing in the tree; it and the provider wrapper are removed, which is also the readiness review's criterion: no augmentation of the deleted library survives anywhere.
- **The word map stays where it is and becomes plain.** The module's existing word-map file keeps its four keys and its name; it stops being passed as a plugin `localization` and is imported directly by the screens that render its words. Its docblock is updated to say the map is read directly and that T-027 adds its eight People keys beside these four — the eight are T-027's to add, not this ticket's.
- **Error shape is preserved through the mutation seam.** The sign-in screen branches on the fetch error's HTTP status (the 429 sentence). The client's calls return `{ data, error }` rather than throwing; each mutation function throws the returned error object unchanged so TanStack Query surfaces it and the screens' status checks read exactly what they read before.
- **Query keys are the module's own, and the mutations that change what a session means invalidate them.** The session and organisations queries get module-owned keys. Setting the active workspace invalidates the session and organisation queries on success. Sign-in and sign-out keep their existing whole-cache clears — those are the screens' own acts and stay in the screens.
- **The resume mutation keeps its transport behaviour.** The OAuth continue call relies on the client plugin's own request hook reading the signed query off the screen's address; the module's mutation wraps the same client call, so that behaviour rides along unchanged.
- **The records come out with the code.** The two packages leave the web app's manifest and the lockfile. The notices file loses the `auth-provider` item's provenance rows and its prose (the error-toaster paragraph included), keeping its record true to what is vendored. The `[DESIGN5]` exemption sentence leaves `CODING_RULES.md`. The lint fence's comment explaining the better-auth-ui carve-out is rewritten to the new world; no new ban glob is added, because an uninstalled package cannot be imported and the dependency's absence is the fence.
- **ADR 0033 gains a dated reversal paragraph; the README row moves with it.** The paragraph records that the provider, localisation and hooks taken on 2026-09-03 are replaced by the platform's own on 2026-09-05, and why: release cadence, broken declaration emit, peer noise, and a second library surface for 70 lines the client already covers. The one-line index row is updated in the same commit.
- **The web tsconfig stays on `bundler`, and its comment already survives the change.** The comment names better-auth-ui as the trigger but grounds the setting on what builds the app; the trigger clause is trimmed to match the new tree. `exactOptionalPropertyTypes` stays on.

## Testing Decisions

- **One seam, already built: the browser suite.** The Playwright suite in the web app's e2e directory drives the real screens against the real api — sign-in, the picker, the refusal, sign-out and the OAuth resume. The hooks are replaced beneath it and the suite is not edited; it staying green unchanged is the proof that behaviour survived the swap. This is the whole behavioural test story: the suite tests what a person does, not how a hook is wired.
- **No unit tests for the hooks.** Seven thin factories over a client the api's own suites already exercise would be tests of implementation details; the owner confirmed the browser suite is the one seam (2026-09-05).
- **The existing lint-rule test updates its probes.** The web lint-rules test asserts the import fence by probing files in and out of the auth module; its rows that name the removed package change to assert the post-removal fence, following the probe pattern already in that file.
- **The existing no-*organization*-string assertion stands untouched** and keeps proving the word map does its job with the library gone.
- **The gate is `pnpm check` from the root**, which carries lint, types and both tiers' tests, with the T-042 flags still on.

## Out of Scope

- **T-027's People screens and their eight localisation keys.** The map is shaped to receive them; adding them is T-027's acceptance criterion.
- **The T-028 re-cut.** The contradiction with its adminPlugin-screens criterion is resolved by re-cutting T-028, per the 2026-09-05 grill — nothing here touches it.
- **The members tRPC slice and the invitation-accept page** — T-027's, on T-048's tables.
- **Moving `apps/web` back to `nodenext`.** The `bundler` setting stands on the app's own grounds (nothing in web is emitted); removing the package that triggered it does not reopen the resolution decision.
- **The upstream declaration-emit issue** — already filed under T-042; nothing further to do.
- **Any change to the api tier or to `better-auth` itself.** The server side of `[DESIGN5]` is untouched.
