# T-004 — Identity and the MCP surface

*Spec written retrospectively on 2 September 2026, after PR #7 merged. It is the spec that should have preceded the build, reconstructed from the T-004 ticket body, the four grilling rounds of 1 September (twelve owner decisions), the pre-build gate briefing (ticket 79, §7), research 80 and prototype 61, the builder's design notes, and the PR body's acceptance map. Where the build substituted a mechanism for the one the ticket named, this spec records the substitute as the decision and says so. The last section is the review record: what the five Cubic rounds rejected or deferred, and where each now lives. Decisions recorded here are taken; do not re-open them.*

## Problem Statement

Before T-004, the platform had a database with tenant isolation (T-003) and nothing that could reach it as a person. There was no notion of who a call was made as, no way for a Claude host to connect, and no surface for it to call. Every design document assumed a Principal built from a verified credential and passed as the first parameter of every function that touches tenant data, and none existed. The MCP approach had been settled (T-019, ADR 0030) but not built, and prototype 61 had shown that connecting the real claude.ai host involves three silent configuration traps that a build without a conformance test would fall into again.

The owner's constraint is one identity, many memberships: a person signs in once, may belong to several workspaces, and picks one before consent, so that a token carries exactly one workspace and nothing above the database ever has to guess. The platform must be its own authorization server, in process, because a second server is a second thing to deploy, back up and drill, and the deploy unit is two 4 GB boxes run by one non-technical operator.

## Solution

Better Auth runs inside the Hono app as an OAuth 2.1 authorization server. A Claude host discovers the platform through a hand-written protected-resource document, identifies itself with a client-ID metadata document rather than registering, and walks a person through three plain server-rendered pages: an emailed six-digit code, a workspace picker for a person in more than one workspace, and consent that names the client's real address. The token it receives names one workspace and one person.

Every call then passes through one resolver: the token's claims become a Principal only inside a transaction that has set the row-level-security scope, read the member row and checked the person's revocation instant. A failed resolve is a refusal, never a default role, and nothing holds a Principal past the transaction. The same resolver serves a cookie session, so the browser and the host are one identity.

The MCP surface is four host-agnostic entries, `find`, `ask`, `open` and `give_feedback`, behind one fetch-shaped seam, each carrying its annotations, none taking a workspace argument, served in both protocol eras until every host on the conformance list has been seen to speak the newer one. Rate limits are Postgres counters, one per token and one per client address in front of everything unauthenticated. Workspaces are provisioned by the platform, never created by a person. Every sign-in, pick, consent, issue, refresh and revocation writes a structured log line with the audit fields.

## User Stories

### Connecting a host

1. As a Claude host, I want to discover the platform's authorization server from the URL a person typed, so that connecting needs no configuration beyond that URL.
2. As a Claude host, I want to identify myself by my own public metadata document, so that no registration step or pre-shared secret stands between the person and the connection.
3. As a Claude host running the 2025 protocol era, I want the surface to answer me, so that a person on an older client is not locked out.
4. As a Claude host running the 2026 era, I want `server/discover` answered with the version and the tools capability, so that I can use the newer negotiation.
5. As a Claude host, I want an unauthenticated call answered with a 401 and a challenge naming the whole surface's scopes, so that I can start the flow with the right request.
6. As a Claude host, I want `tools/list` to carry a real TTL and a private cache scope, in a fixed order, so that I cache it correctly and a person sees the same list every time.
7. As a Claude host, I want my refresh token to rotate and live ninety days sliding, so that a person authorises once and is silently refreshed until they disconnect.

### Signing in and choosing a workspace

8. As a person connecting a host, I want to sign in with a code sent to my work email, so that I need no password.
9. As a person in exactly one workspace, I want to reach consent without seeing a picker, so that I am not asked a question with one answer.
10. As a person in several workspaces, I want to pick one before consent, so that the token I grant names exactly the workspace I meant.
11. As a person in no workspace, I want the picker to refuse and mint nothing, so that a sign-in alone grants no access.
12. As a person at the consent page, I want to see the client's real address beside its self-declared name, and a line saying what "stay connected" means, so that a look-alike client cannot phish my consent.
13. As a person, I want the sign-in, picker and consent forms to refuse a submission from another site even when my cookie is present, so that a page I did not open cannot consent for me.
14. As a person, I want those pages to refuse to be framed by another site, so that a click on someone else's page is not a click on mine.

### Being a principal

15. As a workspace member, I want my role read from the member row in the same transaction as the work it authorises, so that a role change takes effect on my next call.
16. As a workspace Admin, I want a person's credentials revoked as one act that refuses every token issued before the instant, ends their browser sessions and revokes their refresh tokens, so that revocation means what it says.
17. As a workspace Admin, I want a token whose role claim disagrees with the member row refused, so that a stale or forged claim cannot outrank the row.
18. As a person, I want a credential naming a workspace I do not belong to refused, so that membership is the only door.
19. As a person who has signed in on the web, I want the same identity to answer as my session and as my host's token, so that there is one me.
20. As a member of one workspace, I want my calls unable to reach another workspace's rows, so that the identity set's global tables do not weaken the tenant boundary.

### Using the surface

21. As a workspace member on a Claude host, I want four entries that need no workspace argument, so that the token decides the scope and I cannot name the wrong one.
22. As a workspace member, I want every entry to declare whether it reads or writes, so that my host can ask me before the one write and not before the reads.
23. As a workspace member, I want `open` to return the concept's fields as structured content with the human rendering derived from them, so that a host can build a view and a person can read the same thing.
24. As a workspace member holding a read-only token, I want `give_feedback` absent from my list and refused if called, so that scope is enforced, not advertised.
25. As a workspace member, I want the map's state and the trust words rendered in every answer, so that I know what the answer was checked against.

### Being protected

26. As the operator, I want unauthenticated traffic to `/oauth2/*`, the pages and `/mcp` limited per client address, keyed on the one header the tunnel sets, so that a spoofed forwarding header cannot rotate around the limit.
27. As the operator, I want every token limited per window in Postgres, with a one-sentence 429 and a `Retry-After`, so that one host cannot starve the box.
28. As the operator, I want the counter tables unable to become the load they shed, so that a flood does not write the write-ahead log.
29. As the operator, I want the client-metadata fetcher to refuse private, loopback, link-local and carrier-grade addresses after resolution, to follow no redirect, and to cap time and size, so that a metadata URL cannot reach the estate's own network.
30. As the operator, I want the worker's database role unable to read or write the identity set, so that a compromised worker cannot mint or enumerate identities.
31. As the operator, I want `/health` to say when the authorization server failed to start, so that a box that cannot sign anyone in is not reported healthy.
32. As the operator, I want the email-code endpoints limited per address and per email, so that a code cannot be brute-forced or a mailbox flooded.

### Auditing and provisioning

33. As the operator, I want workspaces provisioned by the platform in one transaction that creates the partition, the first Admin and the config row, so that a half-made workspace cannot exist.
34. As a signed-in person, I want Better Auth's own create-organisation endpoint refused, so that self-serve creation is a later flag and not today's default.
35. As the audit slice's builder, I want sign-in, pick, consent, issue, refresh and revocation logged with principal, workspace, client id and outcome, and never a secret, so that audit records can be derived without a second instrumentation pass.
36. As the reader of the glossary, I want the database and the code to say *workspace* where Better Auth says organisation, so that one word means one thing.

### Building and reviewing

37. As a builder, I want a lint rule that refuses an entry without annotations and a lint rule that refuses a workspace argument, so that the two invariants cannot regress by omission.
38. As a builder, I want the RLS coverage test to name the identity set as its exemption and check the list both ways, so that a new global table is a visible diff and not a silent leak.
39. As a builder, I want the CIMD Node fix carried as a lift with its notice and a removal condition, so that the platform does not wait for an upstream release and knows when to stop carrying it.
40. As a builder, I want research 80's host-agnostic conformance test and prototype 61's three traps as tests, so that the real host connects on the first try after every change.
41. As a builder, I want no MCP library type to cross into the core package, enforced by lint, so that the library choice stays reversible.

## Implementation Decisions

### The Principal resolver, the deep module

One function at the Postgres store door: `withPrincipal(door, claims, work)`. Claims are the reduced form of either credential: the workspace id, the user id, the issue instant, and a role only where the credential carries one. Inside, one transaction sets the RLS scope to the claimed workspace, reads the member row and the user's revocation instant, and only then runs the caller's work with a Principal whose lifetime is the transaction. Refusals are four: not a member, credentials revoked, role disagrees, no such user. Every refusal rolls back. The Principal reserves a `groups` field, returned empty until T-006's audience work fills it (grilling Q7). The shape that came from the design notes:

```ts
type Claims = {
  workspaceId: string; userId: string; issuedAt: Date; role?: Role;
};
type PrincipalRefusal =
  | "not-a-member" | "credentials-revoked" | "role-disagrees" | "no-such-user";
withPrincipal<T>(door, claims: Claims, work: (principal, tx) => Promise<T>)
  : Promise<Result<T, PrincipalRefusal>>
```

Why a wrapper and not a resolver that returns a Principal: a returned Principal invites the caller to hold it past the transaction; the wrapper makes the transaction the Principal's lifetime by construction. Nothing above the door knows Better Auth's tables.

### Two credential paths, one resolver (grilling Q4)

The OAuth bearer is verified in process with jose against Better Auth's JWKS: signature, issuer, audience equal to the MCP URL exactly, expiry, the required scope; algorithm confusion refused. The cookie session is read through Better Auth and reduced to the same Claims. Both go through `withPrincipal`. The personal token (ADR 0018) is not built; the resolver already accepts a role claim and refuses disagreement, and the Account page's ticket mints it. Agent-auth, the Better Auth team's separate outbound protocol, is out of scope: no Anthropic client speaks it and its server half would be the second server ADR 0018 forbids.

### The identity set, isolated by key not by scope (grilling Q3; ADR 0009 amended 2026-09-01)

Sixteen Better Auth tables are global: no workspace column, no policy. Better Auth's organisation model is mapped onto the `workspace` table, which loses its RLS in a migration; `organizationId` becomes `workspaceId` on member, invitation and session through field mapping, so the database speaks the glossary's word. The reason is structural: the picker must read a workspace's name before any scope exists, and the membership read is what establishes the scope. The exemption is declared once as a named constant, the RLS coverage test takes it as its list and checks both directions, `[DESIGN4]` gains the sentence, and the `CONTEXT.md` *workspace* entry reads "every tenant row" with the identity-set clause. The worker's role is revoked on every identity table and both counters, keeping only reads of workspace and its config.

### Better Auth in process, CIMD only, no registration

The oauth-provider and cimd plugins, with a hand-written protected-resource document whose `resource` is the URL exactly as typed, served at both paths; the `@better-auth/mcp` package is not used. Dynamic registration stays off and the test asserts no registration endpoint. The `client (connected)` glossary entry is amended: no registration, but the platform caches each client's metadata document as a row with the scopes it may request, which is what prototype 61's first trap turned on. Better Auth's Node transport bug is carried as a lift with its third-party notice and a removal condition naming the upstream fix.

### The three pages, plain and server-rendered (grilling Q5)

Email code, workspace picker and consent are Hono routes rendering plain HTML, to be replaced by the SPA's screens in T-022 (which has since moved sign-in and the picker into the SPA and kept consent server-rendered on `mcp.`). A person in one workspace never sees the picker: the active workspace is set by the session-creation hook, with a sole-membership fallback for a session made before the membership existed. The three POSTs are same-origin only with the browser's Origin carried through to Better Auth's in-process call; clickjacking is refused by frame-ancestors and X-Frame-Options. The consent page shows the client id's hostname and the redirect hostname beside the self-declared name and says to cancel if unexpected.

### The MCP surface behind one seam (ADR 0030)

Mounted in Hono as a `(Request, { authInfo }) => Response` handler with authentication before it. Per request: a request with no bearer or a malformed one pays the per-address counter first; a well-formed bearer is verified; the Principal is resolved once in a short transaction that also counts the call against the token and reads the workspace's `tools/list` TTL; every `tools/call` then resolves again with its read. Four entries in one fixed order, registered only where the token holds every scope the entry names; `knowledge:read` is the surface's prerequisite and `give_feedback` needs `feedback:write` too. Each entry carries annotations; a lint rule and a functional test refuse one without. No entry takes a workspace, bundle or tenant argument; a second lint rule and an emitted-schema test refuse one. Both protocol eras are served on the SDK's stateless legacy mode; the move to 2026-only is conditioned on `server/discover` observed from every host on the conformance list, never on a date. No concept is served as a resource; capabilities are tools only. No MCP library type crosses into the core package, enforced by a lint override with a functional test.

### `open` is structured; the answer is one contract

`open` takes an IRI or a locator, exactly one, and returns the concept's frontmatter, body, relations, trust state and evidence as fields, with the human rendering derived from them. The answer contract is verdict first (`ok`, `warn`, `refuse`), citations, conflicts, coverage, unmapped passages and the map's state; refusal carries one sentence. Trust is tier, status and checked-by, rendered in the glossary's fixed words with its two riders. The entries' bodies answer an empty estate; their substance is B9's.

### Rate limits, three counters, all in Postgres

An ingress counter, global and unlogged, keyed by scope, client address and window, in front of `/oauth2/*`, discovery (`/.well-known/*` and `/jwks`), the three pages and `/mcp`, plus the per-email send throttle on the sign-in page. A per-token counter, tenant-scoped and unlogged, incremented inside the call's transaction, answering 429 with one sentence and a `Retry-After` to every method (ADR 0018's rate counter; the answer-spend ceiling at which only `ask` refuses is B9's). Better Auth's own limiter is database-backed with per-address rules on the email-code endpoints; it is per address per path only, so the per-email throttle is the platform's. Each consume sweeps the key's expired windows in the same statement. Client address is read from `CF-Connecting-IP` alone, one exported constant, with a spoofed `X-Forwarded-For` ignored (grilling Q8); IPv6 is keyed by its `/64` after canonicalisation. The tunnel is the sole ingress and no host port is published.

### The SSRF policy in the transport itself

In the same code that replaces Node's lookup: https only, the resolved address refused if private, loopback, link-local or carrier-grade, no redirect followed (so the re-check-after-redirect requirement is met by a cap of zero), a ten-second deadline that the resolver also runs under, a 64 KB response cap, a bounded per-host cache, and a bound on in-flight resolutions with the excess refused at once.

### Revocation as one act (grilling Q6)

`revokeCredentials` in the workspaces slice: writes the instant, never moving it backwards, ends every session created before it and revokes every refresh and access token minted before it, in one transaction returning a Result. The resolver refuses any credential issued before the instant and any role claim disagreeing with the member row. Consent re-resolves the session through the resolver, so a revoked person cannot mint a code. The People screen will call the act; until then the tests do.

### Workspaces are platform-provisioned (grilling Q11; judgement call 1)

`provisionWorkspace` in the core workspaces slice is one transaction: the row, the scope, the partition through the one definer function, the first Admin, the config row, tested to leave nothing behind on failure. Better Auth's create endpoint is closed to people. The ticket asked for the after-create hook to call the partition function inside the creating transaction; Better Auth's route runs no transaction and its hook receives no handle, so the atomic act is the platform's and the hook is wired to the same partition step for the day self-serve is flipped. The hook runs as a platform principal.

### Roles through the organisation plugin's access control

Admin, Editor and Viewer defined through Better Auth's access control with Admin as the creator role and the plugin's owner, admin and member defaults not registered. Because the plugin merges its defaults into the map regardless, the fence is a database CHECK on `member.role` and `invitation.role`, and before-hooks that refuse a foreign role. Invitations are refused with a not-implemented answer until T-027 ships the accept page. Every unscoped store-door call carries a platform principal as its first parameter.

### Audit logs now, audit records later (grilling Q12)

Better Auth's after-hooks emit sign-in, workspace pick, consent, token issue, refresh and revocation as structured log lines carrying principal, workspace, client id, outcome and the token id where one exists (a revoked refresh token is opaque and hashed, so revocation threads by client and principal). A test asserts the fields and that no secret appears.

### Configuration and the deploy unit

Bootstrap is split: `migrate` needs the database alone; the app additionally needs `PUBLIC_URL`, an https origin with no path, query, fragment or credentials, which is the `mcp.` origin the authorization server issues from, and `AUTH_SECRET`. `/health` reports the authorization server's state and answers 503 until it is ready or if it failed. The `tools/list` TTL is a per-workspace config row seeded by provisioning with one exported default. `exactOptionalPropertyTypes` is off in the api alone because the oauth-provider plugin's type fails under it, with the reason and re-check trigger recorded in the tsconfig.

### The auth module boundary

`better-auth` and its packages are importable only under the auth folder and the lift; a repo-wide import restriction refuses them elsewhere with a functional lint test. The auth module exports the instance factory, the bearer verifier, the session-to-claims reader, the constants and the three pages' routes.

### Sequence and residuals

Built on T-003's substrate; unblocked by T-019. Residuals routed at merge: the email transport, the compose env and the first workspace's provisioning to T-005; groups to T-006; the entries' bodies and the answer-spend ceiling to B9; the invitation accept page and the per-role surface to T-027; the personal token to the Account page's ticket; the CIMD allow-list and per-client `offline_access` to ADR 0009's 2026-09-02 amendment, landing with T-005.

## Testing Decisions

A good test here drives a real host's request shape through the real server against a real Postgres and asserts the wire and the log, never the internals: what a host sees, what a person sees, what a refused caller does not see. Every refusal is a named test (T-025's rule).

### Seams, highest first

- **The HTTP harness.** One `TestApp` that starts the server over a Testcontainers Postgres, with `provision()` and `addMember()` as the two-workspace factory and a client that carries cookies. Research 80 §9's conformance assertions and prototype 61's three traps run here, replaying claude.ai's captured requests through all three pages. This is the highest seam and the one every later ticket reuses.
- **The MCP handler seam.** The fetch-shaped handler is called directly for the era and entry tests, so the protocol is proven without a socket.
- **The core store tests.** `withPrincipal`'s six refusals and behaviours, `revokeCredentials`, `provisionWorkspace`, the counters and the renderings, each through the door against a migrated database in a rolled-back transaction.
- **The schema tests.** The RLS coverage test with the identity set as its two-way exemption; the worker role's refusal on every identity table; `UNLOGGED` asserted on both counters; the role CHECKs.
- **The lint rules.** Each custom rule has a functional test that feeds it the case it must refuse and the case it must allow, so a rule that fails open is a failing test.
- **The lift's transport.** Its SSRF policy, deadline, cache bound and refusal paths tested at the transport's own interface with a controlled lookup.

### Prior art

- T-003's RLS tests and the migrated-Postgres harness in the schema package.
- Prototype 61's captured claude.ai flow, carried as the test fixture.
- T-025's refusal-path rule and single-sourced pins.

## Further Notes

### Judgement calls the build recorded

Eleven, all in the PR body and accepted at merge: the after-create hook is not the atomic act; `exactOptionalPropertyTypes` off in the api alone; the organisation id renamed through field mapping; the per-token counter runs before the handler per HTTP request; `/me` added as the cookie path's testable surface; sign-up by email code stays open because a user row alone grants nothing; consent and continue go through Better Auth's handler in process; CIMD only; `workspace_config` is a tenant table; `[DESIGN4]` gains the exemption sentence; `https://claude.ai` removed from trusted origins.

### The review record

Five Cubic rounds (40, 27, 8, 6, 0 findings), a `/security-review` that found and fixed CSRF on the three forms, a two-axis `/code-review`, and an independent `[SEC3]` pass that fixed consent phishing via self-asserted client identity. Of the findings, 71 were applied, 4 rejected and 4 deferred. Cubic's `get_pr_issues` on PR #7 returns all 34 threads still open on 2 September and the repository has no learnings, because the PR predates the review loop in `docs/agents/code-review.md`. Each of the eight is placed here; `T-031` is the act of recording the statuses on the threads.

**Rejected, each `intended_behavior` with its citation:**

- The identity-set exemption lets the app role read identity rows without a scope (`56bc0d43`). Refused by ADR 0009's 2026-09-01 amendment: isolated by key, the picker must read a name before a scope exists.
- The authorization server and the MCP endpoint should be separate hosts (`a1179be0`). Refused by ADR 0022: `mcp.` carries `/mcp`, discovery and `/oauth2/*`; the separation is from `app.`, which the tunnel supplies.
- `find` and `open` should keep working at the ceiling (`e9e9177e`). Refused by ADR 0018 line 25: the rate counter answers 429 to every method; the answer-spend ceiling is B9's.
- The counter key export exists only for the test (`eddbaa4b`). Refused: the key an address becomes is the module's seam and its contract test belongs there.

**Deferred, each now placed:**

- The in-process hostname router (`987e5743`): Better Auth's handler answers the wildcard on every hostname, the api reads no hostname, and T-005 carried no line. Now `T-030`, after T-022.
- Per-role per-verb coverage of the plugin's member and invitation endpoints (`eb8ca96c`): a line on `T-027`.
- Revocation on the plugin's organisation endpoints (`94525b53`): the sessions half was applied, since `revokeCredentials` ends every session before the instant and the plugin consults the member row on every call; `T-027` gains the test showing a revoked session refused on invite, role change and removal.
- The flood gate before signature work (`55973bef`): half applied, the other half won't-fix. A well-formed bearer costs one in-process signature check against a JWKS read from the database, the counter is charged on every failure, and charging valid traffic on the unauthenticated counter would rate-limit a shared Cloudflare egress.

### Versions pinned at the build

Better Auth 1.7.2 and its plugins, the MCP server SDK 2.0.0 (the Hono package deliberately not taken), jose 6.2.10, all read from the registry on 1 September 2026 under `[DEPS1]`. Root check at merge: 166 schema, 32 core and 101 api TypeScript tests, 4 Python.
