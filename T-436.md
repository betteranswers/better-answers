## Goal

One workspace's git failure during a reconciler pass becomes that workspace's own failed outcome. Every later workspace in the pass is still reconciled.

## Acceptance Criteria

- [x] A test that fails before the fix: a pass over two or more workspaces, one of whose repositories makes the commit scan fail after its `rev-parse` has succeeded (e.g. a missing object), gives that workspace `{ ok: false, error: Error }` and reconciles every other workspace to `ok`.
- [x] The existing test "reconciles every workspace, each on its own outcome" still passes; its `no-such-repository` case is unchanged.
- [x] `reconcileEveryWorkspace` never rejects because of one workspace's git error.
- [x] `check` green, on the pull request and in the merge queue.

## Agent Brief

> *This was generated by AI during triage.*

**Category:** bug
**Summary:** Catch the commit scan's git throw inside the per-workspace reconcile, so it becomes that workspace's outcome.

**Current behavior (verified on main 9fdf00b7, 27/09/2026):**
The per-workspace reconcile reads its watermark through `attempt`, then calls `commitsAfter`. `commitsAfter` catches its `rev-parse` and `merge-base` failures but not the `rev-list` call, and the repository lock rethrows. `reconcileEveryWorkspace` has no guard around its loop, so the throw escapes the whole pass. The api's tick catches it at the very top, logs "the reconciler tick failed" and returns `fail`, so every workspace after the broken one waits for the next tick. It is skipped on every tick for as long as the broken repository stays broken.

**Desired behavior:**
A git error while scanning one workspace's commits is returned as `err(Error)` in that workspace's `WorkspaceReconciled.outcome`. The loop goes on to the next workspace. `outcome` is already typed `Result<Reconciled, ReconcileRefusal | Error>`, so no type change is needed.

**Key interfaces:**
- `commitsAfter` in the git store door: either it returns the `rev-list` failure as a `Result`, as it already does for `rev-parse`/`merge-base`, or its call site wraps it in `attempt`. Follow `[TYPES6]`: catch only around the library, and route the throw through `normalizeError`.
- The reconciler's own `attempt(...)` then `if (!x.ok) return err(x.error)` sites are the pattern to copy.

**Tests:** these are real-git, real-Postgres tests; there is no fake git door. Use `arrange()` and `doorsOf()` from the workspace-with-bundle test helper, and the repository-breaking helpers in the bundle test helper (`removeRepository`, `divergeHistory`, `emptyRootCommit`), adding one if none leaves `rev-parse` working while `rev-list` fails.

**Out of scope:**
- Changing the api's tick, its log line or its `fail` outcome.
- Retrying a failed workspace within the same pass.
- Any other unguarded call in the reconciler that the sweep did not name.
