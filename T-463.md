## Goal

*No workspace yet* tells a person what they can do next. It says that connecting Claude waits until they have joined, when they came from Claude. It shows any invitation waiting for them, which is the quickest way in. Today it shows only the ask-to-join form, to everyone.

## Acceptance Criteria

- [x] Reached from a Claude connection (a carried, signed OAuth query), the screen shows, from the SPA's word table: "Claude can connect once you've joined a workspace. When you're in, connect again from Claude."
- [x] Reached any other way, that line is absent.
- [x] The workspace picker's redirect to *No workspace yet* keeps the carried query, as the sign-in and display-name redirects already do.
- [x] A person with an open invitation (addressed to them, not expired, not accepted) sees it on the screen: the workspace it is for and a way to accept it, through the existing invitation page and its `acceptInvitation` act. With none, nothing about invitations shows. The ask-to-join form stays in both cases.
- [x] Accepting from this screen while a carried Claude query is still live continues to Claude's consent with that query. With no live query, the accept lands where it does today.
- [x] Specs cover: arrival from Claude with no invitation; an ordinary arrival with no invitation; an arrival with an open invitation; and an arrival from Claude with an open invitation, accepted inside the query's life, reaching consent. Every sentence and heading is read from the SPA's tables, and the two specs that type "No workspace yet" as a literal read `NO_WORKSPACE_HEADING` instead.
- [x] The accessibility gate is green on each state.
- [x] `check` green, on the pull request and in the merge queue.

## Agent Brief

> *This was generated by AI during triage.*

**Category:** bug
**Summary:** Carry the Claude query to *No workspace yet*, say that Claude connects after joining, and surface a waiting invitation there.

**Verified behaviour (main 9fdf00b7, 27/09/2026):**
- **The Claude request is a signed query, not a stored row.**
  - Better Auth's oauth-provider (1.7.5) signs it with `exp` = issue time + `codeExpiresIn`, default **600 s**, which this repo does not override.
  - Consent refuses with `set_workspace` when the person has no active workspace.
  - The token verifier refuses a bearer that names no workspace.
  - So a person with no workspace cannot finish connecting, and nothing resumes the request later. Neither the `access_request` row nor the invitation email carries the query.
- **Where the query is lost.** The SPA recognises the query through its carried-flow helpers (`carriedFlow` / `carriedOnTo` → `"connecting"`), and keeps it through `/sign-in` and `/display-name`. The workspace picker drops it when it redirects a person with no workspaces to `/no-workspace`.
- **What the screen shows.** Only a heading, `AskToJoin` and sign-out.
- **Who reaches it.** Membership is only the `member` row, so the screen is reached by:
  - a new person;
  - a person an Admin removed, or who was erased;
  - a person whose only workspace was refused at the pick;
  - a person with an invitation they haven't accepted;
  - a person whose request is waiting.
- **Invitations.** Accepting one inserts the membership and sets the session's active workspace, then navigates to `/`. An invitation lasts seven days.

**Key interfaces:**
- The carried-flow helpers and the picker's redirect.
- The no-workspace words table, where the new line and the invitation words go.
- A person-facing read of their own open invitations. The `person` router today has `invitation` (one invitation, by id) and `acceptInvitation`. Add a read of the signed-in person's open invitations if none exists. ADR 0009 keeps the organisation plugin's reads, so its list of a user's invitations is admissible. Core owns the act, and the api stays a transport.
- The accept path's redirect: when a live carried query exists, continue it to consent instead of `/`.

**Out of scope:**
- **Showing that a request to join is waiting.** ADR 0038 answers an access request *neutrally*, the same whether the slug resolves, is unknown, is already a membership or is already waiting, "so the surface can never enumerate workspaces or memberships". Showing a person their waiting requests would name workspaces that exist, so it needs a new ADR, not this ticket. The existing "Request sent" acknowledgement stands.
- Storing the Claude request so that it survives beyond its 600 s, or changing `codeExpiresIn`.
- Consent without a workspace.
- The api's server-rendered pages.
