# The graph is plain Postgres tables under RLS — and the database substrate is one journal, one role seam, one definer function

`T-003`'s pre-build grilling (2026-09-01) put the database task to three independent reviews: a staff-engineer review of the settled decisions against industry practice, a survey of Dust's public codebase, and a clean-context review of schema ownership. One decision was overturned — **Apache AGE is not adopted** — and its removal shrank three others, which is why this is one ADR rather than four: the pre-build gate's blocking fault came from one design living in two documents, and the *graph is application data* amendment already chose one document over four for exactly this cluster.

**The graph is two ordinary tenant tables** — `graph_node` and `graph_edge` in the platform Postgres — under the same `withRLS()`, `workspace_id` column and visibility columns as every other tenant table, traversed by prepared recursive-CTE templates in the one graph query module per tier, depth capped at 4 by the template. This is ADR 0023's own named fallback, promoted to the decision.

## Why AGE fell: the two deviations were one

The staff-engineer review found exactly two elements of the estate outside the standard multi-tenant-Postgres pattern (single database, RLS, per-transaction GUC, non-owner runtime role, list partitioning — which Supabase, Crunchy Data and AWS's SaaS-factory material all document at this scale): the per-workspace worker roles, and AGE itself. They are not two bets. AGE stores each workspace's graph as its own Postgres *schema*; row-level security guards rows, not schemas; the only per-schema control Postgres offers is a role's `USAGE` grant — so isolating fifty graphs required fifty roles. The role machinery was AGE's induced cost, not a decision of its own.

And the design had already stripped away what a graph engine is for: entry by key only, no graph-side index as a retrieval route, five named edge types, every statement a prepared template, depth ≤ 4, graphs of tens of megabytes. A small fixed set of templates over a tiny graph is precisely the case where hand-written SQL is cheap and Cypher earns least. What AGE's removal deletes, before any of it was built: the per-workspace role creation, membership grants and `pg_dumpall --roles-only` backup consequence; the string-built graph name with its regex allowlist and lint rule (the gate's "one isolation control" finding closes because RLS now covers the graph); the `agtype` parser in both tiers; the label-table DDL that produced the gate's blocking finding; the custom Postgres image; and the `T-007` spike. Dust's evidence points the same way from the other side: no database-level graph engine, and their reference architecture never puts per-tenant objects in the catalogue.

Sequencing forced the decision now rather than after a spike: `T-003` would have built the AGE DDL, roles and image *before* `T-007` could run the spike that might kill them — building the machine and then deleting it, the pattern the gate's Q4 existed to avoid. The owner chose removal over a decide-first spike on the simplicity mantra; the spike's only remaining question (traversal cost) is answered by the staff review's assessment that recursive CTEs at this depth and size are unremarkable, and is confirmed cheaply by an ordinary functional test when the graph slice lands.

## What stands from ADR 0023, expressed as columns

Everything in the *graph is application data* amendment except the engine. `workspace_id` on every node and edge is now an RLS'd column, not a property beside a schema boundary. The three visibility terms are columns on `graph_node` and `graph_edge` as they are on every readable unit. `gen` is a column; generations exist for full rebuilds only; the delta joins the app's commit transaction; rebuild-equivalence and the nightly second-parser audit remain the two fences. Keys are never text — the unique indexes carry over as `(workspace_id, gen, uid)` on the bundle-and-record rows and `(workspace_id, uid)` on source entities, with the label now a closed `label` column (`Concept`, `Section`, `Source`, `Actor`, `Composition`, `Evidence`, `CanonicalEntity`; prefixed source-entity labels) and `kind` a property column, indexed. `LINKS_TO` with `from_kind`/`to_kind`/`section`/`sentence`, the named edges, canonical entities, the `Person` floor, the two-level synchronous class recompute: unchanged. The full rebuild is the worker's (ADR 0031) and is still not a predicate read.

## The substrate: what the grilling settled

- **One migration journal.** Drizzle's journal in `packages/schema` is the sole schema stamp: Drizzle *generates* migrations for `public`'s tables and *carries* hand-written SQL migrations (`drizzle-kit generate --custom`) for the `index` schema, extensions, RLS policies, SQL functions and graph tables — which is where `contracts/`' README already says the tier-contract SQL functions land. `[WRK1]`'s check against `__drizzle_migrations` therefore covers everything the worker touches. A CI check asserts generated migrations never touch `index` or the graph tables.
- **One role seam.** `app_rt` and **one** worker login role, both non-owner under `FORCE ROW LEVEL SECURITY`, both scoped by `SET LOCAL app.workspace_id`. Every tenant-table policy calls one migration-installed function, `current_workspace_id()` (`LANGUAGE sql STABLE PARALLEL SAFE`), written into policies as `(SELECT current_workspace_id())` so bulk writes pay it once per statement. A missing scope is an empty GUC is zero rows. `T-015`'s coverage check asserts every tenant policy uses the seam.
- **One definer function.** The owner DSN reaches `migrate` only. Workspace-lifecycle DDL — today the per-workspace `index.chunk` partition and its HNSW index — is a `SECURITY DEFINER` function installed by migration, `SET search_path = pg_catalog, pg_temp` pinned, `EXECUTE` revoked from `PUBLIC` and granted to `app_rt` alone, all objects created in one transaction. (This supersedes the "owner DSN reaches the two runtime-DDL paths" clause of ADR 0023's amendment; the paths are now one function the runtime role calls.)
- **`vector(N)`, fixed.** pgvector's HNSW refuses a dimensionless column ("column does not have dimensions"; the documented workaround — a cast-expression index — silently full-scans any query not repeating the cast), so ADR 0007's untyped-vector clause was latent-defective as written. `index.chunk`'s column is `vector(N)` with N read from the day-one embedding route's model on the day (`[DEPS1]`); `embedding_route_id` stays on every row; list partitioning by workspace and the per-partition HNSW index stay for the recall-isolation reason ADR 0007 gave. **Reopening condition, named:** the first workspace pinning a different-dimension model — the decision then is a column per dimension family (`halfvec` included), and the re-embed it needs is the route-change rebuild the design already names.
- **The worker's view of the schema is generated and committed.** A generator runs the migrations against a throwaway Postgres and emits the Python schema module the worker imports, carrying the migration id (`[WRK1]`'s stamp). CI regenerates and fails on drift **in both directions**: a stale committed view, and any table in the migrated database the journal does not know (out-of-band DDL). This is the pattern that held in the predecessor (`canonical`: generated TS types + CI parity) applied to the side it left exposed (hand-transcribed Python dataclasses, no real check).
- **TypeScript schema ownership is affirmed, independently.** The clean-context review, given the facts and the MCP-first strategy but not the incumbent answer, concluded the journal belongs with the application of record (auth tables, RLS, user-facing writes — where churn originates), that pipelines are schema consumers everywhere this shape appears, and that Python ownership would forfeit Drizzle's and Better Auth's generators where types pay most. It independently re-derived `[PIPE1]`'s `managed_by="user"` invariant as its one warning — evidence the invariant is load-bearing.

## Considered options

- **Keep AGE, spike first (re-sequence `T-007` before the graph DDL).** The evidence-first path, and the recommendation put to the owner. Declined: the spike defends a convenience (Cypher for a handful of templates) whose induced complexity is the larger of the two sides whatever the spike measures; the mantra decides it without the spike's cost.
- **Keep AGE and build `T-003` as cut.** Builds the machine the spike might delete. Rejected on the gate's own Q4 precedent.
- **An edges table but per-workspace roles kept anyway.** The roles carried weight only against AGE's schema boundary; without it they are catalogue sprawl, a third mechanism, and a restore-drill trap (`pg_dump` does not carry roles) purchased against no threat RLS does not already cover.
- **Two journals (Drizzle for `public`, a second runner for `index`/graph).** Makes `[WRK1]`'s stamp blind to exactly the schema the worker writes; a composite stamp is a distributed-systems problem invented out of nothing.
- **Python (Alembic) or neutral-runner schema ownership.** Reviewed clean-context and rejected; see above. Pure neutral-SQL is already subsumed: the journal carries hand-written SQL, Drizzle is runner *plus* generator.

## Consequences

- **Files**: `deploy/postgres.Dockerfile` is deleted; the database image is the official pgvector image pinned by digest (read on the day, `[DEPS1]`); no postgres job joins `build.yml`. `deploy/stores.compose.yaml`, `BACKUPS.md`, `RUNBOOK.md`, `restore-drill.sh`, `coolify.md` lose their AGE lines in `T-003`'s PR.
- **Tasks**: `T-003` is re-cut from this ADR (substrate + proving tables: `workspace`, `index.chunk`, the llm-route table with the `llm-routing` SQL function and its `contracts/` fixture; queue and concept-inbox functions land with the tasks that bring their tables). The deploy-dependent lines (deployed-by-digest, the `\du` probe, the memory-limit sweep) move to `T-005`. `T-007` is void.
- **Rules**: ~~`[DESIGN4]`'s~~ the constitution's graph clause is rewritten — the graph tables are tenant tables under the same guarantee, and the ban on LLM-authored SQL and on the `neo4j` ecosystem stands with no exception (the rule itself is retired to this ADR on 2026-09-05; amendment below). `[SEC2]`, `[PIPE1]`, `[WRK1]` unchanged.
- **Docs**: ADR 0023 gains a skimmer pointer (engine superseded; write model stands, restated here); ADR 0007 gains pointers at its untyped-vector and AGE clauses; `docs/adr/README.md` updated in this commit; `CONTEXT.md`'s *graph* entry drops the AGE parenthesis. *map*, *generation*, *graph sync run*, *entity merge*, *canonical entity* already describe behaviour, not engine, and stand as written.
- **The tier contract** (ADR 0031) is untouched: the visibility columns the worker writes now land on graph *rows* rather than AGE properties, which is the same agreement with a simpler landing.

## Amendment — 2026-09-05, the tenancy rule leaves the constitution and its substrate is recorded here (T-078)

The constitution's tenancy rule — `DESIGN4` until this date; the tag is retired and appears nowhere in the tree — was design content wearing a rule identifier, as ADR 0029's 2026-08-29 consequence already said. Design principles are not coding rules (owner, 5 September 2026), so it is re-filed here in the words it used:

- **Workspace on every row, and RLS is the guarantee.** Every tenant table carries the workspace id and is created `withRLS()`, so a table with no policy returns no rows to anyone, under `FORCE ROW LEVEL SECURITY`, read by the non-owner `app_rt`, with `SET LOCAL app.workspace_id` set from the Principal. One zero-rows test per tenant table is the proof. The one exemption is the **identity set** — Better Auth's tables, read by key before any workspace is known, from which a workspace id is resolved (ADR 0009, 2026-09-01) — named in `IDENTITY_SET` and checked both ways by the RLS coverage test. The store door (ADR 0029) is ergonomics over that guarantee and never a substitute for it: drizzle-orm exposes no query lifecycle hook, so there is no interception layer to trust. Every document carries the `external_access` shape and its binding's sensitivity (ADR 0013).
- **The graph tables are tenant tables like any other.** `graph_node` and `graph_edge` carry `workspace_id` and the three visibility terms as columns under the same RLS; traversal is a prepared recursive-CTE template in the one graph query module per tier, depth capped at 4 by the template; no LLM-authored SQL runs against a shared store; no `neo4j` driver, no Bolt, no APOC, no `neo4j_graphrag` import, with no exception. Neither table is migrated yet; this is the model the task that migrates them builds to.

What is checkable stays a rule: the Principal first is `[SEC2]`; the zero-rows test per tenant table, the definer function's four checks and the ban on LLM-authored SQL and on the `neo4j` ecosystem are `[SEC3]`. Where an earlier record cites the retired tag — ADRs 0005, 0021, 0023, 0028, 0029, this ADR's 2026-08-30 consequence, the T-004 and T-015 specs and the pre-build gate — the citation is struck and pointed here, as the index's convention asks; no conclusion changes.
