# The graph is Apache AGE inside the platform Postgres — one graph per workspace, written in generations, backed up with everything else, and never a hard dependency

> **Engine superseded by ADR 0032 (2026-09-01): the graph is plain Postgres tables under RLS — no AGE, no per-workspace roles, no custom image.** The *graph is application data* amendment below **stands in full** (workspace id and visibility on every element, the delta in the commit transaction, generations for rebuilds only, keys never text, the label set and the `Person` floor) and is restated as columns in ADR 0032. Read this file for the write model's reasoning, never for the engine.

The platform's derived graph (ADR 0011) lives **inside the one Postgres** as **Apache AGE 1.8.0 on Postgres 18** (Apache-2.0; `apache/age:release_PG18_1.8.0`, pushed 28/08/2026 — research 71). There is no graph service: the Postgres image is our own build, `deploy/postgres.Dockerfile`, **AGE's PG 18 image plus pgvector 0.8.6 compiled in**, pushed to `ghcr.io/betteranswers/postgres` by the build workflow and deployed by digest like the two tiers (ADR 0022). Postgres stays a **Coolify database resource** pointed at that image — Coolify's resource takes any Postgres-shaped image (its `image` field; `apps/docs-site/operations/coolify.md` already relied on it for pgvector), so research 71's one unverified risk is closed on the docs, and confirmed on the box at the first deploy as a probe.

**One AGE graph per workspace** (`create_graph('ws_<id>')`), created by the app at workspace creation — the only runtime DDL beside the chunk partition (ADR 0007) — and dropped at workspace deletion. A graph is a schema, so tenancy is a schema boundary the session cannot cross: every query names the caller's graph from the session principal, and the **workspace-scoped worker role** (ADR 0005) has `USAGE` only on its workspace's graphs. `workspace.graph_instance` is gone — instance-per-tenant is the default, free. (This paragraph originally dropped `workspace_id` from nodes and edges on the strength of that schema boundary; the *graph is application data* amendment below **restores it as a property and a term of every `WHERE`**, because the deploy unit disarmed the boundary. Read the amendment.) Uniqueness is a **Postgres unique index on each label table** (`(gen, uid)` on the bundle-and-record partition, `(uid)` on source entities), in the app's migrations; presence is still the writer's guarantee, tested, plus a nightly audit.

**Everything ADR 0021 settled about writing and reading stands, and is restated here in full rather than carried over by reference** — a builder who must open a superseded ADR to learn the live design will build the superseded design. Where the 2026-08-29 *graph is application data* amendment below and this restatement disagree, the amendment governs; the clauses it changes are marked *amended*.

*Written in generations.* The bundle-and-record partition — our own derive — carries `gen` on every node and edge. A **full rebuild** (`reason`: first-sync · route-change · reconciler · erasure · upgrade · drill) writes the next generation beside the live one, cross-checks the parse against the app-written concept index (a mismatch stamps anyway and raises `bundle_health` as a state), and the swap is **one row update, `workspace.graph_live_gen`**, which every read binds; the retired generation is swept per label in batches after a 60-second grace — **for an erasure the flip and the sweep are one step**, and the sweep's last commit is the timestamp on the `erasure_request` report. *Amended:* the incremental `graph_sync_run` — woken by `bundle_commit` and a record watermark, one run per workspace under a per-workspace lock, a five-second debounce capped at 30 seconds — is **not built**; the delta joins the app's commit transaction and generations survive for full rebuilds only. The **source-entity partition** carries no generation, passes the read predicate on `binding_id`, and is erased by suppression + reprocess (ADR 0020), never by a flip.

*Keys are never text* (prototype 52): concepts by IRI, sections by `(IRI, slug)`, source entities by `(document, type, normalised-text hash)`, actors by `(workspace, actor id)`, compositions by `(record id, version)`. A confirmed alias merge is an **`entity_merge` rule** — an audit event, never a commit — producing a **canonical entity**: a node of its own keyed by the rule, carrying no `binding_id`, with *every* contribution hanging off it by `SAME_AS` under its own binding, class and audience; a canonical with no contribution visible to the caller is never returned; undo is deleting the rule and re-deriving; a `Person` concept links by `IS_CONCEPT` and is never merged into.

*The read predicate lives once*, in the app's graph query module — and it moves for the store: it **cannot ride inside a path pattern in AGE**, so every traversal is a **bounded variable-length pattern with the predicate in `WHERE` on every node and edge of the path**, emitted only by the builder, which cannot emit a pattern without it; depth is capped at 4 by the template, never by the caller. Three functional tests ship with the module: a Person merged from a published and an unpublished binding returns only the published contributions to a non-Admin; a query that does not name the caller's workspace throws in every environment; a Restricted `Person` concept reached through `IS_CONCEPT` by a Viewer outside its names returns nothing and hints nothing.

*Entry is by key, never by a graph-side index.* Hits come from Postgres (ADR 0016); the graph is entered by IRI or entity id through the unique-index-backed lookup and expanded outward, depth ≤ 4; no graph-side vector or full-text index is a retrieval route; every statement is a prepared template from one graph query module per tier with a per-query timeout (a `statement_timeout` on the graph role).

*When the map is behind, nothing the rows can stand behind stops.* Search, badges, guides and cited answers work from Postgres; `ask` still finds entry points, judges and reuses an `Answer` at depth 0 and its verdict is computed as usual; impact, successors and coverage show the phrase and what still works; the successor chase falls back one hop to the successor IRI the concept index row carries; MCP carries a `map` field, never a count; a map-drawn read has a per-request budget after which it degrades. *Amended:* *map as of <time> · updating* is not built, because the map is never behind for an edit.

*The rebuild's budget stays the promise.* A nightly test on a deterministic fifty-workspace fixture asserts the estate rebuild under 60 minutes and shows it as headroom with a signal at 75 %; the per-workspace figure (≤ 2 minutes) is the promise on the erasure report; the monthly drill rebuilds one workspace on the restore target, diffs node and edge counts per label against production, and exercises the sweeper.

*The source-entity partition has no cocoindex target.* cocoindex's Postgres target lands entity rows in `index`, and a derive step in the same run lifts them into the graph per document (`MERGE` split by node then edge, the AGE way), carrying `binding_id` and class. Every statement is `cypher()`-in-SQL over `agtype`; the app reads through `pg` with an `agtype` parser in the graph query module, the worker through `psycopg` — one graph query module per tier, as before.

**What does not carry from ADR 0021**: Bolt and the `neo4j` driver, the JVM memory keys and `neo4j-admin server memory-recommendation`, "not backed up", `workspace.graph_instance`, cocoindex's Neo4j target, the inline quantified-path predicate, APOC, and the `neo4j-graphrag` matcher lift — **cut** (see the amendment below).

**The graph is backed up, because it is Postgres.** It rides every `pg_dump` (`apps/docs-site/operations/BACKUPS.md`) and every restore; the *rebuild* is now a repair path, not the recovery path — kept, drilled monthly on one workspace, and budgeted as before (≤ 2 minutes per workspace on the erasure report; the 60-minute estate headroom measured nightly), because a rebuild is still how a route change, the reconciler and an erasure re-derive get a safe "rewrite everything". Research 55's open question 6 flips: the graph *is* backed up, without stopping anything.

**Never a hard dependency, still — and the degraded state shrinks.** The map cannot be down while Postgres is up, so *map unavailable* is reachable only when the whole database is; what remains is *behind*: **map as of <time>** and **map as of <time> · updating** carry the day-to-day truth, `ask` still traverses at depth 0 when a workspace's graph is mid-rebuild, and a map-drawn read keeps its per-request budget — a per-statement `statement_timeout` on the graph role. The phrases and the MCP `map` field are unchanged (ADR 0016).

## Considered options

- **Neo4j Community 5.26** (ADR 0021) — zero rework and supported to 06/2028, but a JVM reserving ~3 GB for a graph of tens of megabytes, a second stateful service, and the only store in the estate that could not be backed up consistently without stopping it. On a founder-run 16 GB box beside Postgres, Garage, Forgejo and a 3–5 GB CPU embedding server, the memory and the operational exception cost more than the 3–4 days of re-grilling plus ~2 build days porting `okf-neo4j`'s Cypher.
- **An edges table with recursive CTEs** — the fallback if AGE fails the first-deploy probe: full tenancy for free, every traversal hand-written SQL.
- **LadybugDB (Kuzu fork), embedded in the worker** — single-writer, so the app cannot traverse; moves answering into the worker behind HTTP. Rejected with ADR 0005's seam.
- **Memgraph, FalkorDB** — licences (BSL; SSPL) that a multi-tenant SaaS cannot sign without counsel, for no simplicity gain.
- **Postgres moved into `stores.compose.yaml` with a `build:`** — no registry push, but loses Coolify's resource UI and its second backup writer (ADR 0022) for a risk the docs already close. Kept as the day-one fallback if the probe fails: the same Dockerfile, one compose service, `DATABASE_URL` unchanged.
- **`pgvector/pgvector` as the base and AGE compiled on top** — the same image either way; AGE's build is the fussier of the two (bison, flex, `shared_preload_libraries`), so it is the base.

## Consequences

- **Files**: `deploy/postgres.Dockerfile` (new; built and pushed by `build.yml`, pinned by Renovate — both extension versions read on the day, `[DEPS1]`); `deploy/stores.compose.yaml` loses `neo4j` and `/data/neo4j`; `deploy/platform.compose.yaml` loses `NEO4J_URI`/`NEO4J_AUTH` (`DATABASE_URL` reaches the graph); `apps/docs-site/operations/BACKUPS.md`, `SECRETS.md`, `RUNBOOK.md` and `coolify.md`, and `deploy/restore-drill.sh`, swept; ~3 GB of VPC 1 returned to the box-sizing pass (ticket 74).
- **Records**: `graph_sync_run` and `entity_merge` unchanged; `workspace.graph_live_gen` stays; `workspace.graph_instance` **deleted**; the concept index row still carries the resolved successor IRI.
- **DDL the app owns** (ADR 0007 amended): `CREATE EXTENSION age` and `vector`; one graph per workspace; the label tables' unique indexes and the `gen` range index per label; `statement_timeout` on the graph role; no Neo4j memory keys anywhere.
- **Signals** (ticket 42): *reachable* becomes the database's own; map age per workspace, last run as a state, rebuild, estate headroom and the presence audit stay; add the label tables' size per workspace (the one number a graph inside Postgres can quietly grow).
- **`CONTEXT.md`**: *map* keeps its three phrases (the third now the database's outage); *generation*, *graph sync run*, *entity merge*, *canonical entity* unchanged; *graph* gains "inside the platform Postgres".
- **The constitution's graph clause** (its tenancy rule, since retired to ADR 0032): the graph named from the principal; the predicate in `WHERE` on every path element through the builder; depth capped in the template; split `MERGE`s; no `neo4j` driver, no Bolt, no APOC, **no `neo4j_graphrag` import and no matcher lift** — the ban has no exception (see the amendment below).
- **The first build task's spike** (replacing ADR 0021's): depth-4 cost on a 100k-node label set with and without the `gen` index; the agtype parser in `pg`; `MERGE` split cost for the largest `Answer` subgraph; the derive step's idempotency from cocoindex's Postgres target; the graph role's grants across `create_graph`; that the Coolify resource on the custom image keeps its backup writer.
- Amends ADRs 0005, 0007, 0016 and 0022 as recorded on each; **supersedes ADR 0021**, whose writing and reading design is restated in full in the body above — not incorporated by reference, so no builder need open a superseded ADR.

## Amendment — 2026-08-29, what an edge is (ticket 50, ADR 0026)

Every markdown link between concepts is a `LINKS_TO` edge carrying `from_kind`, `to_kind`, `section` and `sentence`, between nodes labelled by kind; `SUPERSEDES`, `CITES` and `IS_CONCEPT` (for every kind, not only `Person`) are the only named edges. No typed-relation derivation from a relations list; a predicate label, if ever wanted, is derived from edge sentences by an enrichment job and stays in the graph. Written under the same scoped keys and generation as the rest of the bundle-and-record partition.

## Amendment — 2026-08-29, the graph is application data (ticket 79, the pre-build gate)

*This amendment states the whole graph write model in one place, and it is deliberately one amendment rather than four. Architecture review pass 2 found its one blocking fault precisely because this design lived in two documents written a day apart — ADR 0026's "nodes labelled by kind" (in the amendment above) against this ADR's "a unique index on each label table … in the app's migrations" — each assuming the other had spoken. Four separate amendments would have created four fresh chances to do it again. Where this amendment and any earlier clause disagree, this one governs.*

**One `Concept` label; `kind` is a property.** The bundle-and-record partition uses a **closed label set the app's migrations own** — `Concept`, `Section`, `Source`, `Actor`, `Composition`, `Evidence`, `CanonicalEntity` — and a concept's kind is a **property**, indexed, never a label. Source-entity labels keep their own closed, prefixed set, so a source-entity type that shares a kind's word no longer collides with it. The clause "between nodes labelled by kind" in the 2026-08-29 edge amendment above is **withdrawn**; everything else in that amendment stands.

Three reasons, in the order they matter. **A label is a registry.** It is a schema object — created, named, indexed and granted in the catalogue before any row can wear it — and ADR 0026's whole decision is that a kind is *not* registered anywhere: OKF's one required key is "not registered centrally", and a producer mints a concept precisely so it need not fit anywhere yet. Labels-by-kind rebuilds the vocabulary file ADR 0001 died for, inside the Postgres catalogue, where it is worse than the YAML was — a catalogue entry needs DDL and a grant where a file needed only a commit, and a kind rename, which ADR 0026 makes *one bulk commit*, would become a schema migration. ADR 0026 had already reached this conclusion without noticing: it made `from_kind` and `to_kind` edge **properties**. **Nothing could create the label anyway.** Kinds arrive with the concepts that carry them, at whatever moment an Admin accepts a suggestion set, so no migration can name one; and the writer runs under a role with `USAGE` only. Labels-by-kind therefore required either DDL on the write path or `CREATE` in the worker's grants — both refused. **The two unique indexes stopped colliding**, and a `(uid)` index no longer makes the side-by-side full rebuild impossible.

**`workspace_id` returns as a property on every node and edge**, in both partitions, and is a term of the builder's `WHERE` on every element of every path — beside the read predicate, not instead of it. This is not a second lock added out of nervousness: ADR 0007's own amendment already specifies non-owner runtime roles under `FORCE ROW LEVEL SECURITY`, and the constitution's tenancy rule already says every node and relationship carries the workspace id. This ADR deleted the property on the strength of a schema boundary, and the deploy unit then disarmed that boundary — one `WORKER_DATABASE_URL` for every workspace, the owner DSN for the app, and a graph name AGE cannot parameterise (its own manual's dynamic example uses `format()` and `EXECUTE`). So the graph had one isolation control where every other store in the estate has two, and restoring the property closes a contradiction rather than adding a mechanism. A wrong graph name now returns **zero rows** instead of another tenant's knowledge. The graph name is derived from the Principal through one allowlisted function that regex-checks `^ws_[0-9a-z]{26}$` and is the only place string-building is permitted; a lint rule refuses `cypher(` outside the graph query module's builder.

**The three visibility terms are properties too — on every node and edge, and columns on every readable unit.** `published_at`, `sensitivity` and `audience` were specified as fields on a *source binding*, and neither a concept nor a composition has a binding: a concept is minted from evidence that may span several, or typed by a person from none. They become real columns on `concept_index`, on `composition` and on every `index.chunk` row whatever its unit kind, and properties on every graph element, so the predicate has something to test everywhere it is applied. **A class is a record, not knowledge** — a company with no platform marks *documents* confidential rather than annotating each unit of what it knows, and OKF lists access control among the silences this platform meets in the graph and in records, never in the file (`[OKF1]`, `[OKF2]`, ADR 0011). Because it is a record, it may be derived and recomputed, which is what the derivation does: **a concept's class is the most restrictive among the bindings of the evidence it cites; a composition's is the most restrictive among its includes; a unit with no evidence takes the workspace default.** Three riders. The recompute is **synchronous, inside the narrowing act's own transaction** — a queue reopens the leak for the length of the queue. It cascades **two levels**, binding → concept → composition; one level only, and the guide-footnote leak survives the fix. And a **per-kind floor** overrides inheritance where ADR 0020 sets one — a `Person` concept starts Restricted even when minted from the public website, and only a recorded Admin override may widen it. That override deliberately creates a reader who sees an assertion whose evidence passage they may not: the evidence pane carries a fixed word for that state, as it does for *source moved on*, never an empty pane that reads as a fault. The derivation reads the *bindings of the evidence*, so it depends on `evidence` being keyed on `(workspace_id, source_document_id, locator)` rather than on `resource`/`locator`, which re-keys silently when a file moves.

**The bundle-and-record delta joins the app's commit transaction.** Generations, the live-generation flip, the five-second debounce, the record watermark, three System signals and the reader-facing *map as of … · updating* phrase were all designed to bridge a second store the app could not write transactionally. This ADR removed that store. The delta therefore lands in the same transaction as the concept index row, the `bundle_commit` and the `audit_event`; **generations survive only for full rebuilds**; the watermark, the debounce, the three signals and the degradation phrase are not built. The map is never behind for an edit, which is what ADR 0012 argued for when it won the same point for the index row. This does not touch ADR 0011's layering: sources → bundles → graph is a statement about what derives from what and about authority, not about which process runs the derivation, and a map that agrees with the bundle at every instant makes "never a source of truth" *more* honest, not less. Two fences keep it that way, both named running tests rather than hygiene: **rebuild-equivalence** — a rebuild from bundle plus records reproduces the live graph exactly, which is the only enforceable meaning of *derived*, and matters more now that writing the graph is cheap enough to tempt it into carrying state of its own — and **the second parser survives as a nightly auditor**, cross-checking the app's parse hash-by-hash and raising `bundle_health` on mismatch. Nightly is fine; deleted is not.

**Consequently the worker's graph surface is the source-entity lift, and the app runs as a non-owner.** Source entities stay in the worker, correctly — they derive from sources, which is the worker's layer. The app runs as `app_rt` under `FORCE ROW LEVEL SECURITY`; the owner DSN reaches only `migrate` and the two runtime-DDL paths. One worker **login** role holds no table privileges at all and `SET LOCAL ROLE`s into the per-workspace role, so a forgotten `SET ROLE` fails with *permission denied* rather than reaching every workspace. The constitution's graph clause is rewritten from this amendment verbatim, and the `neo4j-graphrag` matcher lift is **cut** — ADR 0026 abolished typed-relation prediction, so its only consumer is gone and the ban stands with no exception.

**Amends** ADRs 0007 (roles and the DDL owner), 0012 (the delta joins the commit transaction), 0013 (the predicate is a projected column set on every readable unit, not three binding fields), 0016 and 0026 (the edge amendment's label clause withdrawn; its relations rule untouched). **Build tasks** B2 (`T-003`) and B5 (`T-006`); the spike is B6 (`T-007`), which now runs under concurrent read traffic and a concurrent hourly dump because the ≤2-minute rebuild budget was set for a Neo4j-shaped box with its own isolated heap and has never been re-derived. Whether AGE auto-creates a label table on first write is recorded at the first deploy; it does not reopen this decision either way.

## Amendment — 2026-09-05, the read predicate's columns, recorded here (T-078)

`[SEC2]` carried the list of units and columns the read predicate is tested against; a specification of that kind belongs with the decision, so it is recorded here and the rule keeps its checkable sentence. The predicate — published · sensitivity · audience — is tested against **columns on the readable unit**: `concept_index`, `composition` and every `index.chunk` row carry `published_at`, `sensitivity` and `audience` whatever the unit's kind, and `graph_node` and `graph_edge` carry the same three terms as columns (ADR 0032); never against three fields of a source binding, because a concept and a composition have no binding. The write model above stands.
