# The tier contract is six agreements in three forms, fixtured in one language-neutral `contracts/` directory both suites read — and the read predicate is not one of the six as first written

ADR 0029 named the app↔worker contract as the risk that outlives it: six cross-tier things agreed, at the time, by two independent implementations of the same prose. This ADR settles them. **Each agreement lands in exactly one of three forms** — *SQL function* (the behaviour is the database's, both tiers call it), *fixtured* (a golden vector in `contracts/` both suites read), or *generated* (produced from one source, ADR 0028's mechanism) — and **one cross-tier conformance surface exists from before the first table: a top-level `contracts/` directory whose manifest both tiers' test suites read and assert identically**. The suite is a walking skeleton today — it proves the cross-language plumbing, the part that fails silently — and each agreement's fixtures join it as `T-003`+ makes them real. `packages/contracts` (a pnpm package the Python tier cannot read) dissolves: `Result` folds into `packages/core`'s `kernel`, and the name moves to the directory that can actually serve the seam.

## Amendment, 05/09/2026 — the set is seven: id-shape joins it

ADR 0035 gives the platform one minter and one id shape, and the shape is cross-tier by construction: the worker seeds and reads ids the app minted, and the app parses ids the worker wrote at a boundary that now narrows to the pattern (ADR 0028). That is exactly an agreement in this ADR's sense, and its form is *fixtured* — the pattern, the ids that must parse and the ids that must not, in `contracts/id-shape/cases.json`, with each tier holding it against its own minter and its own boundary rather than against a written-out copy. **The six of the title become seven**; nothing about the three forms, the two thin runners or the directory's place changes, and `contract_version` bumps to 1 for the first time, which is the mechanism this ADR built working as designed (T-074).

## Amendment, 08/09/2026 — the set is eight: concept-file joins it

ADR 0014's content hash is computed twice: by the app at every write and replay, and by the worker on every nightly audit, which reports a concept *mismatched* when its number differs. Two parsers holding one number is an agreement in this ADR's sense, and its form is *fixtured* — `contracts/concept-file/cases.json`, a frontmatter in and the canonical text and SHA-256 out, with the cases the two languages disagree on by default: an object's integer-like keys (which a JavaScript object enumerates first, in numeric order, and RFC 8785 sorts as the text they are), every number shape `Number::toString` and Python's `repr` lay out differently, the `sources[]` reduction and the trust keys left out. Each tier holds its own canonicaliser and hash to the fixture rather than to a hash literal copied from the other tier's probe, which is what the two suites did until PR #51's second review round found the sort disagreeing. **The seven become eight**; the three forms, the two thin runners and the directory's place stand, and `contract_version` bumps to 5.

## Amendment, 10/09/2026 — the set is nine: redaction joins it

ADR 0020's seam runs in the worker and the review of what it found is an Admin's act in the app, so what the seam withholds is read by both tiers and written by one: the worker replaces a span and inserts the `finding` row, and the app shows the category on a review screen, restores an always-set span with a reason, and reads the binding's rules in force the seam ran under. Two tiers holding one answer to *what is withheld, and under which word* is an agreement in this ADR's sense, and its form is *fixtured* — `contracts/redaction/cases.json`, which pins four things and no more: **the category list** with the tier each sits in; **the placeholder word per tier and category** — one neutral `[withheld]` for the whole always set, because a typed placeholder there would tell the audience what class of data the document holds, typed words such as `[home address withheld]` for the rest, and `[person A]` for a name, which is a stable pseudonym and not a blank; **the special-category rule**, that such a finding and only such a finding narrows the document to *Restricted*; and **the version string's shape**, `rule_version:detector_pin`, one separator and two non-empty parts with no whitespace, so splitting it is the same operation in either tier whichever end it splits from. Nothing in the file is derived from a detector: no recogniser, no threshold, no model id, because the detector is T-121's and a fixture that named one would be the seam describing itself rather than being held to something. **The fixture is the contract and the descriptors are held to it** — the worker's one declaration per category, from which the analyzer registry and `rule_version` are built, is the thing this file tests, and a category added there without this file is a category the app has never heard of. Each tier asserts from its own side, as id-shape's halves do: the TypeScript half against the boundary schemas the app stores a finding and a binding with, the Python half against the columns the worker writes them into. **The eight become nine**; the three forms, the two thin runners and the directory's place stand, and `contract_version` bumps to 6 (T-120).

## Amendment, 11/09/2026 — the queue agreement gains the kinds a claimant runs, the job's subject and the run key

The set stays **nine**: nothing joins it here, and the queue's form is still *SQL functions*. What changes is what those functions agree, because S1 puts a third kind on the queue whose handler arrives a ticket later, and a kind that exists before the tier that runs it means a claim can no longer be "the oldest claimable job".

**`claim_job` takes the kinds the claimant can run**, as a required third argument, and **both arms are filtered by it** — the candidate arm and the poison arm alike. The worker passes the kinds its registry holds; the ops command that runs a rebuild in the foreground passes the rebuild kind alone. The poison arm takes the same filter on purpose: poisoning is a verdict on a job that keeps losing its worker, and a claimant that cannot run a kind has learnt nothing about that job by failing to claim it — a claimant that poisoned a kind it does not run would be retiring somebody else's work. The argument has no default, so a caller must say which kinds it runs rather than inherit every kind the schema grows.

**A job may name its subject**, a nullable `subject_id` under a biconditional CHECK per kind, and **a subject has at most one run and at most one job waiting**: the queued side is a partial unique index over queued rows on `(workspace_id, kind, subject_id)` — the glossary's *run key*, so a second enqueue for a binding already waiting is the database's refusal and the enqueue reads the waiting job's id back — and the claimed side is the claim's own sibling check, which passes over a candidate whose subject has a job of the same kind claimed under a lease that still stands. The claimed side lives in the claim rather than in a constraint because it is a fact about an instant: the lease either stands now or it does not.

**The fixture is where both tiers meet this.** `contracts/queue/cases.json` gains a `kinds` array on every claim, a `subject_id` on every job, a `refused_enqueues` list of inserts the run key must refuse with the SQLSTATE it refuses them by, and a `lapse_first` on a claim that needs a lease taken away part-way through a sequence — the same trick the relative instants already play, moved from seed time to mid-sequence. The cases it gains say: a claimant reaches only the kinds it passes and leaves a kind nobody passes queued; a spent job of a kind nobody passes is not poisoned either; the worker claims on its registry's kinds and the app claims on the rebuild kind alone — which is the **grant and the policy** proving the agreement admits the app as a claimant, and not a statement that any kind's descriptor names the api tier, because every descriptor names the worker today; a binding's second run waits while the first holds a live lease, and the binding's work is handed out again the instant that lease lapses. `contract_version` bumps to **7** (T-127).

## Amendment, 11/09/2026 — the set is ten: document-chunk joins it, and visibility-columns gains its first real fixture

S1 cuts a document's normalised redacted text into chunk rows in the worker and reads a passage back out of them in the app, and the two halves have to agree about an address. That is an agreement in this ADR's sense and its form is *fixtured* — `contracts/document-chunk/cases.json`, which pins four things. **The chunk id is derived, never minted**: a document's ULID and the zero-padded ordinal joined, so a reprocess upserts on the row's own key (ADR 0036's stable id, amended 2026-09-10) and either tier can name a row from its address without asking the other. It is therefore not the shape `id-shape` describes, and that agreement's own description is corrected in the same commit — its sentence that the worker mints no id has been stale since T-057's self-scheduled audit. **The locator is a span**, `<source document id>/chars:<start>-<end>`, and its offsets are **Unicode code points** into the normalised redacted text — which is the reason this agreement could not be left to prose. The two tiers do not count a string the same way: Python indexes by code point and JavaScript by UTF-16 unit, so the fixture's text carries an astral character before every cited span and writes both lengths down. A tier counting units returns a passage that starts one character early and ends one character short, which is a wrong answer that reads like a right one and no single-tier test can see. **The chunk rows partition the text** — the first starts at zero, each row's end is the next row's start, and the last row's end is the text's code-point length — so a span straddling two rows has exactly one answer whether it is cut from the whole text or joined from the rows a read selects. **A malformed, an out-of-range and an unknown locator answer with one word**, *not found*, the same word a withheld passage gets, and the fixture records which of the two gates refuses each: the parser refuses what the string itself is wrong about, and the read refuses what needs the text or the rows in front of it. The app holds its derived id, its locator parser and its span cut to the file now (T-128); the worker holds its splitter and its offsets to it in T-129, and `passageAt` is held to the same rows in T-133.

**`visibility-columns` gains its first real fixture in the same commit.** It has been a row in the table above and a key in both suites' registries since this ADR was written, with no file under it. What it now states is the fields a binding carries, the class a document may carry of its own — nullable, where null means *the binding's* — the columns every chunk row must carry, and the order the two classes fold in, which is the narrower of them and never the document's word alone. And it states the thing the S1 spec added: **two writers of one source**. The worker writes these columns on every chunk row a run lands and **re-copies** the binding's and the document's current fields onto every row it wrote in the run's last statement, inside its own scoped transaction before the job finishes; the app rewrites them on a publish, on a binding's narrowing and on a document's narrowing, in the act's own transaction. Both copy from the same row, so they can disagree only in a race — a run that read the binding before a narrowing committed and upserted its rows after it — and the re-copy is what settles it: a narrowing that lands mid-run wins, and one that lands after the re-copy finds the rows and rewrites them itself. The cross-tier test holds that race from both sides (T-137).

**The nine become ten**; the three forms, the two thin runners and the directory's place stand, and `contract_version` bumps to **8** (T-128).

## Amendment, 21/09/2026 — the set is eleven: upload-media-types joins it

S1 left the list of media types an upload is admitted under written twice: the app's bind act refuses a type outside `UPLOAD_MEDIA_TYPES` while the Admin still has the file (T-131), and the worker's converter dispatches on the type the catalogue row carries, one converter per type (ADR 0013, T-130). Two tiers holding one answer is an agreement in this ADR's sense — the owner's ruling of 19/09/2026 — and its form is *fixtured*, because a TypeScript constant cannot cross the tier boundary and a file can: `contracts/upload-media-types/cases.json` carries the four admitted types, and a few outside the list chosen because each is the nearest way one tier would drift from the other. The app holds the constant its bind act enforces to the file; the worker holds **the keys of its dispatch** to it, which is why `converted`'s `if` chain became a mapping, `CONVERTERS` — a list written beside a chain would have been a third copy, free to drift from the chain it described. Each tier's seeded suite then offers the same outside types: the app's sees them refused at the bind act with `media-type-refused`, and the worker's sees them quarantined on the catalogue row under `UnsupportedMediaType` rather than converted.

Drift was a visible and safe failure before this — the worker quarantines what it cannot convert — so what the agreement buys is the failure moving from an Admin's quarantined document to a red suite. The list grows when connectors arrive, and admitting a type is then one commit to the file, to both tiers and to `contract_version`, with ADR 0013's choice of that type's one converter beside it. **The ten become eleven**; the three forms, the two thin runners and the directory's place stand, and `contract_version` bumps to **9** (T-165).

## Amendment, 21/09/2026 — the contract's version is a digest both tiers compute and the worker reads at run time; a manifest's form is held to the disk; and the chunk leaves visibility-columns

`contract_version` was read by two tests, each against a constant written beside it, and by nothing at run time. At one commit that check can fail only by forgetting to edit a number, and where tiers do skew — two images, one of which failed to build — nothing read it. **The number becomes a digest of `contracts/`**, computed by each tier at build: `migrate` stamps it, and the worker compares its own beside the schema stamp it already checks (*The stamp check stays strict*, below) and refuses to claim on a mismatch. `SPOKEN_CONTRACT_VERSION` leaves both suites; admitting an agreement or editing a fixture is a commit to the file and to the tiers, and to no number. A benign fixture edit trips the check on a partial deploy, and that is accepted: both images are built from one commit, so a mismatch means a partial deploy, which should be loud. Declined: one "same commit" stamp for schema and contract alike — an api-only deploy would idle the worker for nothing.

**A manifest entry's form is held to the disk.** *Fixtured* has a fixture and *generated* has golden rows, asserted by both suites beside the inventory check they already make; `credential-envelope` and `cost-ledger`, which say a form and have neither, get theirs or change form.

**The chunk leaves `visibility-columns`.** The agreement held two tiers' folds of a chunk's visibility equal. ADR 0044 makes a chunk's visibility something no tier writes — it is read from the chunk's binding and its document — so when that build lands the worker writes none of these columns on a chunk row and the fixture's cases go with them. What the table's row still says of the graph elements the worker will land is S6's to settle, with ADR 0044 read first: a source-derived element carries its `binding_id`, so it can be read the same way. If nothing is left to agree, the agreement retires and the set is ten. The class ranking's one SQL statement, `narrower_class`, is held against the app's rank by the core suite alone.

## Amendment, 22/09/2026 — the set is twelve: citation joins it

The comment rule refuses a comment that cites, and it runs twice: an oxlint rule over the TypeScript tier and a script over the Python one. Each carried the same five patterns — a ticket id, an ADR number, a rule tag, an ISO date, a slashed date — written out in its own language, so a sixth was two edits that could disagree and a fifth that drifted would have the two gates refusing different trees. Two tiers holding one answer is an agreement in this ADR's sense, and its form is *fixtured*: `contracts/citation/cases.json` carries each pattern with the words the gate's message puts after *cites*, the samples a gate must refuse and the text it must quote back, and sentences that carry none of the five and must pass. The pattern is written in the subset both languages read the same way — no flags, because a flag is not part of a pattern string either tier can compile, so the ADR shape spells its letters in both cases. A sample is written as the parts a suite joins, because a rule tag spelled whole in that file would be a rule tag written outside the three places the rules allow one, and the two gate suites already spell theirs that way for the same reason.

The gate is what is held, not a copy of it: each tier compiles the file once, in `packages/devtools/src/citations.ts` and `packages/devtools/python/citations.py`, and the rule, the script and the write-time hook that runs them read that. Adding a sixth pattern is one edit to this file, and both gates refuse it with no line of either gate changed. Each tier's contract suite drives its own gate rather than the table under it, which is what holds the second half of the agreement — that neither gate carries a pattern of its own, read as silence over the sentences the fixture says cite nothing: the core suite runs the rule through the throwaway-tree runner, and the worker suite runs the script itself and reads the finding it prints. **The eleven become twelve**; the three forms, the two thin runners and the directory's place stand, and `contract_version` bumps to **10** (T-316).

## Amendment, 22/09/2026 — `credential-envelope` gets its fixture, and the format it is a fixture of

The set stays **twelve**: nothing joins it here. What changes is that the first of the two agreements the 21/09/2026 amendment above told to "get theirs or change form" got theirs. `credential-envelope` has declared *fixtured* since this record was written, with no directory and no manifest entry, and a golden sealed vector is only a contract if something can open it — the failure the redaction amendment names, an agreement describing itself. So the fixture landed with the **format** half beneath it: one AEAD, one versioned frame, a seal and an open in each tier, written down as an amendment to ADR 0005, which has called the envelope a versioned *format* contract since 2026-08-25 with the format nowhere. `contracts/credential-envelope/cases.json` carries the key, three frames that open with the plaintext each must yield, and seven that key does not open, each with the word its opener answers — among them a frame sealed with the version left out of the authenticated data, which is what holds an opener to supplying it while there is only one version to observe. Sealing is otherwise not fixtured and cannot be: a fresh nonce per seal leaves no frame reproducible, so what each tier is held to is opening the file's frames, refusing its bad ones in its words, and writing a frame of its widths. What did not land is ADR 0041's credentials provider, which is the first slice's that needs a credential. `contract_version` bumps to **11** (T-274); `cost-ledger`, the other of the two, is still owed its golden rows.

## The read predicate leaves the contract

`T-020`'s goal text said the worker "must render \[the read predicate\] identically". Swept against every document (2026-09-01), that reading fails: **no described worker behaviour reads under the predicate.** The Principal-first rule scopes the predicate to `packages/core` functions; the glossary's own line — "every **consumer** reads through the same predicate" — is scoped to consumers, and the worker's runs are producers by the glossary's example list. The worker's reads are a whole-tree git checkout at a commit (ADR 0024), unfiltered platform-state rows under a workspace-scoped role, and the nightly parse cross-check — which compares hash-by-hash against *every* row and would report false mismatches under any filter. The predicate applied to that read is not merely unnecessary; it is wrong.

What is genuinely cross-tier is the **column contract**: the worker writes the three visibility terms onto everything it lands — and `binding_id` on the source-derived rows and elements, which is where ADR 0023 puts it; a canonical entity carries no binding — "so the predicate has something to test everywhere it is applied" (ADR 0023). Absent or mis-carried columns make the app's predicate silently over- or under-filter — that is the failure the fixtures guard. The "one definition, N renderers, one corpus" problem stays entirely inside `packages/core/access/`, where ADR 0029 already placed it.

## SQL functions do not contradict stores-not-code

ADR 0005's contract is "data, never code" across the tiers. A SQL function is schema: authored by the app, which owns all DDL (ADR 0007), shipped in a migration, and living *in* the shared store the way a table does. Neither tier imports the other's code to call it; each speaks SQL to the store it already speaks SQL to. The precedent for the alternative — two codebases implementing the same protocol prose — is the Dust survey's `retries.ts`: 39 lines in one repo, 115 in the other. Pushing the claim/lease/heartbeat transitions into functions makes the transition *the database's act*, not two clients' agreeing interpretation of it.

## The suite: fixtures are the contract, each tier proves its own side

"One conformance suite both CIs run" is **one fixture set, two thin runners**: `packages/core`'s vitest and the worker's pytest each read `contracts/` and assert the same expectations, so a failure lands on the side that diverged. (Today one workflow, `check.yml`, runs both tiers; the property that matters is both suites reading one directory, and it survives the CIs splitting.) A single boot-both-tiers runner was rejected: it cannot name the guilty side, couples the toolchains, and its job is done better by the ordinary integration tests that arrive with `T-003`. The fixture directory is `contracts/` at the repository root — deployed by nothing, imported by nothing, readable by anything. The word is already used with qualifiers elsewhere (**answer contract**; ADR 0007's "the schema is the contract"); the unqualified word is reserved for this seam (ADR 0029), and the directory is that seam made checkable.

## The stamp check stays strict; the redeploy window is the accepted cost

The worker claims no job while its schema stamp does not match `__drizzle_migrations`, by its own rule, and no expand/contract discipline exists anywhere in the rules — ~~the deploy rule says only "migrations are forward-only"~~ (forward-only is ADR 0022's own decision and never the deploy rule's — ADR 0022's 2026-09-21 amendment, T-184; the point stands unchanged, only the record that holds it moves). Reconciliation: **keep the strict stamp**. Deploy order is already `migrate` → `app` → `worker` (ADR 0007), the worker's data layer is generated from the app's schema and checked in CI against it, so every schema change already implies a worker image; the "outage" is the minutes of the deploy that was happening anyway, and ingestion is queued work — delayed, never lost. The narrower check (a manifest of what the worker reads, diffed per migration) buys machinery no one needs while both deploys are ours. **Reopening condition, named:** the customer-hosted worker (v1.0), whose redeploy we do not control.

## The full graph rebuild is the worker's

ADR 0023's amendment moved the incremental delta into the app's commit transaction and left the full rebuild unassigned. It is the worker's: bulk derive is the worker's listed work, and the rebuild doubles as the parse audit the worker already owns. Still not a predicate read (above).

## Considered options

- **Keep a pnpm package named `contracts`** — the worker is Python; a package it cannot read is a contract in name only, and ADR 0029 had already sentenced it.
- **A dedicated third workspace running one boot-both-tiers suite** — cannot attribute a failure to a side; a third toolchain; rejected in favour of two thin runners over one fixture set.
- **The predicate as a cross-tier renderer contract with a shared corpus** — `T-020`'s own acceptance text, rejected on the sweep above: it would conformance-test behaviour the worker does not have and, in the parse auditor's case, must not have.
- **Narrow the stamp check / adopt expand-contract migrations** — both add a mechanism or a rule to avoid a cost (a deploy-window pause of queued work) that is currently near zero; deferred behind the named reopening condition.
- **A more specific directory name (`tier-contract/`, `conformance/`)** — avoids the word's fourth use, but surrenders the reservation ADR 0029 makes; the qualified uses are qualified precisely because the bare word means this seam.

## Consequences

- Top-level `contracts/` exists: a manifest naming the six agreements and their forms, and a fixture inventory the manifest must match. `packages/core/test/tier-contract.test.ts` and `apps/worker/tests/test_tier_contract.py` assert the same expectations against it from this PR on; fixtures (envelope vectors, lease-expiry cases, golden `llm_call` rows) join as `T-003`+ lands each piece, and the SQL functions land in migrations then too.
- `packages/contracts` is deleted. `Result` (`ok`, `err`, `attempt`, `normalizeError`) moves to `packages/core/src/kernel/`, the slot its doc comment reserved; `apps/api` imports `@better-answers/core/kernel`; `apps/web` loses a dependency it never imported.
- ADR 0005's 2026-08-25 amendment (the golden vector "in `packages/contracts`") is amended here-and-there: pointer added at the stale claim; the vector's home is ~~`contracts/envelope/`~~ `contracts/credential-envelope/`, the agreement's own id, which is this manifest's path convention and what every fixture written since follows (ADR 0005's amendment of 22/09/2026, T-274).
- ADR 0029's consequences gain skimmer pointers: the rename it ordered is enacted, and its six-item list overstates the predicate.
- ADR 0012 gains the enrichment-ordering amendment (same day, separate text): enrichment jobs read committed concepts; a run may enrich its own candidates before submitting its suggestion set.
- `CONTEXT.md` gains **lease** — the glossary already used the word undefined. `slice`-style architecture words (`agreement`, `fixture`, `conformance`) stay out.
- `T-020`'s acceptance criteria are amended to match: the predicate line becomes the column contract; the SQL functions' landing moves to the tickets that bring their tables.
