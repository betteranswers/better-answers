# Trust is derived from the file, told in a fixed set of words, and moved only by a check

Everything a reader is told about a concept's trust is derived from its OKF file by the spec's own rules and never stored in it: the tier from `verified[]` keyed on the `human:` prefix with **verifier ≠ generator** enforced on the producer part of the actor string; *Out of date* from `stale_after` alone — **absence means no shelf life**, as Google's reference implementation and every other consumer read it — while the owner's **review cadence** is a per-type workspace setting seeded from the type vocabulary (Certification, Insurance, Rate: twelve months; most types none) that batches *due a check* into a weekly digest and never touches the file; *Changed since checked* from a `content_hash` that is RFC 8785 canonical JSON of the frontmatter with `generated`, `verified`, `stale_after`, `status` and `iri` removed, scalars as source text, `sources[]` reduced to ordered `(resource, locator)` pairs with paths resolved to `/abs.md`, plus the body with `\r\n → \n`, trailing whitespace stripped and one trailing newline — so a heading rename or a swapped source un-checks and a source-title fix, a link rewrite or a `stale_after` edit does not, and every verify commit carries the per-document hash precondition. **Anyone with the Editor or Admin role who may view a concept and every source it cites may check it**; the person whose edit made the current version — of a concept or a composition; the accepter of a rewrite suggestion — may not; the owner stays answerable. Actor ids follow the spec's samples: a person is `human:<email>` (Liam, 27/08/2026 — the email is itself a credibility signal, as in Google's `human:jsmith@acme`), an agent is `better-answers-<purpose>/<version>` so verifier ≠ generator is visible on the string, a process is `process:better-answers-sync`; an import preserves the original `generated` and mints `process:better-answers-import` only where absent; an imported human id that is not a member gets an Admin-set **actor alias**. An **imported** check keeps the tier the file gives it and reads *Checked by <id> · imported*; a guide's action threshold names a rung **and an origin**, defaulting to any origin and tightened per guide. **Supersession** is derived, never keyed: `SUPERSEDES` when a concept's `sources[].resource` resolves to a `status: deprecated` concept of the same `type` (else `DERIVED_FROM`), inbound links revisited on every deprecation commit, chains walked with a visited set to the newest non-deprecated node; the platform also writes a `**Supersedes:** [old](/path.md)` body line as the writing convention and never parses it. A deprecated concept is reachable by IRI and from its successor, excluded from `find`, `ask` and asserting traversal, wears the word **Deprecated**, and sends one *cited concept deprecated* request per citing composition with *use the successor* inline; a discarded concept's row is *removed* and its evidence retired, never deleted, and its citers read *no longer exists*. A source that moved on since a check is told as one rider — **· source moved on** — with the reason (*source changed* · *source gone*) on the row and one open request per (concept, reason); the tier stands. An `Answer` minted without evidence is `status: draft`, reads *Unchecked · no evidence*, is hidden from `find` and `ask` and cannot be checked; its owner or an Admin moves it to `stable` once evidence is attached (ADR 0017 kept); the platform writes `stable` only there and on acceptance and reads whatever the file says. Editors and Admins run question sets and save an Answer from history; a Viewer asks, flags and may *suggest* one. Code-owned keys are `iri` (kept and flagged when hand-written on import), `generated` (moved only when `content_hash` moves), platform-written `verified` events and `status` on deprecate; every other key, nested unknown keys included, is preserved verbatim; the parser accepts `/abs.md`, `./rel.md` and bare `dir/x.md` and the emitter writes `/abs.md`, rewritten once in the import commit with Google's key order and the `verified` list form; `stale_after` is read as a date or a datetime with offset and written as the UTC date; every normaliser is a pure function in `packages/` with round-trip tests on Google's four sample bundles and openwiki's wiki.

We decided this because the file is the substrate any OKF consumer reads (`[OKF1]`, `[OKF2]`): a word the platform shows that another consumer of the same file could not derive — *Out of date* from an invented default, *Unchecked* over an imported human check — would make the platform disagree with the bundle it exports; because a hash two parsers must agree on has to be a specification, not a description; because a check must mean a second pair of eyes wherever the word appears or it means less than it says; because any citation of a deprecated concept is a derivation and only a same-type one is a succession — without that rule *use the successor* repoints a Brief at the wrong concept; because to a Sales reader "source changed" reads as "the fact changed"; and because forcing a second person before a typed Answer is usable is the bottleneck ADR 0017 refused.

## Considered options

- **The platform writes `stale_after` on every check** — policy dressed as knowledge; every check a content commit; the export carries the cadence as if it were the fact's shelf life.
- **Absence means stale after N months, computed** — contradicts every other consumer of the same file.
- **A workspace-wide twelve-month cadence** — treats a company address like an insurance certificate; the first import's queue reads *everything due* for good.
- **Owner-only checking** — one person's queue; the word reads *checked by the owner* and nothing else. **Any role, Sales included** — a thumbs-up, not a comparison against sources.
- **Hash the body only** — a swapped source keeps its check. **Hash every source key** — a title fix or the platform's own locator repair un-checks its own work.
- **Opaque per-member ULIDs for people** (the briefing's recommendation; ticket 16's rule) — no personal data in the file, stable across renames; Liam chose the spec's sample form: the email is the credibility signal a reader of the raw file wants, and the erasure map (ticket 24) carries the cost.
- **Imported checks earn no tier** — simple; the platform disagrees with the file it exports. **Imported checks count for actions too** — no vendor does. **A platform-origin threshold by default** — a migrated five-year library unusable on day one.
- **The `Supersedes:` line parsed** — a convention a reword breaks. **A `superseded_by` extension key** — rejected under `[OKF2]` (ticket 47). **Any `sources[]` link into a deprecated concept** — every derivation becomes a succession.
- **Two reader words for a source that moved on** — more precise; two more words on a badge. **Fold into *Changed since checked*** — says the concept changed when it did not.
- **A check as the only route from draft to stable** — with verifier ≠ generator, a second person before any typed Answer is usable; contradicted ADR 0017.
- **File-relative links on emit** (Google's agent rule) — break when a file moves directories; nobody renders on GitHub here.

## Consequences

- Reader words: **Deprecated** joins the seven; two **riders** — *· imported*, *· source moved on* — may follow *Checked by*; *changed since last verified* is now *changed since checked* everywhere. Nothing else reaches a badge; *source changed*, *source gone*, *due a check*, *shelf life ending* and *cited concept deprecated* are `verification_request` reasons.
- Every `verification` row carries `origin` (platform · imported) from commit; an imported event has no `content_hash`, so *Changed since checked* is never shown for it and the cadence reads its `at`. **Amends ADR 0014**: the hash normaliser above replaces "body + frontmatter minus the trust keys"; `verified[].by` for a person is `human:<email>`, not an opaque id; the `actor_alias` record joins the attached-by-IRI kind.
- **Amends ADR 0004**: a guide's action threshold names a rung and an origin, default any origin; roles are **levels** — Admin · Editor · Viewer — never job titles (Liam, 27/08/2026: the platform stays agnostic about who a bid writer is); where ADRs 0004, 0015–0018 say *Bid writer* read *Editor*, where they say *Sales* read *Viewer*.
- Personal data now lives in the bundle and its git history (`human:<email>` in `generated.by` and `verified[].by`): the erasure request (ticket 24) must name what happens to those strings — rewrite to the alias id in a history-rewriting commit, or retain under a documented basis — before the first ingest, and the DPIA lists it. `sources[].author` is still stripped for company-origin documents.
- The graph's derive (ticket 39) implements the same-type `SUPERSEDES` rule, the inbound revisit and the visited-set walk; `find` and `ask` land on the newest non-deprecated node. Knowledge keeps an Admin-only *include deprecated* filter.
- Ticket 50 settled the per-type cadence as a workspace setting keyed by the kind string (ADR 0026 — no vocabulary file; the seed values are platform defaults); ticket 41's CI runs the round-trip tests; ticket 37's citation-repair agent proposes the fix a *source moved on* request asks for; a check needs *view* on every cited source (ticket 24's sensitivity applies), else *cannot check — source restricted*.
- Words for `CONTEXT.md`: *review cadence*, *actor id*, *actor alias*, *shelf life*, *rider*, *Deprecated*, *Editor*, *Viewer*; avoid *stale* (for readers), *superseded by*, *TTL*, *expired*, *Bid writer* and *Sales* as role names.
- Reopens nothing in ADRs 0001–0003, 0005–0013, 0016, 0018; amends 0004, 0014, 0015 and 0017 by the role rename only.

## Amendment — 2026-08-27, the erasure line answered (ticket 24, ADR 0020)

`human:<email>` is retained under a documented basis while a person's checks stand and rewritten to `human:<member-id>` across history only on a valid erasure request; `verification.origin` gains **erasure-rewrite** so a hash the routine moved never reads *Changed since checked*. A `Person`'s ending word is **Left**, never *Deprecated*.
