---
status: accepted
title: "Records attach to concepts by IRI, are versioned where edited, and audited in one audit log"
applies_when:
  - "Adding a record family or a table that refers to a concept"
  - "Writing an action that must leave an audit event"
  - "Adding a version table for text a person edits"
---

A record attaches to a concept by `(workspace_id, iri)`, a composite foreign key to the concept's `concept_identity` row. The record never restates the concept. A list saved inside a column cannot be a foreign key, so a changed concept would reach its write-ups only by a scan, or not at all.

Only text a person edits gets a version table. A version table is append-only and has no status or current flag, because a flag that changes would make the table no longer append-only. Each workspace has one audit log, and ADR 0038 defines its shape.

## A copy is a usage row, not an audit event

When a write-up is copied out of the platform, the platform writes one `usage` row for each write-up version taken. The row names the version, the act, and who took it. It never holds the text. A copy is not an Admin action, a governed write, or a platform action, so it writes no audit event.

The `usage` table belongs to the `usage` slice. That slice imports only the kernel and the store's `Tx` type, so the guides and concepts slices can record a use without an import cycle through `answering`.

## A guide snapshot is a usage row, and an export is an audit event

Exporting a guide's prose takes each write-up version out of the platform. The export writes one `usage` row with the act `exported` for each version it carries. The export is also an Admin action, so it writes one audit event in the same transaction as its usage rows. A snapshot of the knowledge base writes an audit event and no `usage` row, because it takes no single concept into a document.

## Rejected

- One generic JSON version table, or before-and-after values in audit payloads. Neither has types, and a UI cannot list, diff, or restore that history.
- One audit table per action. Reading them needs a union across tables, and nothing can be queried by target.
