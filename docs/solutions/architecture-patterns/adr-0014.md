---
status: accepted
title: "Records attach to concepts by IRI, are versioned where edited, and audited in one audit log"
applies_when:
  - "Adding a record family or a table that refers to a concept"
  - "Writing an action that must leave an audit event"
  - "Adding a version table for text a person edits"
---

A record attaches to a concept by `(workspace_id, iri)`, a composite foreign key to `concept_identity`, and never restates the concept, so a changed concept reaches every record that cites it by a join. Only text a person edits gets a version table, which is append-only and has no status or current flag. Each workspace has one audit log (ADR 0038), and taking a write-up out of the platform, by copy or export, also writes one `usage` row per version taken, holding no text.

## Rejected

- One generic JSON version table, or before-and-after values in audit payloads. Neither has types, and a UI cannot list, diff or restore that history.
