title: "The worker composes cocoindex's blocks and writes only what the engine has no block for"
applies_when:
  - "Adding or changing a cocoindex pipeline, component, memo or target in apps/worker"
  - "Deleting a connected source's passage rows, for a wipe, an erasure or a rule change"
  - "Deciding whether the worker builds a piece of queue machinery or takes it from cocoindex"
---

The worker uses cocoindex's per-component commit, memoisation, target sync and one `Environment` per connected source, and writes its own code only for the queue, the catalogue, the landing and supervision. The only memo is the detector's, and it holds spans, never text, so a policy change does not rerun detection.

## Consequences

- A sync over a standing store does not re-upsert what it believes it already landed. Any deletion of a connected source's passage rows must also remove that source's store, or a withdrawn document's passages stay.
