title: "The worker composes cocoindex's blocks and writes only what the engine has no block for"
applies_when:
  - "Adding or changing a cocoindex pipeline, component, memo or target in apps/worker"
  - "Deleting a connected source's passage rows, for a wipe, an erasure or a rule change"
  - "Deciding whether the worker builds a piece of queue machinery or takes it from cocoindex"
---

The worker composes cocoindex's building blocks: per-component commit, memoisation, target sync, and one `Environment` per connected source. The worker writes its own code only where the engine has no block. That covers the queue, the catalogue, the landing, and supervision.

The only memo is the detector's. It holds spans, never text.

A sync over a standing store does not re-upsert anything it believes it has already landed. Any deletion of a connected source's passage rows must therefore come with the removal of that source's store. Otherwise the passages of a withdrawn document stay in place.

## Rejected

- One memo over conversion and detection that returns redacted text. Every policy change would run detection again, and an erasure would have to remove the store.
- The `finding` table as the cache. A wipe deletes the table's unmarked rows. A partial set of findings then reads as complete, and a document goes un-redacted with no error.
