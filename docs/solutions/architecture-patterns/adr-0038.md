status: accepted
title: "Groups are flat, an access request is answered neutrally, and the audit log is append-only"
applies_when:
  - "Adding a group, a member or a People page field"
  - "Writing an action that lands an audit event"
  - "Changing how a non-member asks to join a workspace, or how an Admin answers"
  - "Porting a page whose fields assume teams, several roles or access that expires"
---

A group is a flat set of a workspace's members, aligned with Entra groups, and changes what a person may see, never what they may do. There are no nested groups, no teams, no second role, no access that expires and no Suspended state, so an access check never walks a tree.

A non-member who asks to join a workspace by its short name gets the same neutral acknowledgement whatever the name resolves to, so the request cannot test which workspaces exist.

The database keeps `audit_event` append-only. Its migration revokes `UPDATE` and `DELETE` from `app_rt`, because a rule kept in code is one the next migration forgets.
