status: accepted
title: "Groups are flat, an access request is answered neutrally, and the audit log is append-only"
applies_when:
  - "Adding a group, a member or a People page field"
  - "Writing an action that lands an audit event"
  - "Changing how a non-member asks to join a workspace, or how an Admin answers"
  - "Porting a page whose fields assume teams, several roles or access that expires"
---

A group is a flat, Entra-aligned set of a workspace's members that changes only what a person may see, never what they may do, and teams, plural roles, temporal access and a Suspended state are not adopted. A signed-in non-member's access request is answered with one neutral acknowledgement whatever the short name resolves to, because a different answer for a real workspace and an unknown one would be an oracle over the tenant list. The audit log is an unpartitioned tenant table the database keeps append-only by revoked privilege, since append-only enforced in code is a convention the next migration forgets.

## Rejected

- Nested groups, or teams beside groups: a walk per check and a second concept for one set of people.
- Approving through Better Auth's invitation endpoint: it would import the identity provider into core.
- Month partitioning of the audit log: a policy-bearing partitioned table changes what the RLS suite proves, and a row-count trigger reopens it.
