title: "Better Auth runs in-process as the api's own authorization server, behind a seam"
applies_when:
  - "Importing better-auth, or reading a Better Auth table, anywhere outside the auth modules"
  - "Running work that outlives a person's session, such as a job, a scheduled run or a replay"
---

Better Auth runs inside the api as a library, so the api is its own OAuth 2.1 authorization server for MCP and runs email-code sign-in for the SPA with no extra process, backup or migration owner. In the api only `apps/api/src/auth/` imports it, and no Better Auth type crosses into `packages/core`, which a transport reaches with a `Principal` built from the verified token. A `Principal` is a `UserPrincipal` or the `PlatformPrincipal`, work that outlives a session runs as the platform principal, and the operator is a separate `OperatorPrincipal`.

## Rejected

- Keycloak. It is about 1.25 GB, needs a third-party extension for email-code sign-in, and keeps its configuration outside the repository.
- The MCP SDK's OAuth helpers. They work only with Express and are no longer developed.
