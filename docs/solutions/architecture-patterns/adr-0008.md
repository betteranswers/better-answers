The api runs as one process, and each class of caller gets its own contract from it:

- The SPA calls tRPC.
- Integrations get an OpenAPI document generated from the same router.
- Agents get the MCP server, which offers tools only.
- The share agent gets hand-written `/agent/v1` routes on the `agent.` hostname.

Each class wants something different. The SPA wants types, an integration wants a document, and an agent wants tools with descriptions. REST for all of them would lose the types. tRPC for all of them would lose the document and the tools. Every boundary validates with one library, zod, and that is what lets one router feed all of these contracts.

## Rejected

- REST and OpenAPI for everything. The SPA would lose end-to-end types, and MCP tools would wrap REST calls twice.
- GraphQL. It is a second schema language beside zod and OKF frontmatter, and nothing on the roster speaks it.
