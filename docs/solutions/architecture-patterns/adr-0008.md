title: "The SPA calls tRPC; callers outside get generated OpenAPI, MCP or /agent/v1"
applies_when:
  - "Adding a way for a caller to reach the api"
---

Each class of caller gets its own contract from the api's one process: the SPA calls tRPC, integrations get an OpenAPI document generated from the same router, agents get the tools-only MCP surface, and the share agent gets hand-written `/agent/v1` routes on the `agent.` hostname. Each class wants a different thing, types, a document, or tools with descriptions, and REST for all three loses the first while tRPC for all three loses the other two. One validation library at every boundary, zod, is what lets one router feed all of them.

## Rejected

- REST and OpenAPI for everything: the SPA loses end-to-end types, and MCP tools would wrap REST calls twice.
- GraphQL: a second schema language beside zod and OKF frontmatter, which nothing on the roster speaks.
