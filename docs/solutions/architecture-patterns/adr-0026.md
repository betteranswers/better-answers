title: "Kinds emerge from the concepts; a link is the relation and is never named"
applies_when:
  - "Adding a field, a table or a check that lists or validates concept types"
  - "Adding an edge label to the map, or a relation between concepts"
  - "Adding a key to a concept file that names how two concepts relate"
---

A concept's kind is the short string its producer chose. The platform folds it when the concept is written. The Kinds list is derived from the concept index. No vocabulary file declares the kinds, and no check refuses a kind that a list leaves out.

A relation between two concepts is the markdown link in the concept's body. The map stores that link as a `LINKS_TO` edge that carries the link's sentence. The relation has no name. The map has six edge labels, `LINKS_TO` and five named edges, listed in `MAP_EDGE_LABELS` in `packages/schema/src/knowledge/map-tables.ts`.

OKF's first non-goal is a fixed taxonomy. A typed relation would add an edge label to the map and change nothing on the answer path, because the drafting model reads the link's sentence anyway.

## The Kinds page counts and never names

The Kinds page lists each kind with its count, in total and per collection. It reads the counts from the concept index under the read predicate, so a count never reveals a concept the reader cannot see.

The page offers no rename and no merge. A kind is whatever its producers chose, and a registry that someone has to tend is what this decision rejects. Story S7 renames a kind by rewriting the concept files.

## Rejected

- A vocabulary file per tenant, with a closed-world check. The file would restate what the concept files already say, and an Admin would have to maintain it as a registry.
- A `relations` key beside the body link. The owner rejected it.
- A list of relations, matched against link sentences. It goes wrong without any error when two relations share the same pair of kinds, and someone has to maintain the list.
- Predicates as a fixed platform list. Every workspace's bundle would carry the platform's vocabulary.
