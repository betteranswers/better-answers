title: "Kinds emerge from the concepts; a link is the relation and is never named"
applies_when:
  - "Adding a field, a table or a check that lists or validates concept types"
  - "Adding an edge label to the map, or a relation between concepts"
  - "Adding a key to a concept file that names how two concepts relate"
---

A concept's kind is the short string its producer chose, folded at write, and the Kinds list is derived from the concept index with no vocabulary file and no closed-world check. A relation between concepts is the markdown link itself, a `LINKS_TO` edge carrying its sentence, and is never named; `LINKS_TO` and five named edges are the map's only edge labels. OKF's first non-goal is a fixed taxonomy, and a typed relation would be an edge label on the map and nothing on the answer path, since the drafting model reads the sentence anyway.

## Rejected

- A per-tenant vocabulary file, checked closed-world: a list restating the concept files, and an Admin tending a registry.
- A `relations` key beside the body link: rejected by the owner on 26/08/2026.
- A relations list with sentence matching: silently wrong on shared kind pairs, and a registry someone maintains.
- Predicates as a fixed platform list: platform vocabulary in every workspace's bundle.
