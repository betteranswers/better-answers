status: accepted
title: "A workspace's model key is sealed under the envelope key and opened only by the api at the moment of a call"
applies_when:
  - "Setting, reading or rotating a workspace's model key"
---

A workspace's model key is sealed under the envelope key and never hashed, because the platform sends it to the provider with every call and a hash cannot be sent. The api tier alone holds the envelope key and opens a model key at the moment of a call, the worker holds no grant on `model_key`, and setting a key is an audit event while a read is accounted for by its `llm_call` row. No command re-seals, so a new envelope key means every model key is set again, and after a compromise every key sealed under it is reissued at its provider, not only sealed again.

## Rejected

- Hashing behind a lookup prefix, the provider's shape for tokens the platform checks: a hash cannot be sent to a provider.
