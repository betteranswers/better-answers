status: accepted
title: "A boundary schema is generated from its table and a refinement only narrows it"
applies_when:
  - "Adding a table, or a column to one, in packages/schema"
  - "Validating a row or an input against a table's shape with zod"
  - "Branding an id or narrowing the values a column accepts"
---

`drizzle-zod` generates the select, insert and update zod schemas for every table, in `packages/schema` alone, because hand-written schemas drift from their tables. A refinement is a per-column callback that may only narrow its column. The types never check this, and a refinement written as a plain schema drops the column's nullability, so `packages/schema/test/boundary-schemas.test.ts` proves against a real Postgres that each refinement narrows.
