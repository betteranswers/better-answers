status: accepted
title: "The model client is one fetch-shaped seam with a registry of wire shapes"
applies_when:
  - "Calling a model from the api tier, for any purpose"
  - "Adding a provider, a model host or a wire shape a model choice can name"
  - "Proposing a provider's SDK, a gateway library or a second path to a model"
  - "Testing code that calls a model"
---

Every model call the api tier makes goes through one fetch-shaped seam in core's `llm` layer, `packages/core/src/llm`. A registry keyed by provider holds the wire shapes: the Messages API and one decision-model shape. The caller injects the fetch function, so a test fakes the wire and never the platform's own code.

The platform adds no provider SDK. A fake at the wire tests the code that builds a request and reads a response. A mocked SDK tests only the mock.

## Rejected

- A provider's SDK, or a gateway library that speaks to many providers. Either one is a second path to a model beside the seam, and a test cannot fake it at the wire.
- Falling back to another model when a call fails. The fallback would be a judgement nobody chose, at a price nobody set.
