status: accepted
title: "The MCP surface is MCP SDK v2 in apps/api, behind one fetch-shaped seam"
applies_when:
  - "Changing the MCP surface, its entries or the library under it"
  - "Proposing FastMCP, a Python MCP server or an MCP App framework"
  - "Proposing an outbound connector, a sync or a write into a system that is not a connected source"
---

The MCP surface is built on the MCP SDK in `apps/api`, reached through one fetch-shaped seam that verifies the bearer and runs each entry under a `Principal`, so the library choice sits behind the seam and can be reversed in an afternoon while the tier placement cannot. FastMCP's real advantage is authentication and it is Python-only, hanging off an OAuth proxy where someone else owns the accounts, while ADR 0009 makes the platform its own authorization server. The platform builds no connector into a system that is not a connected source, because the Claude platform is the integrator there, reaching it through the person's own MCP servers with credentials we never hold.

## Rejected

- FastMCP Python, with the MCP surface moved to the worker: it would put a transport across the tier boundary from the Principal and the predicate.
- Outbound connectors, an OAuth client or a sync engine into third-party SaaS that is not a connected source: a nightly sync with no person in the loop would be a new ADR and a new deployable.
