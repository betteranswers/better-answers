applies_when:
  - "Writing a test, and choosing whether it runs in-process, on a real store, as a process or image, in a browser or on the schedule"
  - "Adding a store door, or a slice that reads or writes through one"
  - "Adding a browser spec, or a regression test for a bug a page shows"

The rule was that every test uses the real Postgres, object store, git repository and map. The suites' time went to seeding loops, serial process launches, readings that assert nothing and the browser's test count, not to claims about a store. A test now sits at the lowest of five layers that can see its claim, which are in-process unit tests, integration tests on a real store, process and image tests, the browser, and readings and budgets on a schedule. A real store stays the claim for row-level security and zero-rows (ADR 0032), migrations and DDL (ADR 0007), the SQL a slice runs for visibility, walks and sensitivity folds (ADRs 0023, 0032 and 0044) and for ranking, locks and races, governed commits and history rewrites (ADRs 0012 and 0024), the erasure rehearsal, boundary-schema parity (ADR 0028) and the tier contract's SQL agreements (ADR 0031). A decision over rows already read is a pure function on its slice, tested in-process, so the unit layer needs no stand-in for a store, and the four store doors of ADR 0029 stay concrete.

## Rejected

- PGlite as an in-process Postgres. It applied all 99 migrations and held row-level security, but a fresh database per file took a median of 274 ms against 86 ms for the container's template clone (n=5 each). It has one backend, so two clients share a pid, a role and an advisory lock, and a lock or race test passes without testing anything. A `pg.Pool` that sets the role `app_rt` came up as the superuser and saw both tenants' rows. Core takes a `pg.Pool`, and no adapter maps PGlite onto it.
- In-memory store doors behind ports. `ObjectDoor` holds an S3 client and `GitDoor` a root, and slices write SQL inline in 94 of the 176 source files under `packages/core/src` at commit 981da2858. A fake Postgres door cannot reproduce row-level security, recursive walks or locks, and a port with one real adapter is a port `.claude/skills/survey-architecture/references/deepening.md` forbids. No slow test's cost was the object store.
- A module-mocking layer for unit tests. The `anti-slop/no-module-mocking` lint bans every vitest or jest module mock, and the worker's conftest guard bans a mock of this repository's own code. Pure functions and the injected seams that exist, such as the clock, the model client's fetch function (ADR 0049) and the Better Auth seam (ADR 0009), carry the unit layer.

## Consequences

- In `packages/core`, a test reaches the files of the one `src/` directory its folder mirrors, `test/<x>/` for `src/<x>/` and `test/store/<door>/` for `src/store/<door>/`, and every other directory only through an `index.ts` the `exports` map names, and the `import-direction` lint holds it.
- No decision under `docs/solutions/architecture-patterns/` is superseded. The rules that move are AGENTS.md's real-store bullet under *Testing*, the browser spec for every web change and web bug in `.agents/playbooks/verification.md`, and the browser-suite skill's rule that a page is never asserted against its source.
