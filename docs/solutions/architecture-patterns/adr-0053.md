A test sits at the lowest layer that can see its claim. There are five layers, from lowest to highest:

1. In-process unit tests.
2. Integration tests on a real store.
3. Tests of a process or an image.
4. Browser tests.
5. Readings and budgets that run on a schedule.

The previous rule had every test use the real Postgres, object store, git repository, and map. The suites' time went to seeding loops, process launches run one after another, readings that asserted nothing, and the number of browser tests. Little of it went to claims about a store.

A real store stays where the store is the claim:

- row-level security and zero rows (ADR 0032)
- migrations and DDL (ADR 0007)
- the SQL a slice runs for visibility, walks, and sensitivity folds (ADRs 0023, 0032, and 0044), and for ranking
- locks and races, governed commits, and history rewrites (ADRs 0012 and 0024)
- the erasure rehearsal
- boundary-schema parity (ADR 0028)
- the tier contract's SQL agreements (ADR 0031)

A decision over rows that a slice has already read is a pure function in that slice, and its test runs in-process. The unit layer therefore needs no stand-in for a store, and the four store doors of ADR 0029 stay concrete.

## Rejected

- PGlite as an in-process Postgres. It applied every migration and held row-level security. A fresh database per test file took a median of 274 ms, against 86 ms for the container's template clone (n=5 each). PGlite has one backend, so two clients share a pid, a role, and an advisory lock. A lock or race test then passes without testing anything. A `pg.Pool` that set the role `app_rt` came up as the superuser and saw both tenants' rows. Core takes a `pg.Pool`, and no adapter maps PGlite onto one.
- In-memory store doors behind ports. `ObjectDoor` holds an S3 client and `GitDoor` holds a root path. Slices write SQL inline in more than half of the source files under `packages/core/src`. A fake Postgres door cannot reproduce row-level security, recursive walks, or locks. A port with only one real adapter is the kind of port that `.claude/skills/survey-architecture/references/deepening.md` forbids. The object store made no slow test slow.
- A module-mocking layer for unit tests. The `anti-slop/no-module-mocking` lint bans every vitest or jest module mock. The worker's conftest guard bans a mock of this repository's own code. Pure functions and the injected seams that already exist carry the unit layer. Those seams include the clock, the model client's fetch function (ADR 0049), and the Better Auth seam (ADR 0009).

## Consequences

- In `packages/core`, each test folder mirrors one `src/` directory: `test/<x>/` mirrors `src/<x>/`, and `test/store/<door>/` mirrors `src/store/<door>/`. A test may reach any file in the directory its folder mirrors. It reaches every other directory only through an `index.ts` that the `exports` map names. The `import-direction` lint enforces this layout.
- No decision under `docs/solutions/architecture-patterns/` is superseded. Three rules outside the ADRs changed with this one. They are the real-store bullet under *Testing* in AGENTS.md, the browser spec for every web change and web bug in `.agents/playbooks/verification.md`, and the rule that a page is never asserted against its source, which now lives in the playwright-specs skill.
