  - "Adding a store, a column or a copy that could hold a person's identifier"

## The decision

The **redaction seam** withholds personal data in the worker's conversion step and on the read-live tool's return. It runs before splitting, embedding, extraction and every model call, so no derived store and no model ever holds the value. The original bytes stay in the object store. Only an Admin opens them, and each view is an audit event.

- **Sensitivity** has three classes: Restricted (the default for every connected source and every `Person`), Internal and Public. Only *Restricted* is a reader word; the other two are Admin words.
- **Redaction rules** have three tiers: *always* (special-category cues, financial account and government identifiers), *default on* and *default off* per connected source. No connected source switches the always set off. The officer-block rule always wins. Special-category data narrows its document to Restricted on landing.
- One declared descriptor per category, in `apps/worker/src/better_answers_worker/redaction/descriptors.py`, feeds the recognisers, the category list and `rule_version`. A window begins where the document begins something: a heading, then a paragraph.
- A **finding** is its document, its rule and its two offsets into the normalised text. Its category, tier, score and version pair are the last sync's reading of it.
- An Admin's restore, *keep in text* or special-category dismissal reaches the next sync as an argument, never a change key. An erasure outranks all three.
- The seam answers one **withholding** per finding and never rewrites a finding.

Text a person types, such as a question or a note on a flag, never passes the worker's seam. The **typed-text check** covers it in the api tier.

- Before any model call, the check reads typed text against the always tier and replaces each hit with a placeholder in what the model is sent. The record keeps the text as typed.
- Core reads the three always-tier categories with detectors of its own. Cases in `contracts/redaction` hold them to the worker's, and both tiers run every case. A change to the worker's always-tier patterns moves its rule version, and core changes in the same pull request.
- The worker reads a cue, and the word that names a sort code and account number, through its tokenizer. Core has none. The worker finds a cue by taking an ending off the written word. So core reads any word that opens with a cue's stem as a cue, a misspelt one included. The worker reads five words before the pair. Between the pair's two numbers it reads only a naming word, whole or as its plural. Core reads all the text before the pair, and whole words between its numbers. Core's reading is made the wider of the two, so that a difference between them withholds more and not less.
- The limit is stated: a name in typed text is not withheld. The always tier is patterns, which the api tier can read. A name needs the detector's model, which the api tier cannot read.
- A special-category cue withholds its whole sentence, so a one-sentence question that holds one reaches the model as a placeholder alone.
- The check is `checkTypedText` in core's `llm` layer. Its callers are the ask's model calls on a question, the judge and the draft, in core's `answering` slice.

The erasure routine rewrites what the platform wrote; a person edits what the company wrote.

- Every actor id the platform wrote (files, history and its commit trailers, `bundle_commit` rows, verification rows, sensitivity overrides, a finding's reviewer and restorer, git author lines by mailmap) becomes `human:<erasure pseudonym>`, one pseudonym per workspace. The audit log is never rewritten: it names a person by person id.
- A reason the person typed is replaced by what its table's CHECK allows. A finding's review reason becomes NULL. Its restore reason becomes the empty string, because `finding_restore_check` needs one on a restored finding. A suggestion's reason becomes "Removed when its author's personal data was erased.", because `suggestion_reason_length_check` refuses an empty one.
- Who proposed and who decided a suggestion become `human:<erasure pseudonym>`, through `erase_from_the_suggestions`. `suggestion_decides_once` lets only the table's owner rewrite a decided suggestion, and then only those names and the reason.
- A write request is rewritten as the bundle's files are, through `erase_from_the_write_requests`, because the api holds no privilege on the table. `human:<address>` and `human:<person id>` in its title, frontmatter and body become `human:<erasure pseudonym>`. A needle ends at an address boundary, so `a@b.co` never matches inside `a@b.com`. The request is kept, so an Admin can still accept a waiting suggestion, and accepting it cannot write the person back into the bundle.
- A pseudonym can be longer than what it replaces, so a body near its limit can outgrow it. That body becomes a fixed sentence rather than being cut, and a waiting suggestion it belongs to is returned with that sentence as its reason, decided by the erasure. The report counts these as `bodiesReplaced`. A cut body would be accepted as a concept nobody wrote, and a failed rewrite would leave the person in the request on every rerun.
- One value names the person: their person ids and addresses (`Needles`). The routine forms it once per run, from the request, the member it finds, the sign-in addresses, the request's suppression and every user who signs in with one of those addresses. The erasure map, the history rewrite and every actor sweep read it.
- A member's commit to the bundle holds their member row until the commit has landed in Postgres. A git step that overruns its one-minute budget fails, and frees the row. So ending the member waits for a commit under way, and refuses a later one. The routine rewrites history a second time once the member has ended.
- When this is the person's last workspace, it pseudonymises the user row (email to a tombstone, name cleared, id kept) and deletes their sessions, verification rows, invitations and linked accounts. It ends the person as a member here on every arm.
- It reaches *Questions asked* on every arm, in the erasing workspace alone. Who asked and who gave feedback become `human:<erasure pseudonym>`, the question is deleted and each note and each disputed sentence is cleared. The record's skeleton stays (ADR 0017).
- Erasure alone may leave a workspace with no Admin. The operator repairs it with `pnpm ops add-member`.
- It clears the operator's mark where the person carries one.
- It writes its replay copy to the object store, under `erasures/<workspace id>/`, before the completion commits.
- Its stored report tells the erasing workspace nothing of another. The operator's log line says which arm ran.
- Names inside concept bodies are listed for the owner to edit.

A **suppression** belongs to the workspace. There is one per erasure request, and it holds the request's identifier set and the addresses the person signs in with. The seam withholds every exact occurrence of those identifiers each time a document of the workspace, held now or bound later, is indexed. Recording a subject request refuses an identifier too broad to withhold (`identifier-too-broad`). An access answer is locations and categories, never a passage.

The platform emits a **DPIA input** per connected source: its data types, scope, sensitivity class, the redaction rules in force, each model choice with its processor, country and retention tail, the retention class and the audience. The publish action's audit row carries its totals and its hash.

- A workspace's embedding model choice is fixed once any vector exists. Its hosted provider is listed in the DPIA input and in the platform's sub-processor list only from the day that model choice is first called, never ahead of the processing. The local model choice names no sub-processor.
- Four questions are owed to a lawyer, recorded as owed and answered by no build: a six-month governance-locked tier under Article 17, with re-apply-on-restore as beyond use; RPO, RTO and the beyond-use period as contract terms; healthchecks.io and GitHub as sub-processors that hold no personal data; and whether a forward edit satisfies Article 17 for a capability statement that names an employee, which is knowledge the company asserts about itself.

## Why

- The first corpus's most useful file is also the flagged one. Setting it aside is the manual work the product exists to remove. Role-gating in place puts a sort code in four stores and at a processor.
- A placeholder written before splitting is the one control that holds whatever a predicate, a prompt or an assistant's context later does with the text.
- No detector clears 0.6 F1 on independent benchmarks, so the design is detector plus review by category plus a Restricted default.
- The first Admin is a bid writer, not a DPO, so the safe set must be what they get by doing nothing.
- An actor id is a record, so the platform may rewrite it across history. A name in a concept body is knowledge the company asserts about itself (ADR 0011); rewriting it would make every export already issued diverge.
- A pseudonym that is never the person id means two workspaces' rewritten histories cannot be joined on one person (ADR 0035).
- A per-document suppression missed documents bound later, not yet indexed, unreadable, or withheld by a rule later switched off.
- One rule switch must never re-extract fifty thousand documents through a hosted model choice.

## Rejected

- Two classes, or a five-level government scheme: one word for the website and the board minutes, or levels nothing acts on.
- Quarantining flagged documents, or role-gating the passages: the useful file is the flagged one, and the value reaches every store.
- Pseudonymising every name, or nothing by default: a worse answer, or an unsafe default.
- A publish block on special category: blocking widening is the control.
- Reprocessing on a connected-source-wide rule version: about £750 and two days for one switch.
- Rewriting on every leaver, or never rewriting: every clone diverges, or "we cannot" is not a basis.
- Typed placeholders for the always set, or an "incomplete" hint: each tells the reader what exists.
- A targeted text replacement over concept bodies: it rewrites what the company asserts.
- A keyed hash of each finding's value: a hash of a value is the value.
- Calling no model when a question holds an identifier, or sending a question as typed: a person who pastes a form row with an account number gets no answer, or the number reaches a provider. What is given up is a name: one typed into a question reaches the model.
