status: accepted
title: "Business logic is capability slices over four store doors in packages/core, under one import-direction lint rule"
applies_when:
  - "Adding a slice, a store door or a directory under packages/core/src"
  - "Importing from one slice into another, or from a transport into packages/core"
  - "Writing a query against a table another slice owns"
  - "Adding a deployable under apps/"
---

`apps/` holds what deploys, and `packages/` holds what other code imports. `apps/api` holds transports only.

Business logic lives in `packages/core`, as capability slices over four store doors: `postgres`, `git`, `map`, and `objects`. A kernel holds `Principal`, the branded ids, and `Result`. One lint rule, `import-direction`, places both ends of every import in a zone and checks the direction between them.

Business logic has five callers. Four of them have no notion of an HTTP status code, so the logic cannot belong to the HTTP transport.

## Rejected

- A directory plus a lint rule, with no export list. The interface would hold by convention alone.
- Vertical slices that never import from each other. The slices share one database, so the rule forces duplicated queries or a `shared/` directory that collects whatever does not fit.
