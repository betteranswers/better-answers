title: "The tier contract is a list of agreements in three forms, each proved by both tiers' suites"
applies_when:
  - "The api and the worker both read or write the same value, list or format"
  - "Adding a fixture, a SQL function or an agreement under contracts/"
  - "Changing a queue function, the credential envelope or the shape of an id"
  - "Deploying a schema or contract change the worker has to match"
---

When the api and the worker must give the same answer, the answer is an agreement under `contracts/`: a SQL function both tiers call, a golden fixture both suites read, or rows generated from one source. Each tier's suite proves every agreement from its own side, so a failure lands in the tier that diverged. `migrate` stamps a digest of `contracts/` into `contract_stamp`, and the worker checks it against its own digest before it claims a job.

Two codebases that implement the same prose drift apart. A shared pnpm package would not help, because the Python tier cannot read it.
