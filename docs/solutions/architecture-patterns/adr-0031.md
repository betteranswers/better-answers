status: accepted
title: "The tier contract is a list of agreements in three forms, each proved by both tiers' suites"
applies_when:
  - "The api and the worker both read or write the same value, list or format"
  - "Adding a fixture, a SQL function or an agreement under contracts/"
  - "Changing a queue function, the credential envelope or the shape of an id"
  - "Deploying a schema or contract change the worker has to match"
---

Every answer the api and the worker must hold alike is an agreement in top-level `contracts/`, in one of three forms, a SQL function both tiers call, a golden fixture both suites read, or rows generated from one source, and each tier's suite proves it from its own side so a failure lands on the side that diverged. The contract's version is a digest of the directory that `migrate` stamps and the worker compares before claiming a job. Two codebases implementing the same prose drift, and one survey found a shared helper at 39 lines in one repository and 115 in the other.

## Rejected

- A pnpm package named `contracts`: a contract the Python tier cannot read.
- One boot-both-tiers suite in a third workspace: it cannot name the side that diverged.
