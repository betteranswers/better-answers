applies_when:
  - "Importing anything from apps/api into apps/web"
  - "Adding a way for the SPA to reach the api other than tRPC"
  - "Proposing server-rendered pages or a public site"
---

The api is one long-running Hono process on Node that runs tRPC, the MCP server and the authorization server, and serves the Vite React SPA on the same origin. It holds MCP sessions and each workspace's model routing, which suit a process that starts once, and every page sits behind sign-in, so server rendering would solve a problem no page has. The SPA reaches the api only through tRPC, which gives it end-to-end types from the zod schemas every boundary validates with.

## Rejected

- REST or GraphQL for the SPA. REST loses the end-to-end types, and GraphQL is a second schema language beside zod.
