The api is one long-running Hono process on Node. It runs tRPC, the MCP server, and the authorization server. It also serves the Vite React SPA on the same origin. The SPA is built separately.

The api is a service first and a website second. It holds MCP sessions and each workspace's model routing, and a process that starts once fits that work better than a framework built around single requests. Every page sits behind sign-in, so server rendering would solve a problem that no page has.

## Rejected

- Next.js. It couples the interface and the API in one runtime built around requests. It brings Vercel's conventions to servers the project hosts itself, and it makes the MCP server a guest inside a page framework.
- Bun as the runtime. The repository pins Node LTS in `package.json`, and the MCP SDK, Vitest, and Testcontainers target Node.
