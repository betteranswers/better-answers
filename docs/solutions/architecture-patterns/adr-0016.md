title: "An answer asserts concepts only, found by traversal and served as one verdict-first contract"
applies_when:
  - "Changing how an answer finds, reuses or drafts from concepts"
  - "Adding an endpoint or a transport that returns an answer"
  - "Changing the entry step's search or adding embeddings to it"
---

An answer asserts only what a concept states. The api finds those concepts before it writes any prose, by traversing the map from full-text entry points. Every `Answer` concept that fits comes back word for word, side by side with the others. The api never blends them.

The api serves an answer as one event stream, with the verdict first. One pure function folds the stream into one object, and the UI, MCP, and the record all use that object.

A sentence generated from document passages belongs to no knowledge layer, so no trust word can describe it. Once someone pastes that sentence into a tender, nobody can take it back.

## Rejected

- Drafting from documents when no concept answers. The result is fluent prose that nobody owns.
- Two contracts, one per transport. They would drift apart, and the single renderer exists to prevent that drift.
- A cross-encoder reranker in v0.1. It costs seconds per query on a CPU for a marginal gain.
