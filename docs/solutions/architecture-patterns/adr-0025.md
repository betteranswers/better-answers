A signal is a named query over rows the platform already keeps, with its threshold a config row an Admin changes on System, and there is no metrics store, no scrape and no dashboard product. Every model call writes one `llm_call` row with its tokens, seconds and priced cost and never the prompt or completion, and that row feeds the spending limit, price drift and replay spend. Every signal a sync emits is already a row or a count over rows, so no instrumentation is added, and a threshold in code would make every tune a release.

## Rejected

- A metrics store now, VictoriaMetrics or Prometheus with Grafana: 0.5 to 1 GB on a 4 GB box, a second login, and signals a restore does not bring back.
- Spend derived from _Questions asked_ and the syncs' job rows: it loses enrichment and embedding calls and cannot price a sync mid-flight.
