title: "A write-up cites its concept by a footnote labelled by the include"
applies_when:
  - "Storing, rendering or copying a guide section's Brief or a response"
  - "Building the write-up editor or its markdown round trip"
  - "Minting an `Answer` concept from a response at the promotion gate"
---

A write-up's prose is stored as markdown, and every claim that rests on a concept carries a footnote reference labelled with the include's id, such as `[^i7]`. The include row holds the IRI, the chosen wording and the content hash, and the renderer builds the footnote text from it, so no stored definition goes stale on a rename. The mark must survive editing, because the guide page puts the passage beside the claim and a copied text keeps its citations, so the Tiptap 3 visual editor and the CodeMirror 6 source editor both round-trip the markdown, and a body the visual editor would change opens in source mode.

## Rejected

- A markdown link on the claim, pointing at the IRI. It cannot say which wording or which version it cites.
- A rich-text editor that stores JSON or HTML. One text would have two formats.
