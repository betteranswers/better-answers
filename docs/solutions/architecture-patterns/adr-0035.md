status: accepted
title: "A person has one platform-minted id, carried on every Principal and every record the platform keeps"
applies_when:
  - "Naming a person on a record, an audit event or a commit"
  - "Minting an id in either tier"
  - "Writing an erasure step or declaring an audit action"
---

A person has one id: the id of their `user` row in the identity set. The platform's one ULID minter creates it. Better Auth receives the same minter as its `generateId`.

The id is `userId` on every `Principal`. Every record the platform keeps names the person as `human:<person id>`. A concept file is the exception, and it keeps `human:<email>`.

A person named by three ids is joined by none of them.

## Rejected

- A pseudonym per workspace as the everyday id. Every record would carry two ids for each person.
- Better Auth's own id shape. The platform would have two id shapes and two refinements, and the Python tier could not pin a fixture for both.
- One global id that erasure rewrites every erased person's records to. Records held by different controllers could still be linked to each other.
