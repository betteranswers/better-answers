A person has one id, the identity set's `user` row id, minted by the platform's one ULID minter that Better Auth is also handed as its `generateId`. It is `userId` on every Principal and `human:<person id>` on every record the platform keeps, while a concept file keeps `human:<email>`. A person named by three ids is joined by none of them.

## Rejected

- A per-workspace pseudonym as the everyday id: two ids per person on every record.
- Better Auth's own id shape: two shapes, two refinements, and a fixture the Python tier cannot pin.
- One global rewrite target on erasure: linkable across controllers.
