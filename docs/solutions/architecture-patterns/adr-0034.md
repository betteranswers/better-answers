One origin, `app.<apex>`, carries the SPA, sign-in, consent, `/oauth2/*`, `/.well-known/*`, and `/mcp`. `app.<apex>/mcp` is the `resource` in the protected-resource document and the audience of every access token.

Two hosts that share one session need a cookie scoped to the apex. That cookie sends the product's own bearer token to every subdomain, including any subdomain a third party might serve in future.

The issuer moved before any assistant held a credential, so the move cost nothing. A later move would have broken every assistant's connection.

## Rejected

- Keeping `mcp.` as a resource host that accepts bearer tokens only. It would be a second host that serves documents, and it would need a fence across four hostnames to protect one path.
