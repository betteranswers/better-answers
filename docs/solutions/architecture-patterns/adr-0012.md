---
status: accepted
title: "The api alone writes the bundle, one governed commit per action that the reconciler can replay"
applies_when:
  - "Writing any action that changes a workspace's bundle"
  - "Adding a row that is written in a governed write's transaction"
  - "Changing the reconciler, the head check or `pnpm ops reconcile-watermark`"
---

Only the api writes a workspace's bundle, and each governed action makes one commit. The api holds a lock from the hash precondition through the Postgres `COMMIT`. It mints the `audit_event` id first and writes it into the commit's `Audit:` trailer.

The action's rows land in the member's transaction after git has the commit. The `bundle_commit` history is therefore always a prefix of git history, and the reconciler replays from a watermark with no gaps to look for. The id is minted before the commit because the reconciler exists for one case: a commit whose rows were never written. An id minted after the commit would be missing from the trailer in exactly that case.

A governed commit lands only on a head that `bundle_commit` records. A commit whose rows were lost stays the head until the reconciler replays it. Until then, the api refuses a governed write with `unrecorded-head`.

## Rejected

- Landing agent output as `status: draft` when it arrives. Every wrong atom would need a clean-up commit in a permanent history.
- Admins clone and push, and the platform checks each push when it arrives. The rules would live in two places, and the history would be one the platform did not make.
