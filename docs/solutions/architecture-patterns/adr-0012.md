status: accepted
title: "The api alone writes the bundle, one governed commit per action that the reconciler can replay"
applies_when:
  - "Writing any action that changes a workspace's bundle"
  - "Adding a row that is written in a governed write's transaction"
  - "Changing the reconciler, the head check or `pnpm ops reconcile-watermark`"
---

Only the api writes a workspace's bundle, one commit per governed action under a lock held from the hash precondition through the Postgres COMMIT, with the `audit_event` id minted first and carried in the commit's `Audit:` trailer. The action's rows land in the member's transaction after git has the commit, so `bundle_commit` history is always a prefix of git history and the reconciler replays from a watermark without hunting for holes. An id minted after the commit would leave the trailer empty exactly when the row was never written, the one case the reconciler exists for.

## Rejected

- Landing agent output on arrival as `status: draft`: every wrong atom becomes a clean-up commit in a permanent history.
- Admins clone and push, checked on arrival: rules in two places and a history the platform did not make.
