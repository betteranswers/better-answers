title: "The api alone writes the bundle, one governed commit per action that the reconciler can replay"
applies_when:
  - "Writing any action that changes a workspace's bundle"
  - "Adding a row that is written in a governed write's transaction"
  - "Changing the reconciler, the head check or `pnpm ops reconcile-watermark`"
---

Only the api writes a workspace's bundle, one governed commit per action. It mints the `audit_event` id before the commit and writes it into the `Audit:` trailer, and it lands the action's rows only after git has the commit, so `bundle_commit` is always a prefix of git history and the reconciler can replay a commit whose rows were lost. Until the reconciler replays it, that commit stays the head and the api refuses every governed write with `unrecorded-head`.

## Rejected

- Admins clone and push, and the platform checks each push. The rules would live in two places, and the history would be one the platform did not make.
