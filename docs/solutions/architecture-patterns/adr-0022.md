Production is a Coolify Postgres resource and two Compose stacks on one box, `stores` redeployed only for a store upgrade and `platform` on every release, every image by digest, migrations forward-only so a rollback is the previous digest, with every irreplaceable byte encrypted and copied off-host. A Coolify redeploy restarts the whole resource, so one stack would restart the tunnel and every store on every release. Every dump is a personal-data copy, so a restore replays the erasures completed after it, which is what makes "beyond use" honest.

## Rejected

- One compose stack for everything: an outage per release.
- WAL archiving from day one: a second process with its own failure modes, until the database passes 5 GB or a contract asks for an RPO under an hour.
- A compliance-mode lock for twelve months: a scripting mistake is unfixable, and "we cannot" reads as failure to design for erasure.
