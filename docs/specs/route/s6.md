# S6 · A bid document's questions answered as one document

**Destination.** An Editor brings a bid document's questions in, confirms them in a table, and gets a response to each, drafted in the background and shown as each finishes, unanswered first. The set goes out as one response-set document.

**Done when.**

- The browser suite takes a bid document to a confirmed question table on Question sets, and no response exists before the person confirms.
- The api claims the question-set job, and a queued job of that kind older than a lease leaves the worker healthy.
- A response-set document records one *usage* row per response.
- The owner reads the efficacy measure for the first customer's past question sets.

**Rests on.** ADRs 0004, 0005, 0014 and 0016.

**Builds on.**

- `claim_job` takes the kinds its caller runs, and the api's role may call it (`packages/schema/migrations/0087_the-held-lapsed-claim.sql`).
- `packages/schema/src/platform/job-tables.ts` gives each kind a claiming tier. Every kind is the worker's, which claims only the kinds in `apps/worker/src/better_answers_worker/kinds.py`.
- S2b's answer path, `packages/core/src/answering/`.
- `write_up`, in `packages/schema/src/knowledge/write-up-tables.ts`.

**Must carry.**

- The question set is extracted as a suggestion, and the person confirms it before any response is drafted. It is never a source or company knowledge.
- The bid document's input object is Restricted by default, passes the redaction seam before extraction or any model call, is retained by rule, and is in the erasure map.
- The api claims the question-set job through `claim_job`, with the lease, heartbeat, reaper and poison that *job* and *claimant* name. Responses stream per question.
- `apps/worker/src/better_answers_worker/health.py` counts only the worker's kinds as waiting, so an api-claimed job never marks the worker unhealthy.
- The job runs under a deferred principal that records the person it borrowed from and expires with that authority. This block settles its type in `packages/core/src/kernel/principal/principal.ts` and adds *principal* to `GLOSSARY.md`.
- A response-set document is never an export.
- Each response is a *Questions asked* record an Editor may raise as a *promotion*.
- Question sets is the first page of the area for work produced from the knowledge, in the rail beside Ask and Knowledge.
- The efficacy measure runs the first customer's past question sets through this path, measuring each response against the library `Answer` it must reuse.

**Open for the plan.**

- The deferred principal's shape: a fourth principal kind, or a user principal carrying the borrowed person and an expiry.
- How a finished response reaches the page: a tRPC subscription over the job, or a read of its outcome rows.
