# C1 · The first customer onboarded and live

**Destination.** The first customer's people sign in to its workspace and find their bid libraries as `Answer` concepts with their context wordings. Its website is a connected source, and its guides are seeded from templates.

**Done when.**

- Every imported `Answer` has an answer test in the customer's workspace, and the owner reads recall at ten there.
- CI runs a WebKit project on an iPhone device profile over sign-in, Ask, Connected sources and the accessibility gate.
- A release that fails after promotion re-promotes the last tagged release, unless it added a migration (BA-48).
- The owner reads that the lawyer's four questions are answered and the DPIA is written, before the first real connected source is published.

**Rests on.** ADRs 0004, 0011, 0020, 0022 and 0027.

**Builds on.**

- The first customer's workspace on production, provisioned with `pnpm ops provision-workspace`, and its reviewed bundle, written with `pnpm ops import-bundle`.
- The erasure chain and the publish release of sensitivity, in every release.
- One browser-suite project, `chromium`, in `apps/web/playwright.config.ts`.
- An answer tests page that shows an empty state.

**Must carry.**

- Each answer test uses its `Answer`'s context wording as the question that must reuse it. The tests live in the customer's workspace, never in this public repository, and recall at ten read there decides S8.
- Each contradiction the bundle's review found between the four libraries becomes a conflict.
- The library files are a connected source, so the redaction seam runs on real material. The training-attendee list is never bundle content.
- The platform bundle is seeded into the customer's repository. Nothing in the tree seeds one yet.
- The lawyer's four questions are answered outside the repository.
- Before the first upload, `pnpm ops replay-erasures` runs once on production over every completed erasure request.
- The import's numbers and the customer's connected sources are the first real-customer row in `docs/operations/readings.md`, as `docs/operations/RUNBOOK.md` asks.
- The WebKit project runs a tagged subset of the browser suite.
- At go-live the release mode turns to `drill`, and the signed-in production journeys return with the rollback on a failed release.
- The orchestrator's rebuild on the runbook's page 5 is rehearsed once, and the second escrow holder opens the vault once, as page 9 asks.

**Open for the plan.** None.
