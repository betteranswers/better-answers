# C1 · The first customer onboarded and live

**Destination.** The first customer's people sign in to its workspace and find their bid libraries as `Answer` concepts with their context wordings. The contradictions between the libraries are recorded as conflicts. Its website is a connected source, and its guides are seeded from templates. Its DPIA is written from the DPIA input before its first real connected source is published.

**Done when.**

- Every imported `Answer` has an answer test in the customer's workspace, and the owner reads recall at ten there.
- CI runs a WebKit project on an iPhone device profile over sign-in, Ask, Connected sources and the accessibility gate.
- A release that fails after promotion re-promotes the last tagged release, unless it added a migration (BA-48).
- The owner reads that the lawyer's four questions are answered and the DPIA is written, before the first real connected source is published.

**Rests on.** ADR 0004, a Q&A pair as an `Answer` concept with its context wordings in its body. ADR 0011, the minting rule. ADR 0020, the DPIA input and the four questions owed to a lawyer. ADR 0022, the release mode and the rollback from the first customer's day. ADR 0027, the hosted service as the product and the repository as public.

Words: *Q&A pair*, *context wording*, *answer test*, *template*, *platform bundle*, *collection*, *conflict*, *DPIA input*, *go-live*, *release mode*, *workspace*, *member*.

**Builds on.** The first customer's workspace is on production, provisioned with `pnpm ops provision-workspace` (#133), its reviewed bundle written with `pnpm ops import-bundle` (#118, #123, #125). Every release carries the erasure chain and the publish release of sensitivity (#277, #279 to #283). The browser suite has one project, `chromium`, in `apps/web/playwright.config.ts`. The answer tests page is an empty state.

**Must carry.**

- **The real answer tests.** There is one per imported `Answer`, with its context wording as the question that must reuse it. They are written in the customer's own workspace and never in this public repository (ADR 0027). Recall at ten read there decides S8.
- **The contradictions as conflicts.** Each contradiction the bundle's review found between the four libraries becomes a conflict.
- **The library files as a connected source**, so the redaction seam runs on real material. The training-attendee list is never bundle content.
- **The platform bundle**, seeded into the customer's repository. Nothing in the tree seeds one yet.
- **The lawyer's four questions**, answered outside the repository before the first real connected source is published (ADR 0020).
- **One replay of completed erasures.** Before the first upload, `pnpm ops replay-erasures` runs once on production over every completed erasure request.
- **The estate size.** The import's numbers and the customer's connected sources are the first real-customer row in `docs/operations/readings.md`, as `docs/operations/RUNBOOK.md` asks.
- **The iPhone run.** v0.1 supports Chromium on the desktop and WebKit on the iPhone. A Playwright project on WebKit, with one of Playwright's iPhone device profiles, runs a tagged subset of the browser suite in CI. Desktop Safari and Firefox are not in v0.1.
- **Go-live on the release.** The release mode turns to `drill`, and the signed-in production journeys return (ADR 0022). The rollback on a failed release lands with them (BA-48).
- **The runbook's go-live rehearsals.** The orchestrator's rebuild on its page 5 is rehearsed once. The second escrow holder opens the vault once, as its page 9 asks.

**Seams.** No new seam. The browser suite gains the WebKit project. The core slice interface holds the answer tests' writes. The `runOps` seam holds `replay-erasures`.
