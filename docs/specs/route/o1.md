# O1 · System's signals, backups and the erasure page

**Destination.** An Admin reads System's Signals, Health and Backups pages as signal lines over rows the platform keeps, worst first, and changes a threshold there. An alert reaches the Admins once and clears once. Personal data's Erasure and suppression page lists the workspace's erasure requests with their reports, and its suppressions.

**Done when.**

- On production, Backups shows each store's latest backup and the latest restore drill from `backup` rows, and no backup script logs that its row was not written.
- On `main`, a test forces a signal over its threshold and reads one alert and one email, then lets it fall back and reads one *cleared* row.
- On `main`, `apps/web/src/shared/navigation/areas.ts` declares the four pages built, and the browser suite opens each as an Admin.

**Rests on.** ADRs 0020, 0022, 0024 and 0025.

**Builds on.**

- Every backup script writes its `backup` row, the drill's to production.
- `app_rt` cannot read that table until the Backups page grants it.
- `apps/api/src/timers/dead-man-ping.ts` sends the dead-man ping.
- `llm_call` rows are written.
- The index job's outcome carries `lmdb_bytes`.
- `packages/core/src/erasure/` holds `recordSubjectRequest`, which only the ops rehearsal and the tests call.

**Must carry.**

- `platform_event`, the threshold rows and the heartbeat's host figures are the block's own tables, under `packages/schema/AGENTS.md`.
- One signal module holds every line. A later block adds a line as a query in its table, never a second module.
- The api's own email sends an alert at once for a short list, and in a daily digest for the rest.
- The worker's heartbeat row carries ADR 0025's host figures once a minute for step A's swap-in signal.
- Retention follows ADR 0025, and `llm_call` keeps a monthly aggregate per workspace (BA-178).
- A lapsed lease claimed again raises a `double_claim` alert. Each connected source's LMDB size is a line, read from the index job's outcome.
- A spend cap, an empty balance or a rate limit that ends a judgement as `judging-failed` is a signal line (BA-186, its second item).
- A test breaks each `pnpm ops smoke` check in turn, and the run fails each time.
- The audit log page moves to `apps/web/src/features/system/` (WP14 of the [architecture review](../../archive/plans/2026-10-08-2311-docs-architecture-review-before-s2-plan.md)).
- Control Centre › Overview, the area's first page, shows the worst signal lines.

**Open for the plan.**

- Which signal line sits on which System page.
- Whether Erasure and suppression records a subject request, with its one-month clock, or only reads.
- Whether retention runs in the daily *sweep pass* or its own pass.
- How a lapsed lease reclaimed is told from a retry, since both raise `attempts`.
