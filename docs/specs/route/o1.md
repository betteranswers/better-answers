# O1 · System's signals, backups and the erasure page

**Destination.** An Admin reads System's Signals, Health and Backups pages as signal lines over rows the platform keeps, worst first, and changes a threshold there. An alert reaches the Admins once and clears once. Every backup and restore drill is a row. Personal data's Erasure and suppression page lists the workspace's erasure requests with their reports, and its suppressions.

**Done when.**

- On production, Backups shows each store's latest backup and the latest restore drill from `backup` rows, and no backup script logs that its row was not written.
- On `main`, a test forces a signal over its threshold and reads one alert and one email. It then lets the signal fall back and reads one *cleared* row.
- On `main`, `apps/web/src/shared/navigation/areas.ts` declares the four pages built, and the browser suite opens each as an Admin.

**Rests on.**

- ADR 0025, the signal as a query over rows, thresholds as rows, alert once, the host figures, the channels and retention.
- ADR 0020, the erasure request, its report and the suppression.
- ADR 0022, the monthly restore drill.
- ADR 0024, growth step A and its swap-in signal.

**Words.** *signal*, *alert*, *backup*, *restore drill*, *dead-man ping*, *erasure request*, *subject request*, *suppression*, *job*, *outcome*.

**Builds on.**

- Every backup script writes its `backup` row (BA-54). The drill writes its row to production.
- `app_rt` holds no privilege on the table until the Backups page grants its read.
- `apps/api/src/timers/dead-man-ping.ts` sends the dead-man ping.
- `llm_call` rows are written (#747).
- The index job's outcome carries `lmdb_bytes`.
- `packages/core/src/erasure/` holds `recordSubjectRequest`, which only the ops rehearsal and the tests call.

**Must carry.**

- **Its own tables.** The block adds `platform_event`, the threshold rows and the heartbeat's host figures, under the rules in `packages/schema/AGENTS.md`.
- **One signal module.** A later block adds a line by adding a query to its table, never a second module.
- **Alert once, cleared once.** An alert goes out once and clears once, by the api's own email. Alerts on a short list go at once, and the rest go in a daily digest.
- **The host figures.** The worker's heartbeat row carries the host figures once a minute, and step A's swap-in signal reads them.
- **Retention.** It runs as ADR 0025 sets it, and `llm_call` keeps a monthly aggregate per workspace (BA-178).
- **A lease claimed twice.** A lease let lapse and claimed again raises a `double_claim` alert. Each connected source's LMDB size is a line, read from the index job's outcome.
- **A provider's refusal is seen.** A spend cap, an empty balance or a rate limit that ends a judgement as `judging-failed` is a signal line (BA-186, its second item).
- **The smoke proves each check.** A test forces each `pnpm ops smoke` check wrong in turn, and the run fails each time.
- **System's home.** The audit log page moves to `apps/web/src/features/system/` (WP14 of the [architecture review](../../archive/plans/2026-10-08-2311-docs-architecture-review-before-s2-plan.md)).
- **Overview.** Control Centre › Overview, the area's first page, shows the worst signal lines.

**Open for the plan.**

- Which signal line sits on which System page.
- Whether Erasure and suppression records a subject request, with its one-month clock, or only reads.
- Whether retention runs in the daily *sweep pass* or its own pass.
- How a lapsed lease reclaimed is told from a retry, since both raise `attempts`.

**Seams.**

- The core interface, for signals, thresholds, alert and clear.
- The ops seam, for the smoke's checks.
- The api harness, for the threshold email against a captured transport.
- The browser suite, for the four pages.
