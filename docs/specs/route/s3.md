# S3 · Concepts typed and edited, guide sections populated

**Destination.** An owner or an Admin types or edits a concept, and anyone else suggests edits for the owner to decide. A guide seeded from a template fills its sections from concepts, and its Brief cites each by a footnote. Each collection has an owner.

**Done when.**

- An owner's edit writes one commit with that person as git author. A Viewer's edit waits as an *edit* suggestion, and its acceptance commits with the Viewer as author.
- Knowledge › Guides shows a seeded guide's sections populated, and an unchanged Brief save writes no version and no commit.
- An Editor who owns a collection sees Knowledge's Curation pages, and one owning nothing does not.

**Rests on.** ADR 0004 for the skeleton projection. ADR 0012 for the governed write and the *edit* suggestion. ADR 0014 for `concept_owner` and the helpers. ADR 0015 for the footnote and the no-op save. ADR 0026 for Kinds.
Words: *suggestion*, *owner (of a concept)*, *collection*, *guide definition*, *template*, *expectation*, *footnote*, *skeleton projection*, *usage*

**Builds on.** `packages/schema/src/knowledge/write-up-tables.ts`, the cascade and footnote read in `packages/core/src/guides/index.ts`. `packages/core/src/concepts/writes/suggestions.ts`, where only Admins decide. Declared admission (#691), the refusal catalogue (#682). Knowledge's pages, unbuilt, in `apps/web/src/shared/navigation/areas.ts`.

**Must carry.**

- **Concept authoring first.** A concept is typed on Knowledge, or offered from a guide page as a missing fact. The owner's or an Admin's edit commits once the page states the consequence, asking once if the concept is reused. Anyone else's is an *edit* suggestion, the proposer as git author (ADR 0012).
- **Edits from the raw file.** An edit seeds from the bundle's file, never the projected read (BA-95). The write keeps `sources` and the evidence rows as one list (BA-127). Source labels are rechecked against this writer (BA-126).
- **The owner record.** `concept_owner` is a table on the concepts slice, with a per-collection default and a per-concept override (ADR 0014). It is never a file key, and it opens the owner-visible pages (BA-12).
- **The no-op save** uses round-trip equality.
- **The skeleton projection** is regenerated in the workspace repository on a guide definition change.
- **Knowledge's pages.** Guides reads the Brief and Detail layers with coverage and edits the Brief. All knowledge is the review table. Kinds counts per kind and collection. Collections and owners names owners. Exports gives an Admin the bundle, its records or a guide. A bundle browser beside Search reads the concept index under the read predicate; the plan names it.
- **Inbox › Waiting on you.** Where an owner decides *edit* suggestions; S5 and V1 add queues.
- **The copy artefact** keeps resolvable footnotes and records its *usage* through the answering slice's `recordUsage`.
- **Actions on the head.** The concept page's actions sit on its head, and its toolbar carries tabs alone (BA-144, third criterion).
- **Creation without a scan.** Creating a concept no longer scans the workspace, because an unresolved path reference is a row. A write at 3,000 concepts is no slower than [trunk's `write-budget.test.ts` reading](../../operations/readings.md#the-governed-write-at-3000-concepts).
- **Schema helpers.** `attachedByIri()` replaces `identityKey`. `versionColumns()` makes both version tables append-only in one migration. `WRITE_UP_HOMES` declares `section` and `response` (ADR 0014).
- **The audience cascade.** An `audience`-only or `audienceGroups`-only move reaches every including write-up.

**Open for the plan.** Whether the bundle browser lifts `extend-hq/jevbox`'s Finder or composes the registries.

**Seams.** The core interface on a bare repository proves each commit's author. The browser suite proves the editor and what a paste keeps, the invisibility suite the cascade.
