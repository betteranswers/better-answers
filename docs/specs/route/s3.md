# S3 · Concepts typed and edited, guide sections populated

**Destination.** Owners and Admins type and edit concepts, and others suggest edits for the owner to decide. A guide seeded from a template fills its sections from concepts, its Brief citing each by footnote. Each collection has an owner.

**Done when.**

- An owner's edit writes one commit with that person as git author. A Viewer's edit waits as an *edit* suggestion, and its acceptance commits with the Viewer as author.
- Knowledge › Guides shows a seeded guide's sections populated, and an unchanged Brief save writes no version and no commit.
- An Editor who owns a collection sees Knowledge's Curation pages except Exports, and one owning nothing sees none of them.

**Rests on.** ADRs 0004, 0012, 0014, 0015 and 0026.

**Builds on.**

- `packages/schema/src/knowledge/write-up-tables.ts`.
- The cascade and footnote read in `packages/core/src/guides/index.ts`.
- `packages/core/src/concepts/writes/suggestions.ts`, where only Admins decide.
- Declared admission (#691) and the refusal catalogue (#682).
- Knowledge's pages, declared but unbuilt in `apps/web/src/shared/navigation/areas.ts`.

**Must carry.**

- **Concept authoring first.** A concept is typed on Knowledge, or offered from a guide page as a missing fact. An owner's or Admin's edit commits once the page states the consequence, asking once if the concept is reused.
- **Edits from the raw file.** An edit seeds from the bundle's file, not the projected read (BA-95). The write keeps `sources` and the evidence rows as one list (BA-127), and source labels are rechecked against it (BA-126).
- **The owner record.** `concept_owner` is a concepts-slice table with a per-collection default and a per-concept override. It is never a file key, and it opens the owner-visible pages (BA-12).
- **The no-op save.** It uses round-trip equality.
- **The skeleton projection.** A guide definition change regenerates it in the workspace repository.
- **Knowledge's pages.** Guides reads the Brief and Detail layers with coverage, and edits the Brief. All knowledge is the review table. Kinds counts per kind and collection. Collections and owners names them. Exports gives an Admin the knowledge base, its records or a guide. A bundle browser beside Search reads the concept index under the read predicate.
- **All knowledge.** It reads the concept index under the read predicate for an Admin or an owner of a collection, 50 rows to a page, and an owner opens it filtered to the collections they own. Its one command, *Set Owner*, is the Admin's, and it writes one `knowledge.owner.named` event per concept sharing one batch id.
- **Kinds.** It is read-only counts per kind and per collection, with a filter for the kinds holding two or fewer concepts. S7 renames and merges kinds (ADR 0026).
- **Exports.** It is the Admin's alone, so it carries no owner flag. Each export needs a fresh confirmation, carries only what the requesting Admin may read, and leaves one audit event. The knowledge base snapshot is a zip of the readable concept files at the recorded head, without `guides/`, and writes no `usage` row, because it takes no one concept into a document. The records export is a zip of one CSV per family: owners (collection defaults and per-concept overrides), verifications and usage. The guide snapshot renders each readable section's Brief with its trust words, dated and marked *Not maintained*, and writes one `usage` row with act `exported` per write-up version it carries.
- **Inbox › Waiting on you.** An owner decides *edit* suggestions there. S5 and V1 add queues.
- **The copy artefact.** It keeps resolvable footnotes and records its *usage* through `recordUsage`.
- **Actions beside the title.** The concept page's actions sit on the concept's own header, beside its title. The page head keeps the group's name, and its toolbar carries only tabs (BA-144, third criterion).
- **Creation without a scan.** Creating a concept does not scan the workspace, because an unresolved path reference is a row. A write at 3,000 concepts is no slower than [trunk's `write-budget.test.ts` reading](../../operations/readings.md#the-governed-write-at-3000-concepts).
- **Schema helpers.** `attachedByIri()` replaces `identityKey`. `versionColumns()` makes both version tables append-only in one migration. `WRITE_UP_HOMES` declares `section` and `response`.
- **The audience cascade.** A move of only `audience` or only `audienceGroups` reaches every including write-up.

**Open for the plan.** Whether the bundle browser lifts the Finder from `extend-hq/jevbox` or composes the registries.
