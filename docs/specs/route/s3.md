# S3 · Concepts typed and edited, guide sections populated

**Destination.** An owner or an Admin types or edits a concept, and anyone else suggests edits for the owner to decide. A guide seeded from a template fills its sections from concepts, and its Brief cites each by a footnote. Each collection has an owner.

**Done when.**

- An owner's edit writes one commit with that person as git author. A Viewer's edit waits as an *edit* suggestion, and its acceptance commits with the Viewer as author.
- Knowledge › Guides shows a seeded guide's sections populated, and an unchanged Brief save writes no version and no commit.
- An Editor who owns a collection sees Knowledge's Curation pages, and one owning nothing does not.

**Rests on.**

- ADR 0004, the skeleton projection.
- ADR 0012, the governed write and the *edit* suggestion.
- ADR 0014, `concept_owner` and the schema helpers.
- ADR 0015, the footnote and the no-op save.
- ADR 0026, Kinds.

**Words.** *suggestion*, *owner (of a concept)*, *collection*, *guide definition*, *template*, *expectation*, *footnote*, *skeleton projection*, *usage*.

**Builds on.**

- `packages/schema/src/knowledge/write-up-tables.ts`.
- The cascade and the footnote read in `packages/core/src/guides/index.ts`.
- `packages/core/src/concepts/writes/suggestions.ts`, where only Admins decide.
- Declared admission (#691) and the refusal catalogue (#682).
- Knowledge's pages, declared in `apps/web/src/shared/navigation/areas.ts` and not yet built.

**Must carry.**

- **Concept authoring first.** A person types a concept on Knowledge, or a guide page offers it as a missing fact. An owner's or an Admin's edit commits once the page states the consequence. If the concept is reused, the page asks once. Anyone else's edit is an *edit* suggestion, with the proposer as git author.
- **Edits from the raw file.** An edit seeds from the bundle's file, never from the projected read (BA-95). The write keeps `sources` and the evidence rows as one list (BA-127). Source labels are checked again against this writer (BA-126).
- **The owner record.** `concept_owner` is a table on the concepts slice, with a per-collection default and a per-concept override. It is never a file key, and it opens the owner-visible pages (BA-12).
- **The no-op save.** It uses round-trip equality.
- **The skeleton projection.** A guide definition change regenerates it in the workspace repository.
- **Knowledge's pages.** Guides reads the Brief and Detail layers with coverage, and edits the Brief. All knowledge is the review table. Kinds counts concepts per kind and collection. Collections and owners names the owners. Exports gives an Admin the bundle, its records or a guide. A bundle browser beside Search reads the concept index under the read predicate, and the plan names it.
- **Inbox › Waiting on you.** An owner decides *edit* suggestions there. S5 and V1 add queues.
- **The copy artefact.** It keeps resolvable footnotes, and records its *usage* through the answering slice's `recordUsage`.
- **Actions on the head.** The concept page's actions sit on its head, and its toolbar carries only tabs (BA-144, third criterion).
- **Creation without a scan.** Creating a concept does not scan the workspace, because an unresolved path reference is a row. A write at 3,000 concepts is no slower than [trunk's `write-budget.test.ts` reading](../../operations/readings.md#the-governed-write-at-3000-concepts).
- **Schema helpers.** `attachedByIri()` replaces `identityKey`. `versionColumns()` makes both version tables append-only in one migration. `WRITE_UP_HOMES` declares `section` and `response`.
- **The audience cascade.** A move of only `audience`, or of only `audienceGroups`, reaches every write-up that includes the concept.

**Open for the plan.** Whether the bundle browser lifts the Finder from `extend-hq/jevbox` or composes the registries.

**Seams.**

- The core interface, on a bare repository, for each commit's author.
- The browser suite, for the editor and what a paste keeps.
- The invisibility suite, for the cascade.
