# S4 · Website and SharePoint connected sources kept fresh

**Destination.** An Admin connects the first customer's website, one connected source per URL prefix, and a SharePoint library. Each is reviewed with its findings and a cost estimate, published, and synced on its cadence. A reader opens the source document behind a passage they may read.

**Done when.**

- A one-line edit to the website fixture re-indexes one passage on the next sync, and a gone document keeps only its cited evidence.
- A SharePoint library behind the Graph API fake is connected, reviewed, published and synced again.
- An Admin accepts a connected source's cost estimate once, on Cost estimates.
- The owner reads ADR 0024's step-A signal on the first customer's first index and records it under [the worker's box figures](../../operations/readings.md#the-workers-box-figures).

**Rests on.** ADR 0013, the connected source. ADR 0036, the sync's cocoindex blocks. ADR 0020, who opens an original. ADR 0024, one sync at a time and the step-A signal. ADR 0041, credential classes. ADR 0044, catalogue before passages. ADR 0027, a lift's licence.

Words: *connected source*, *connector*, *converter*, *sync*, *finding*, *cost estimate*, *retention class*, *citation fix*, *evidence panel*.

**Builds on.** The sync in `apps/worker/src/better_answers_worker/pipeline/`, with its converter (#87). Connect, review and publish in `packages/core/src/sources/`. `packages/schema/src/source-tables.ts`, whose one connector is `upload`.

**Must carry.**

- **The estate-size probe.** A slim enumeration of the real site runs before any cost estimate is priced.
- **The cost estimate.** It is priced at review from measured rates and accepted once. A sync that would reprocess more than a set share waits for re-acceptance. What it prices runs from S7.
- **The first index.** One sync at a time is measured as its onboarding queue. Its memory signals are anonymous memory, `memory.swap.peak` and `pswpin`, and a `memory.peak` at the cap from page cache is not a failure.
- **Evidence outlives its source.** A gone document gets `gone_at` and keeps its passages through mirror retention's grace period. A source that moved on raises a citation fix.
- **No skip on the hash alone.** A sync commits its catalogue writes before its passages (ADR 0044), so an unchanged content hash never alone skips indexing a document.
- **One record per media type.** The worker's converter holds each media type's conversion and page rule together, so admitting HTML forces its page rule.
- **Job kinds from the descriptors.** The worker's `KINDS` is generated from `JOB_KIND_DESCRIPTORS` and checked both ways.
- **One reading of state.** A migration drops `connected_source.state`, which publish writes and nothing reads.
- **Connect apart from upload.** The second connector splits connecting a source from uploading its one document.
- **The redaction categories leave the DPIA module.** They leave `packages/core/src/sources/dpia.ts` when the findings module next changes.
- **The Graph credential.** It is ingestion class, apart from Microsoft sign-in, and this block builds that class in the credentials provider (ADR 0041).
- **Source viewing.** Where the source has a home, the evidence panel links out to it. For an upload, an Admin's switch per connected source, off by default, lets its audience open the original in a viewer, and otherwise shows the whole redacted text. Every view of an original is an audit event. The build amends ADR 0020.

**Open for the plan.** Whether a viewer opens at the cited place, since a locator carries no page. Which viewers to lift, `extend-hq/jevbox`'s MIT viewers being candidates (ADR 0027).

**Seams.** The document-shaped cross-tier test over a changing source, with a fixture site and the Graph API fake. The worker pytest harness per connector. The core slice interface. The browser suite for both pages.
