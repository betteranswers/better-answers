# P1 · Member sign-in, Microsoft and personal tokens

**Destination.** An Admin sees how each member signs in and when they were last active here. A person on Microsoft 365 signs in with Microsoft. A person's Account page shows their name, role and workspace, and mints their personal tokens, which an Admin lists and ends in People.

**Done when.**

- A member page shows a member with a passkey as holding a second factor, never which one, and Members sorts by last active.
- An invited person whose verified Microsoft email matches signs in with Microsoft, and an uninvited account is refused. The owner reads both on production.
- A personal token minted on the Account page calls `find` from Claude Code, and an Admin ends it in People › Personal tokens.

**Rests on.** ADRs 0009, 0034, 0043 and 0048.

**Builds on.**

- `apps/web/src/features/people/` over `packages/core/src/members/`.
- `apps/web/src/features/auth/account-page.tsx`, with its Sign-in and Sessions sections.
- A failed invitation email spends no allowance.
- The session is a platform type, mapped in `apps/web/src/features/auth/auth-hooks.ts`.

**Must carry.**

- The member page gains Sign-in and Sessions sections, and Members gains columns for sign-in methods, a held factor and last active here, per unit U12 of `docs/archive/plans/2026-10-01-2241-feat-people-sign-in-and-security-plan.md`.
- Microsoft sign-in uses one multi-tenant Entra registration the platform owns. A first sign-in links only to a pending invitation whose verified email matches. A person adds Microsoft from the Account page. Strong Microsoft methods count as an Admin's factor and as a re-confirm. Units U13 and U14 wait on the owner's Entra registration (BA-14).
- A personal token lasts ninety days by default, shows once, and carries an OAuth token's principal and scopes.
- A bulk self-removal lands on the chooser (BA-32). A removal from jump-to returns to the narrowed list (BA-33). A late refusal stays visible (BA-40). Ticks survive a refused bulk invitation action (BA-41). The invite dialog keeps unsent addresses when closed mid-send (BA-43).
- Auth's person routes answer `{ word, class }` through one crossing, unwrapped once on the web.
- People has one optimistic update over a filter, and one table of the reads each action moves.
- The `UserId` brand in `packages/schema/src/ids.ts` takes the glossary's name, *person id*.
- The global tables beyond the identity set move from `packages/schema/src/platform/counter-tables.ts` into `packages/schema/src/rls-exemptions.ts`.
- Each of these auth and ingress tests fails without its guard:
  - the per-address counts on the OAuth paths, discovery and `/jwks`
  - the email throttle folding an address
  - the email code stored as its hash
  - the consent page's escaping
  - the CIMD allow-lists
  - HEAD and POST to an unknown path
  - `/health` with a query
  - the audit event's outcome and token id
  - a failed tRPC procedure's log line

**Open for the plan.** Whether the personal token's table is an RLS exemption read by hash, or is read through a security-definer function on the roster in `packages/schema/src/definer-reach.ts`.
