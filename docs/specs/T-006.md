# T-006 — B5: the concept write path, the graph delta and the reconciler

*Spec written 5 September 2026 from the T-006 ticket body, the pre-build gate briefing §7 (B5), ADRs 0012, 0014, 0015, 0019, 0023, 0032, the audience research of 2026-09-01 (`docs/research/audience-representation-2026-09-01.md`), and the 2026-09-05 grill outcomes (`.scratch/readiness-2026-09-04/ui-wiring-and-t006.md`). Source of truth for scope is the T-006 ticket body plus this spec. Decisions recorded here are taken; do not re-open them. Two sibling specs are being cut in parallel (T-046, T-048); the boundary with T-048 is stated in Further Notes.*

## Problem Statement

A workspace's knowledge is a bundle the platform promises to keep trustworthy per fact: every change attributable and revertible, nothing platform-prepared landing without acceptance, the map never behind for an edit, and nothing Restricted ever reaching a reader it was withheld from. Today none of the write path exists. The `concepts`, `audit`, git-door and graph-door slices are documented stubs; the database carries no concept, suggestion, audit, evidence or graph tables; `find`, `ask` and `open` return typed emptiness; the worker image refuses to start by design because nothing exists for it to do; and the four graph ops commands answer *not built*, which keeps the restore drill from ever going fully green.

Two failure modes are named by the ADRs and currently unhandled. First, the crash window: the governed write makes a git commit and then writes rows, and a crash between the two leaves a bundle the database has never heard of — ADR 0012 names the window and names "reconciler hits" as a signal, but no document says what the reconciler *does*. Second, the derived graph drifting into a source of truth: with the delta written by the app in its own transaction, only a running equivalence fence keeps the graph honest.

## Solution

The governed write, implemented end to end in the `concepts` slice over the git and Postgres doors: one commit per act, the person as git author and the platform bot as committer, a hash precondition against the ref, a per-repository lock the app holds — then one Postgres transaction carrying the concept index row, the `bundle_commit`, the `audit_event` **and the bundle-and-record graph delta**. The graph lands as two ordinary tenant tables under RLS in the same slice as the write path that fills them (ADR 0032). The reconciler gains its defined action: on finding the repository head ahead of the last `bundle_commit`, it replays the missed commits through the same handler the live write uses, idempotent on the ids the commit trailers carry. The visibility class derivation runs synchronously inside the narrowing act's transaction, two levels, with the audience representation decided on 2026-09-01. The worker gains its work loop with this task's two job kinds — the nightly parser audit and the full rebuild — and starts by default. The four ops commands gain implementations, and a cross-tier rebuild-equivalence test becomes the enforceable meaning of *derived, never a source of truth*.

## User Stories

### The people who write

1. As an Editor, I want my edit to a concept to land as one commit with me as git author and the platform bot as committer, so that every change to the bundle is attributable to a person and revertible as one unit.
2. As an Editor whose edit was written against content that has since moved, I want the write refused loudly by its hash precondition, so that I never silently overwrite someone else's change.
3. As an Admin, I want each acceptance of a suggestion — in bulk or per item — to be one governed write and one commit, so that a bad producer run stays out of a history that is permanent.
4. As a person who prepared an *edit* suggestion, I want its identity resolved at acceptance from the merge key my payload carries, so that a concept whose identity moved between proposal and decision refuses the acceptance and returns to me rather than landing on the wrong concept.
5. As an Admin opening a suggestion set, I want its summary re-rendered against `concept_identity` as it stands now, so that I decide against the map of today, not the map of the proposal's day.
6. As an Admin declining a suggestion, I want the decline recorded with its reason, so that a producer's rejected work is a fact, not a silence.

### The people who read

7. As a workspace member, I want an accepted edit on the map in the same act that committed it, so that the map is never behind for an edit and no *updating* phrase is ever needed.
8. As a workspace member, I want the map's only states to be *map as of <time>* and *map unavailable since <time>*, so that a full rebuild happens beside the live map and flips in one row update without my noticing.
9. As a Viewer, I want a Restricted-sourced concept to be invisible to me through `find` — no hit, no count, no hint — so that withheld knowledge is indistinguishable from absent knowledge.
10. As a Viewer, I want the same concept never asserted, cited or surfaced by `ask`, so that an answer cannot launder what search withholds.
11. As a Viewer, I want a graph walk to exclude any path with an element beyond my access, so that the middle of a traversal cannot leak what its endpoints would not.
12. As a Viewer, I want a guide page's footnote to a concept I may not see to withhold it the same way, so that a composition's citation is not a side door.
13. As a Viewer, I want `open` by IRI to refuse in a way indistinguishable from the concept not existing, so that probing IRIs reveals nothing.
14. As a reader whose access excludes a concept's cited evidence while a recorded Admin override shares the concept with me, I want the evidence pane to lead with my access, name the Admin whose override created the state, and never dead-end, so that *shared beyond its evidence* is a navigable fact and never a rider or a trust signal.
15. As a member named individually on a Restricted binding, I want that named list carried as an implicit group, so that one grouping model decides everything I may see.
16. As the subject of a `Person` concept, I want it Restricted whatever its evidence says, with inheritance never widening past the per-kind floor, so that a person's card never leaks by derivation.
17. As a reader of a concept whose evidence comes from two disjoint audiences, I want the empty intersection to force the concept Restricted rather than be stored, so that disjoint audiences never accidentally union into visibility.
18. As a workspace member, I want an Admin's narrowing of a binding to recompute classes synchronously inside that same act's transaction, cascading binding → concept → composition, so that nothing readable outlives the act that narrowed it.

### The platform acting as itself

19. As the platform running its own citation repair, I want the repair commit recorded with `verification.origin = repair` and re-hashed in its own transaction, so that repairing a citation does not un-check every concept it touches.
20. As the platform's reconciler, I want a defined action — replay the commits between the last `bundle_commit` and the repository head through the same handler the live write uses, idempotent on the ids the trailers carry — so that the crash window is recoverable, not merely detectable.
21. As the platform's reconciler, I want to act under a platform principal with my own actor id and my acts audited under it, so that recovery is never booked to a person.
22. As the platform's nightly auditor, I want the Python parser to cross-check the app's parse hash-by-hash and raise `bundle_health` on mismatch, so that the two parsers police each other for good.

### The operator

23. As the operator, I want the worker to start by default and run its work loop — claiming the nightly parser audit and full rebuilds under a lease — so that the deploy unit's three services all run and B7 adds job kinds to a loop that exists.
24. As the operator, I want the worker's healthcheck to be a query for a claimed lease with a fresh heartbeat, so that *healthy* means working, not merely importable.
25. As the operator, I want `graph-rebuild`, `graph-sweep`, `graph-counts` and `reconcile-watermark` implemented through the slices that own them, so that the restore drill goes fully green and answers *done · refused · not built* truthfully.
26. As the operator restoring from a dump, I want `reconcile-watermark` to run the reconciler on demand, so that a restored database catches up with a repository that is ahead of it.
27. As the owner, I want traversal and rebuild cost measured under concurrent load as an ordinary functional test with a stated budget — the ≤2-minute rebuild budget re-derived here, not assumed — so that the 4 GB box's numbers are facts.

### The builder and the reviewer

28. As a builder, I want `graph_node` and `graph_edge` as ordinary tenant tables under `withRLS()` with hand-written migrations in the one journal, so that one isolation mechanism covers the graph as it covers everything else.
29. As a builder, I want the read predicate defined once and rendered as SQL applied on every element of every path, so that a predicate written twice cannot drift.
30. As a builder, I want the queue and `concept_write_request` SQL functions in the schema package's migrations with `contracts/` fixtures both tiers' suites read, so that the tier contract stays checkable.
31. As a builder, I want the chunker to index a concept's body only, never its frontmatter, with a test asserting no `@` reaches a concept chunk, so that machine keys never enter retrieval.
32. As the worker tier, I want `worker_rt` granted SELECT on the migrations stamp table in the same migration as the stamp check that needs it, so that `[WRK1]` holds without a standing grant nothing uses.
33. As a builder, I want `evidence` keyed on `(workspace_id, source_document_id, locator)` with `resource` a rendered projection, so that evidence identity follows the document rather than the URL.
34. As a reviewer, I want the ADR work in the same PRs as the code — the write-path amendment stating the audit-id minting and the reconciler's action, and the audience ADR — with the index updated in the same commit, so that the live conclusions are never stale.
35. As a reviewer, I want the `[SEC3]` adversarial pass on every new table, grant and definer function, with tests of what each refuses, so that the write path's threat model is written where it can be checked.
36. As the owner, I want the rebuild-equivalence test to be a named, running, cross-tier test, so that *derived, never a source of truth* has exactly one enforceable meaning.

## Implementation Decisions

### The governed write

- The act lives in the `concepts` slice, composing the git door and the Postgres door — the transaction that spans stores lives in the slice that owns the act, never an orchestrator (ADR 0029). Every act takes a Principal first (`[SEC2]`).
- One commit per act: the person as git author, the platform bot as committer; an en-masse verify is one batch commit with per-document hash preconditions; trailers `Actor:` / `Audit:` / `Run:` / `Suggestion:` / `Projection:` as ADR 0012 fixes them.
- The hash precondition is checked against the ref under the per-repository lock. The lock is the app's own, in-process, keyed by workspace repository, held for the whole act — commit through transaction commit. One api process exists (ADR 0024's estate); multi-process locking is a written trigger, not built.
- Ordering: git commit first, then the one Postgres transaction (concept index row, `concept_identity` upkeep, `bundle_commit`, `audit_event`, the bundle-and-record graph delta, and the synchronous flagging of citing compositions). The window between the two is the reconciler's territory and nobody else's.
- **The `audit_event` id is minted before the commit**, so it rides in the `Audit:` trailer. This is the decision the ADR amendment must state, and the reason is the reconciler: replay idempotency keys on the ids the trailers carry, and an id minted after the commit would leave the trailer empty exactly when the row was never written. The same holds for the suggestion and run ids: the trailer set is the replay's identity.
- The ledger itself — the `audit_event` tenant table and the audit slice's one typed write helper (ADR 0029) — is **founded by T-059** (T-048 slice 1; agreed between the two spec sessions and owner-confirmed, 2026-09-05). T-006's requirement on its shape is exactly one thing: the id is **caller-supplied text** with no database default, so this task can mint it before the commit. The commit linkage lives in the trailer, never as a column. The ordering is CLI-enforced: T-052 (this task's first ticket) `depends_on` T-059.

### The reconciler

- Defined action: on finding the repository head ahead of the last `bundle_commit`, replay the missed commits **in order, oldest first, through the same handler the live write uses**. Idempotency is per trailer id: a replayed commit whose `audit_event` id (or suggestion/run id) already has its rows is skipped as already-landed, not re-written and not an error.
- It runs in the app tier under a platform principal (`process:better-answers-reconciler`); its acts are audited under that identity. A periodic head check in the api process is the trigger; `pnpm ops reconcile-watermark` runs the same slice function on demand (the restore path).
- Reconciler hits stay a signal in ADR 0025's sense: a query over the rows the replay writes, never a metric.

### The graph tables and the delta

- `graph_node` and `graph_edge` land as ordinary tenant tables — `withRLS()`, hand-written migrations in the one journal — with ADR 0032's columns: `workspace_id`, `gen`, `uid` (unique `(workspace_id, gen, uid)` on bundle-and-record rows; `(workspace_id, uid)` on source entities, which carry no `gen`), the closed `label` set, `kind` as an indexed property column, `LINKS_TO` with `from_kind` / `to_kind` / `section` / `sentence`, the named edges, and the visibility columns.
- The delta builder lives in the graph door and emits plain SQL inside the act's transaction. The graph door's and access slice's stub comments still say AGE and Cypher; they are corrected here — the predicate has **one** definition and one SQL renderer, applied on every element of every path by the prepared recursive-CTE traversal templates, depth capped at 4 by the template (ADR 0032).
- Generations exist for full rebuilds only, for the six named reasons; one live generation per workspace, flipped by one row update. The record watermark, the five-second debounce, the three System signals and the *map as of … · updating* phrase are **not built** — the phrase is retired because the delta makes it meaningless.

### Visibility derivation and audience

- A concept's class is the most restrictive among the bindings of the evidence it cites; a composition's is the most restrictive among its includes. Recompute is synchronous, inside the narrowing act's own transaction, cascading two levels: binding → concept → composition. The per-kind floor (`Person` → Restricted) is a rule inheritance can never widen past. An Admin override is a recorded act (an audit event and a row); the state where an override outruns the evidence is **shared beyond its evidence** — never a rider, never a trust signal; the fixed rule is the routing (pane leads with the reader's access, names the overriding Admin, never dead-ends) and the copy is polished at build time.
- Audience is the 2026-09-01 representation: `audience text NOT NULL` narrowed to `everyone · groups`, `audience_groups text[]`, a CHECK tying them (`everyone` ⇒ NULL array, `groups` ⇒ non-empty array), the `&&` overlap predicate against the caller's resolved group ids. The cascade combines audiences by intersection with *everyone* as the identity; **an empty intersection forces the unit Restricted** and is never stored.
- A Restricted binding's named-people audience is represented as an implicit group (member-lists-become-groups) — but **this task never mints one**: minting happens at a binding-management surface, which is B7's, and T-048's group table carries the origin discriminator that makes the implicit kind possible. Everywhere a management surface would be needed, this task treats audience as *everyone*.
- Group ids are opaque text here — platform-minted ULIDs by T-048's decision, which the boundary refinement may assume. This task never defines a group table, and `audience_groups` carries no FK (arrays cannot; the fail-closed `&&` predicate is the guarantee). The audience ADR lands with this task's visibility work and must state one model with T-048's ADR (see Further Notes).

### Suggestions, the inbox and identity

- `concept_write_request` and its SQL functions land in the schema package's migrations, fixtured in `contracts/` as sql-function agreements both suites read. A payload is platform state in no knowledge layer; nothing reads it but the acceptance path.
- `suggestion` gains a nullable `target_iri`. A suggestion's identity resolves **at acceptance, inside the commit transaction**, from a payload carrying the merge key, never a pre-resolved IRI. The set's summary re-renders against `concept_identity` when opened; an acceptance whose resolution moved since the summary was rendered is refused.

### Evidence, verification and repair

- `evidence` is keyed `(workspace_id, source_document_id, locator)`; `resource` is a rendered projection off the document, so identity follows the document rather than its URL.
- `verification.origin` gains a *repair* value. The platform's citation repair commits through the governed write like anything else, and the repair commit re-hashes the affected concepts in its own transaction, so a repair never turns *Checked* into *Changed since checked*.

### The worker

- The work loop replaces the image's refusal CMD. Its first two job kinds are this task's own obligations: the **nightly parser audit** (the Python parser cross-checking the app's parse hash-by-hash, raising `bundle_health` on mismatch — nightly is fine, deleted is not) and the **full rebuild** (the graph sync run, writing a new generation beside the live one; the flip is one row update). B7 adds job kinds to a running loop; it does not create the loop.
- Claim, lease and heartbeat are SQL functions the app migrates (they were named as T-006's in the image itself), fixtured in `contracts/`, honouring `[PIPE1]`'s lease semantics — a lease expires when heartbeats stop, and an expired run is claimable again, never lost.
- The `profiles: ["pipeline"]` line on the worker service is deleted so the service starts by default; the compose healthcheck becomes a query for a claimed lease with a fresh heartbeat.
- The `worker_rt` SELECT grant on the migrations stamp table lands in the same migration as the stamp check that reads it.
- The chunker indexes a concept's **body only, never its frontmatter**, with a test asserting no `@` reaches a concept chunk.

### Ops and the budget

- `graph-rebuild`, `graph-sweep`, `graph-counts` and `reconcile-watermark` gain implementations: the existing ops seam keeps its `done · refused · not built` vocabulary and its table-presence checks, and each command now calls the owning slice's function rather than refusing. `graph-rebuild` enqueues (or runs) a full rebuild; `graph-sweep` deletes non-live generations; `graph-counts` reports per-label counts for the live generation; `reconcile-watermark` runs the reconciler.
- Traversal and rebuild cost under concurrent load is an ordinary functional test with a **measured, stated budget** — the number is recorded in the test with the date and machine class it was derived on. The ≤2-minute rebuild budget is re-derived here, not assumed (T-007 is void; ADR 0032).

### ADRs and the glossary

- ADR 0012 gains an amendment stating the reconciler's defined action and the pre-commit minting of the `audit_event` id (and the trailer-id idempotency rule). A new audience ADR records the representation, the combining rule, the implicit-group decision and the empty-intersection rule. The ADR index gains and changes its rows in the same commits.
- `CONTEXT.md`'s **group** and **shared beyond its evidence** entries (settled 2026-09-05) stand unedited; no new glossary word is needed.

## Testing Decisions

A good test drives external behaviour through the slice's interface and asserts what a caller can observe — commits, rows, refusals, invisibility — never internals (`[TEST1]`, `[DESIGN2]`). Real Postgres always (`[TEST2]`); our own code is never mocked (`[TEST3]`); setup through factories (`[TEST4]`).

The seams, highest first — all but the last are existing seams:

1. **The `concepts` slice interface** (prior art: the workspaces slice's tests) — real Postgres via Testcontainers, a real bare repository in a temp directory. Covers: commit shape, author/committer, trailers, the hash-precondition refusal, the lock, the one-transaction guarantee (a failed row write leaves no partial state; the commit-then-crash shape leaves exactly the reconciler's finding), acceptance-time identity resolution and the moved-resolution refusal, the visibility cascade with the floor, the override and the forced-Restricted empty intersection, the repair re-hash, and the reconciler's replay (drive the handler against a repository whose head is ahead; assert idempotency by replaying twice).
2. **The api test harness** (prior art: the MCP and ops test suites) — the one-functional-test-per-unit-kind invisibility criterion: a Restricted-sourced concept invisible to a Viewer through `find`, `ask`, the graph walk, the guide page's footnote read, and `open` by IRI. Where a surface is not yet product-complete (`ask` drafts nothing until B9; guide pages render in B8), the test drives the highest read that exists — the slice function that surface will call — and the surface entry where it does.
3. **The `runOps` seam** (prior art: the existing ops tests) — the four commands' implemented behaviour and their refusals.
4. **The worker pytest harness** (prior art: the tier-contract and pg-harness tests) — the work loop's claim/lease/heartbeat behaviour, the nightly auditor's hash mismatch raising `bundle_health`, the chunker's body-only assertion, and the full rebuild.
5. **`contracts/` conformance** — the queue and inbox SQL functions as new sql-function agreements with fixtures; both suites taught in the same PR; a fixture on disk but not in the manifest fails both.
6. **Rebuild-equivalence, cross-tier and live** (the one new seam; the owner's decision at spec time): one named test drives the app's own acts — commits, acceptances, a narrowing — against real Postgres and a real bare repository, then runs the worker's rebuild as a real process against the same stores, and asserts the rebuilt generation's nodes and edges equal the live generation's **exactly**, column by column, `gen` aside. No fixture stands between the two tiers; what the app wrote is what the worker must reproduce. This test is the only enforceable meaning of *derived, never a source of truth*.

The budget test is an ordinary member of the suite, run under concurrent read traffic, asserting the stated budget.

## Out of Scope

- **B7**: connectors, indexing, extraction, and every pipeline job kind beyond this task's two; `double_claim` as a `platform_event`.
- **B8**: guide surfaces, records screens, compositions as a product — this task builds only what the cascade and the footnote-invisibility test need.
- **B9**: search ranking, answer drafting, the answer contract's full behaviour — `find` and `ask` become predicate-true over real rows, not product-complete.
- **T-023**: the Suggestions review screen.
- **T-048**: the `group` and group-membership tables, group management screens, access requests. This task stores opaque group ids and treats audience as *everyone* wherever a management surface would be needed.
- The record watermark, the five-second debounce, the three System signals, the *map as of … · updating* phrase — deliberately not built.
- Multi-process repository locking (one api process; a second is a written trigger).
- Imports, exports, and the history-rewrite routine (ADR 0020's erasure task).
