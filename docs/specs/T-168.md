## The ticket in one paragraph

The spec's default-on tier reads *dates of birth, home addresses, **personal contact on a consumer-domain list*** (`docs/specs/s0-redaction-seam-and-erasure.md:93`). T-121's seam raises `personal-contact` from Presidio's bare `EMAIL_ADDRESS` and `PHONE_NUMBER` at threshold 0.6 and no domain list exists anywhere in the tree, so a supplier's corporate address scores high and is written out as `[personal contact withheld]` on every default-on binding — company knowledge withheld from readers entitled to see it. This ticket adds the list, makes an email's domain the condition of raising it, proves both directions on the fixture, and leaves phone numbers exactly as they are.

## Rulings and decisions

**R1 — the redaction agreement does not carry this rule, and `contract_version` stays 6.** Settled on evidence, not preference. `contracts/redaction/cases.json:2` says it outright: *"Nothing here is derived from a detector — no recogniser, no threshold, no model id — because the detector is T-121's and a fixture that named one would be the seam describing itself."* A case carries six fields — `category`, `tier`, `placeholder`, `special_category`, `narrows_to`, `why` — and the `personal-contact` entry at `:67-74` changes in none of them. The one thing that could have dragged the fixture in is `version_string.must_parse`, and it does not: its two samples are `"3:presidio-2.2.364+gliner-multi-pii-v1"` and `"12:9f2c1ab4e7d0"` (`cases.json:96-105`), deliberately unlike the pins, so `RULE_VERSION` moving from 1 to 2 touches no literal there. **So: no `contracts/` edit, no manifest edit, no `SPOKEN_CONTRACT_VERSION` move in either tier, and this ticket does not serialise against S1's queue change, which is what version 7 is spoken for.** Acceptance line 3 is satisfied by this ruling plus both conformance suites run green and unchanged. The verifier is to read it that way.

**D1 — the rule lives in the recogniser the descriptor builds, not in a new descriptor field.** Acceptance line 1 says *"a tracked file the descriptor reads"*. Read strictly, that asks for a `CategoryDescriptor` field; read as the package works, the descriptor's own recogniser reads it. **Default: no new descriptor field.** A field would be carried by all eight descriptors, seven of which have no domains; it would force the hand-maintained digest rendering to grow anyway; and it would put an email-shaped rule in a table that deliberately holds only what every category has. The list is reached from the `EMAIL_ADDRESS` factory at `engine.py:123`, which is the descriptor's own entry in the table of what raises it, and the digest covers the list (plan item 5) so the two still cannot drift. Reverse it and the rule still lands; the cost is a `domains` field on eight descriptors and a second digest recomputation.

**D2 — the list is a Python module, not a data file.** *Default: `consumer_domains.py` with three exported constants.* The package reads no file today — every rule in it is a Python literal (`recognisers.py:53-98`, `descriptors.py:52-125`, `pins.py:21-82`) and there is no non-Python tracked file anywhere under `apps/worker/src/`. A `.txt` or `.json` would be the tier's first, would need a resource read, and would have to be proved to ship in the image — and the image suite is not in this ticket's test commands, so that proof would not run here. A module cannot fail to ship: the Dockerfile copies `src` wholesale (`apps/worker/Dockerfile:69-73`). It is still "a tracked file, with its date and source", which is what the line asks for.

**D3 — one new glossary word, *consumer-domain list*.** The spec uses it at line 93 and `CONTEXT.md` does not hold it; `[GLOSSARY1]` says a missing word is settled in `CONTEXT.md` first. **Default: add the one entry beside *redaction rule*.** Nothing else in this ticket is a domain word.

**D4 — what "its source" means.** No single authority publishes "the UK's consumer email providers". **Default: `SOURCE` names each provider's own sign-up or domain page where one exists, as one line per family, and the docblock says plainly that the membership judgement — which providers count as consumer — is this repository's, dated.** The alternative, citing a third-party aggregator list, would pin a rule to a page nobody here controls. `[DEPS1]`'s discipline is the model: the value comes from the source at the time of the change and the commit names where it was read.

**D5 — the fixture changes two addresses rather than gaining two more.** **Default: change them.** Adding a third and fourth address grows a page whose every offset the suite depends on, and leaves two documentation-domain addresses that now prove nothing. Changing them keeps the page at its size and makes the pair legible: one person's own provider, one company mailbox. The consumer address uses a real provider's domain because the rule under test is membership of that list — a fixture on `example.com` could only ever prove the negative direction.

## Known hazards

**H1 — both of the fixture's emails are on documentation domains, so the rule as written would silently gut the page.** `rosalind.petheridge@example.com` and `callum.whitcombe@example.org` are RFC 2606 reserved, on nobody's consumer list. The page and the rule move in the same commit (D5).

**H2 — `RULE_VERSION` has three literals, not one.** `pins.py:58`, the `VERSION_STRING` literal at `test_redaction_descriptors.py:159-168`, and the `RULE_VERSION == "1"` assertion at `:186`. Move one and the suite is red; move none and the claim in `pins.py:55-57` is false. The descriptor digest at `:183` is a fourth literal and moves only if the rendering grows (plan item 5) — which it should.

**H3 — offsets are code points into the text the seam was given**, never into the redacted text, whose length differs by every placeholder (`test_redaction.py:11-13`). The negative direction is asserted as "no finding overlaps this range in the input", and the "it survived" half is asserted against the **redacted** text. Two different strings; do not mix them.

**H4 — `test_image.py` keeps its own copy of the fixture's answers and this ticket does not run it.** `PLANTED_SPANS`, `FINDINGS_BY_CATEGORY` and `PLACEHOLDERS_IN_THE_TEXT` at `:145-178` are literals by design (`[TEST9]`, its docblock at `:141-144`). The image build is required only under CI (`test_image.py:215`), so a stale literal passes locally and fails on the block's CI run. Move them in the same commit and quote both tables into the note.

**H5 — the redaction suite is slow and the model is lazy.** One process-wide builder at `engine.py:271-285`, about 6-7 s to load plus 2-3 s per `redact()`, and `test_redaction.py` makes seven calls (`:131-158`, module-scoped fixtures). A new case that calls `redact()` with a different argument buys another 2-3 s; prefer reusing the existing module-scoped bindings. The weights must be in a warm `HF_HOME` before the first red-green cycle or the first run downloads hundreds of megabytes.

**H6 — jscpd runs over Python at threshold zero** (`minLines` 5, `minTokens` 50; T-120 and T-121 both lost time to it). A wrapper recogniser that copies `ModelRecogniser`'s shape line for line will trip it. Share the base or state the reason beside an ignore, never move the threshold.

**H7 — two root `check`s never run side by side on this machine** (`docs/agents/build-loop.md`, T-140): each builds the worker and api images inside its suites, and two at once filled the host volume and starved the long core suites. Other agents are live in this session; the evaluator runs 4c alone.

**H8 — the tag rule is wider than "source"** (`[COMMENT2]`, and three loops have lost a root-check run to it): a rule tag never appears in source, a deploy file, a Dockerfile, a CI workflow or a workspace config. `consumer_domains.py` carries its reasons in words; the tags go in the tests.

**H9 — scope.** No migration, no `contracts/` edit, no `contract_version` bump, no descriptor field unless the orchestrator reverses D1, no change to `_finding_of`, no new category, no phone-number change, no image or Dockerfile edit. A finding outside the ticket is one line in ralph's report for the hygiene lane.
