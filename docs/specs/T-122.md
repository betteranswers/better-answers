## Known hazards

**H1 — the compose bind masks the baked weights.** `deploy/platform.compose.yaml` mounts the host's `/data/worker/hf-cache` over the container's and sets `HF_HUB_OFFLINE: "1"` beside it (`# after first warm`). Weights baked at that path are invisible at run time, and with offline already set the result is not a quiet re-fetch but a worker that cannot load a model at all. `docker run --network none` in the test would still pass, because the test mounts nothing — so **the acceptance test alone does not catch this**. C1 removes the bind and a test holds it removed.

**H2 — the tokenizer entry.** `urchade/gliner_multi_pii-v1` loads `microsoft/mdeberta-v3-base`'s tokenizer from a second HF repo (4.1 MB, measured on this host). Fetch by loading the model, not by snapshotting it. The offline test is what proves it either way.

**H3 — image size.** ≈1.8 GB of weights on a 414 MiB image. Both models ship because acceptance line 2 says both are asserted present. If the size is judged unacceptable that is the orchestrator's decision, not the loop's; the report states the number.

**H4 — build time and CI.** `check.yml` (every pull request) runs this tier's pytest, which builds the image with a plain `docker build` and no shared BuildKit cache, so CI downloads the weights once per run; `build.yml` has `cache-to: type=gha,mode=max` and pays it once per cache key. The worker's `check` was 39.6 s before T-121 and ~1m15–1m45 after it; expect another cold minute or two the first time and near-nothing after, thanks to the layer cache and the `--mount=type=cache`. `_build_the_image`'s timeout is 900 s — raise it only if a measured build approaches it, and say so.

**H5 — the second model is measured, never run.** The seam's pin stays `urchade/gliner_multi_pii-v1`. If the measurement argues for moving it, that is a decision for the orchestrator and a different ticket, not this loop.

**H6 — spaCy's pipeline is not under `HF_HOME`.** `en-core-web-sm` is a pinned wheel in `uv.lock` (`tool.uv.sources`), so `uv sync` installs it into the venv at build; there is nothing to fetch into an HF cache. Acceptance line 1's promise — present at build, never fetched at run time — holds, and the test proves it by loading the pipeline in the offline container. The verifier should read the line that way; the docblock says so.

**H7 — `test_image.py` imports nothing from `src`.** Read `pins.py` as text. An import would break the mutmut and Stryker constraint `pyproject.toml` states.

**H8 — `print` is banned** (`T20`, and `[LOG1]`/`[WRK2]`) outside scripts. The measurement is emitted with `logging.getLogger(__name__).info(...)` and the docblock says why it is neither `print` nor the tier's structlog — the file imports nothing from `src` (H7), and the number is for a person reading a run rather than for the tier's JSON log. If the implementor prefers `record_property`, say so in its report; either way the numbers land in the docblock, which is what the acceptance line asks for.

**H13 — `[WRK2]`: `config.py` is the only module in this tier that reads the environment.** `weights.py` therefore reads no environment variable: `HF_HOME` is set by the Dockerfile for the build's process and by the image for the container's, and it is `huggingface_hub` that reads it, never our code. A `weights.py` that did `os.environ[...]` would be a rule break, not a convenience.

**H9 — `_run_the_image` is an existing symbol with callers.** `impact` before editing it, and report HIGH or CRITICAL to ralph rather than absorbing it. Same for the `engine.py` builder.

**H10 — parallel tickets.** T-124 and T-133 are in flight in wave 3. T-124 amends **ADR 0020**, which is why this ticket amends no ADR (**O2**). Nothing else this ticket touches is in another ticket's path.

**H11 — root `check` on this machine has been timing out three core suites under parallel load (T-140).** If those three fail in the root run, re-run them alone and record both readings.

**H12 — arm64 here, amd64 on CI.** The local build is `linux/arm64` (Docker Desktop, Apple M4 Pro). `torch==2.14.0+cpu` has a `manylinux_2_28_aarch64` wheel in `uv.lock`, so `--frozen` resolves here — verified in the lockfile. The measurement's docblock must name the architecture it was taken on.
