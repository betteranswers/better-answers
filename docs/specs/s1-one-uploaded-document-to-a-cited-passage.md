# S1 — One uploaded document to a cited passage

*Block spec written 10 September 2026 from the route spec's S1 block (`docs/specs/v01-route.md`), ADRs 0005, 0007, 0013, 0016, 0018, 0020, 0023, 0024, 0025, 0031, 0032, 0036, 0037, 0039 and 0040 through `docs/adr/README.md`, `CONTEXT.md`, the tree at `d7a36c4`, the S0 block spec beside it, discovery tickets 17, 48, 52, 53, 54 and 55, briefing 53, research `cocoindex-capability-map.md` and `source-connection-configuration.md`, the pre-build gate's §4 and §8, T-113's four reports and the four probes of 10/09/2026. The staleness pass over the sources the block cites is in Further Notes. Decisions recorded here are taken; do not re-open them. S0 is specced beside this block and the boundary between the two is stated in S0's Further Notes and restated here.*

**The authority order** of the route spec binds this document: `docs/adr/README.md` · the ADR body with its amendments · `CONTEXT.md` · the tree · this spec · the gate · the map · a ticket body. This spec cites the first four for *what* and the rest for *why*.

## Problem Statement

The first client's knowledge arrives as four bid libraries handed over as files, and the platform cannot take one. An Admin has nowhere to put a document: the Sources screen renders *unbuilt*, the object door is an empty module, the sources slice knows one act — narrowing a binding that nothing has yet bound — and the worker's loop runs two job kinds that never touch a document. `find` previews the concept index alone; `open` by locator answers *not found* until the source catalogue exists. Nothing between a file on a bid writer's laptop and a passage a reader can cite exists today, and the route holds every later block on the knowledge strand behind this one.

What does exist was declared for a world that embeds. `index.chunk` requires a vector and a route id on every row, carries no locator and no document, and the one runtime-DDL function builds an HNSW index over a column nothing writes until the reserve block S8. The queue cannot say what a job is about, hands any kind to any claimant, and no enqueue can join an act's transaction, so a publish that lands a binding and its index job cannot be one act. The redaction seam S0 builds has no host to run inside.

## Solution

One binding shape, one job kind, one pipeline module and one read. An Admin **binds an upload** on the Sources screen: the file streams through one tRPC mutation to the object door under the workspace's prefix, the binding and its one source document land Restricted and unpublished, and an **`index` job** naming that binding lands in the same transaction. The worker claims by kind and runs the job through one **`pipeline/`** module — the only importer of cocoindex — which reads the landed copy, converts it, passes every span through S0's seam inside **one memoised function** whose return value is already redacted, splits the redacted text into chunks with cocoindex's own splitter, and writes `index.chunk` rows carrying the document, a locator, the binding's three visibility columns and no vector; the chunk's full-text vector is a generated column neither tier writes. The Admin **reviews the findings** by category and rule, keeps a span in text or narrows a document, and **publishes** with the three confirmations; the publish act stamps the binding, rewrites its chunks' visibility copies and writes the ledger row carrying the finding totals and the DPIA input's hash. From then on `find` returns a passage of that document as a hit marked *Not company knowledge* and `open` by locator returns the passage verbatim, in the app and over MCP alike, through one door on the sources slice that applies the chunk's predicate once. Nothing is embedded, nothing calls a model, and the same acts, the same worker process and the same read are asserted end to end by the route's one new seam.

## Implementation Decisions

### The words

`CONTEXT.md` gains four words before code names them (`[GLOSSARY1]`): **chunk** — one unit of a document's normalised, redacted text the index holds, keyed by its document and ordinal, carrying its binding's visibility; **locator** — the address of a passage inside a source document, the string a citation's `sources[].locator` and a chunk's row both carry: a span, `chars:<start>-<end>`, offsets in Unicode code points into the document's normalised redacted text, versioned by the redaction string that text carries (the architecture pass of 10/09/2026, candidate 1 — a span is what the glossary's *evidence* and `docs/okf-v02.md` already say a locator is, and a company with no platform can follow it given the normalised copy; a chunk ordinal is the splitter's artefact and moves on every splitter change); **passage** — the text a locator resolves to, served with its source's title and its sensitivity word, the unit `open` returns and a hit marked *Not company knowledge* previews; **landed copy** — a document's bytes as the platform holds them in the object store, the original and the normalised redacted text under one document key. *Source binding*, *source document*, *job*, *claimant*, *outcome*, *publish*, *retention class*, *destination*, *hit* and *open* stand as written; *job*'s subject sentence (T-113) is what the queue below implements.

### The queue — the first tracer bullet

Three lenses of T-113 converged on the queue, and it lands first because every later line enqueues through it.

- **One declared descriptor per kind**: name, the claiming tier, whether the row names a subject, whether it carries a reason and which reasons, and the role that may enqueue it. The kind CHECK, the subject CHECK, the reason CHECK and the queue fixture's admitted kinds derive from that record, so S4's connector kinds, S6's api-claimed job and S8's catch-up job are one record each and never a migration by hand. The two existing kinds are the first two records.
- **S1 declares one new kind, `index`**: claimed by the worker, subject required — the binding — and carrying a reason from a closed list: *bound* (the upload act's), *restored* (a finding kept in text, S0's act), *rule-change* (the binding's rules in force edited), *wiped* (S0's routine, step 7), *narrowed* (a document narrowed from the review). The route's four names are the shape; the count is this block's: `reindex` is `index` with a reason, because the memo decides what re-runs and a second kind would be a second host path for the same flow; `bind` (a connected source's enumeration) and `prune` (the retention sweep and a binding's removal) are S4's records, one each. The reason CHECK stops coupling a reason to one kind; a rebuild's six reasons stand.
- **`job` gains `subject_id`**, typed text, nullable, under a per-kind CHECK the descriptor writes (owner D3: a typed column, never a payload). An `index` job about nothing is refused by the row.
- **The claim takes the kinds a tier can run**: `claim_job(p_worker_id, p_lease, p_kinds text[])`, the array required; the worker passes the kinds its registry holds, the api's foreground rebuild passes the rebuild kind alone. The queue agreement's fixture gains a case per tier and one where a kind nobody passes stays queued; `contract_version` bumps.
- **One run per binding at a time is the queue's rule**, in SQL: a partial unique index on `(workspace_id, kind, subject_id)` over queued rows makes a second enqueue for the same binding answer the existing job's id (the glossary's *run key*, kept here rather than as a column), and the claim skips a candidate whose subject has a claimed sibling under a live lease. Both are fixture cases.
- **`enqueueJobIn(principal, tx, input)`** lands beside the door form, the door form calling it, so the upload act lands the binding, the document and the job in one transaction and S0's routine enqueues inside its own. The Admin gate is per kind from the descriptor; S8 widens it for an Editor's write.
- **The worker's registry**: the body of the loop's dispatch becomes a lookup, `KINDS[kind](bootstrap, job)` answering an outcome, each kind opening the stores and the transaction it needs; the host keeps claim, heartbeat on its own connection, finish, fail and its two log lines. The two existing kinds open their own scoped transaction and change nothing else. The loop's shape — one pass over every workspace, one job at a time — is untouched, which is what "S1 adds kinds to a loop that exists" means.

### The schema — the ALTERs on empty tables, then the columns

Verdict 4 of T-113: a family is one migration, nothing re-keys. Every column below lands with its boundary refinement (ADR 0028), its row in the table-ownership map and the worker's schema view regenerated; every grant and the replaced definer function with the refusal `[SEC3]` requires beside the served path.

- **`index.chunk`**: `embedding` and `embedding_route_id` drop NOT NULL together under one CHECK that keeps the pair together (probe 1 proved the ALTER propagates on the partitioned parent); `source_document_id` and `locator` written by the worker, unique per workspace with the document, keyed to `source_document` by the pair and cascading with it; `search`, a stored generated `tsvector` over `content` with the English configuration, neither tier writes; the ordinal as a column so a passage read never parses its own locator; `char_start` and `char_end`, the chunk's span in the normalised redacted text as the splitter reported it, so a locator's range resolves to its covering rows by two comparisons. `id` stays the primary key's second half and becomes **derived**, below.
- **The lifecycle function** is replaced: the per-partition GIN index on `search` joins the partition's creation and the HNSW line leaves — an index over a column nothing writes until S8 costs every new workspace a build and memory for nothing, and S8's ALTER on existing partitions is S8's. The refusal tests stand: the guard on scope, the direct read of a partition.
- **`source_binding`** gains what a binding is beyond its three fields: a name, the connector (*upload* in v0.1; the roster's other four are S4's words on the same column), the destination as a set defaulting per connector — an upload's is chunk index and bundle, shown in words, and only the chunk index is acted on until S7 — the retention class (*keep* for an upload), the rules in force (S0's column), and a state word the screen reads: *landed · indexing · indexed · published*. No credential, scope or cadence column lands: an upload has none, and S4 adds them with the connectors that do.
- **`source_document`** gains the catalogue: the source-system id (the upload's file name, unique per binding), the title, the media type and byte size, the locator of the original and of the normalised copy in the object store, `content_hash` over the original normalised text before the seam (S0's decision), the redaction version string the seam returned, first and last seen, `last_modified` nullable, `gone_at`, the run outcome word (*converted · quarantined*), and its own `sensitivity`, nullable — the binding's when null, narrower when set by the seam's special-category verdict or by the Admin's *narrow these documents*. The visibility derivation reads the narrower of the binding's and the document's class through the document row it already joins; the invisibility suite gains the row.
- **`evidence → source_document`** lands as the composite key the docblock deferred, `ON DELETE RESTRICT` (owner D5): a binding's drop is blocked while cited evidence stands, because cited evidence outlives its source (ADR 0013). The removal act itself is S4's; S1 proves the key refuses.
- **`audit_event`** gains the unique index on `(workspace_id, id)` (ADR 0014, amended 2026-09-10), so the publish row can be keyed to later.
- **The worker's privileges**: SELECT on `source_binding`, SELECT and UPDATE on `source_document` (the catalogue every run reconciles is ours — the hash, the copies, the version string, the outcome word, last seen), INSERT, UPDATE and DELETE on `index.chunk` (the target sync deletes a withdrawn document's rows), INSERT on `finding` and SELECT on `suppression` (S0's tables). Each with the refusal proven, and the cross-owner entries in the ownership map naming the worker on `index.chunk` and `source_document`.

### The chunk's identity and the locator

- **The chunk id is derived, not minted**, from `(source_document_id, ordinal)` — the document's ULID and the zero-padded ordinal joined — so a reprocess upserts on the row's key (ADR 0036, amended 2026-09-10) and either tier can compute a chunk's id from its address. It is cocoindex's *stable id* in ADR 0036's sense and not an id the platform mints, so the `id-shape` agreement stands as it is; its description's sentence that the worker mints no id is stale since T-057's self-scheduled audit and is corrected in the same PR.
- **The locator is a span, not the ordinal** (the architecture pass of 10/09/2026, candidate 1; default decision (3) reversed by the owner the same day). On a chunk row the locator is the chunk's own span, `chars:<start>-<end>`; on an evidence row it is the cited span, which S7's extraction writes per claim and which need not coincide with a chunk. Offsets are Unicode code points into the normalised redacted text — the two tiers index strings differently (Python by code point, JavaScript by UTF-16 unit), so the `document-chunk` fixture carries an astral character before a cited span and both tiers must agree on it. The wire form a citation carries and `open` accepts is `<source document id>/chars:<start>-<end>`, the two halves the evidence row keys on, so a citation and a passage are one address; the span's version is the document's redaction string, and a re-detection re-baselines it as ADR 0020 already says. A malformed, unknown or out-of-range wire locator answers *not found*, the same word as a withheld one. The chunk id stays derived from `(source_document_id, ordinal)` — ADR 0036's stable id and the reprocess upsert are untouched; a splitter change re-writes the rows and moves no citation.
- **The chunk's content** is the normalised, redacted text of its span — never the original — and the chunker's body-only rule for concept files stands where it is, renamed for the unit it splits (T-113's C11). The document splitter is cocoindex's recursive splitter at one size the pipeline module states, with the ordinal the splitter's position; the size and the configuration are a constant beside the memo version.

### The sources slice's acts

Every act takes the Principal and refuses before a row is written; every Admin act writes its ledger row bare in the same transaction (`[AUDIT1]`, `[AUDIT2]`), the detail carrying ids and role words (`[AUDIT5]`).

- **`bindUpload`** — the door-taking act: the file's bytes stream to the object door under the workspace's prefix first (blob before row, the object door's discipline, the original's key), then one transaction writes the binding (Restricted, everyone, unpublished, `keep`, the safe rule set), its one document row, the ledger row `sources.binding.bound`, and the `index` job with reason *bound* through `enqueueJobIn`. Refusals, decided before the bytes are read where they can be: a non-Admin; a name or class or audience malformed; a group the workspace does not hold; a media type outside the allow-list — markdown, plain text, Word's `.docx`, PDF — and a file over the per-file cap, one exported constant under the edge's 100 MB. A crash between the put and the row leaves an orphan object; the orphan-blob sweep is S4's, and the key discipline makes it findable.
- **`findingsOf`** — the review read: a binding's findings grouped by category × rule with counts and the document each sits in, never a value or an offset; Admin only. The two bulk acts over it: *keep in text* calls S0's finding restore per span under one batch id and enqueues `index` with reason *restored*; **`narrowDocuments`** sets the named documents' class to Restricted, rewrites their chunks' copies and runs the cascade from those documents' citing concepts, one ledger row per document under one batch id, and never widens.
- **`publishBinding`** — Admin only; refused while the binding's latest `index` job has not finished (*not-indexed*), when already published, or when any of the three confirmations is missing. It stamps `published_at` from the Clock the api hands it (ADR 0040), rewrites the binding's chunks' `published_at` in the same transaction, calls S0's DPIA input function, and writes `sources.binding.published` carrying the three confirmations as typed fields, the finding totals by category and the DPIA input's hash. No job: the chunks exist from the bind, and the rows are the app's to stamp.
- **`narrowBinding`** (T-055) gains level zero: the binding's chunk copies of the three visibility columns are rewritten in the same transaction before the concepts and compositions, under the cascade lock it already takes. The widening act stays S4's.
- **`passageAt(principal, tx, locator)`** — the one read over a chunk's columns: the span's covering rows selected by `char_start` and `char_end` under the reader's predicate applied there once, joined to the document's title, and the span's text cut from those rows' content — a span that straddles two chunks answers as one passage, and a span any covering row's predicate withholds answers *not found* whole; `open` by locator, S2's unmapped passages and S4's citation repair take this door and no other. A withheld passage and an absent one answer alike.
- **`findPassages(principal, tx, query, limit)`** — `find`'s document arm: a full-text match over `search` under the predicate, ranked by the parser's rank, one hit per chunk, excluding a chunk whose document is cited by a concept the reader may see, so a document stands alone only when no visible concept covers it (ADR 0016). The concept arm stays the concepts slice's own read until S2 replaces its predicate with the stored vector; fusion by kind is S2's when both arms rank by one expression.
- **`previewChunks`** — the Admin's road to an unpublished binding's chunks for the Sources screen, applying the class and audience clauses without the published arm; the only read anywhere that omits it, and it takes a user principal that must be an Admin.
- **`reprocessBinding(principal, tx, {bindingId, reason})`** — the wipe's first half as one act for S0's routine and the rule-change edit: the binding's chunk rows deleted in the caller's transaction and an `index` job enqueued with the reason. The LMDB directory is on the worker's volume and the worker removes it: an `index` job whose reason is *wiped* removes the binding's directory before it opens the Environment. That is the order ADR 0036's amendment names, spread across the two tiers that hold the two stores.

### Two writers of the chunk's visibility, one source

The visibility-columns agreement has the worker write `published_at`, `sensitivity`, `audience` and `audience_groups` on every chunk row it lands, and the acts above have the app rewrite them on a publish, a narrowing and a document's narrowing. Both copy from one row — the binding, narrowed by the document — so they can disagree only in a race: a run that read the binding before a narrowing committed and upserted its rows after. **The run's last statement re-copies** the binding's and the document's current fields onto every row it wrote, in the worker's own scoped transaction before the job finishes, so a narrowing that landed mid-run wins; a narrowing that lands after that statement finds the rows and rewrites them itself. The cross-tier test holds the race from both sides. ADR 0031's visibility-columns row gains the sentence.

### The worker as a host

T-113's verdict 2 folded, none of it reshaping the loop:

- **One `pipeline/` module** whose interface is `index_binding(bootstrap, run)` answering an outcome of plain types and whose implementation alone imports cocoindex; the ruff ban S0 lands for the whole tier is lifted for this module alone by a per-file ignore, and a test holds the ban as the `unittest.mock` ban is held.
- **One asyncpg pool per workspace**, `min_size=0, max_size=2` (probe 4: the default is ten), a session-level `SET app.workspace_id` in the pool's connection init, handed to that workspace's Environments through one module-level context key — because the flow's rows land outside the job's transaction and `index.chunk` forces row-level security.
- **Environments in a bounded LRU keyed by binding id** on the host's one event loop; the host awaits `app.update()` on that loop or calls the blocking form from a plain thread, never the blocking form from inside the loop (probe 4: it deadlocks). Eviction drops the reference; every claim reads the binding's LMDB size after the run and writes it on the outcome row.
- **The engine's defaults set from the box** in the tier's one config module, in the commit that first reads them: the LMDB map size from the compose file's per-binding cap, `max_inflight_components` from a constant sized for one run, the LMDB root directory, and the object store's endpoint, key, secret and bucket — the platform's own object store is bootstrap class, as the compose file already gives it to both tiers; a client's own store as a source is the envelope's and S4's. `MAX_CONCURRENT_RUNS` is read and held to one: the loop already runs one job at a time per process, and a higher value is S4's measurement.
- **One log shape**: `RUST_LOG=warn` in the bootstrap and the compose service, and a stdlib-logging bridge into structlog so the engine's connector logs leave in the tier's JSON.
- **Every target `managed_by="user"`**; the app owns all DDL (ADR 0007, `[PIPE1]`); a two-Environment test proves a drop on one binding leaves the table, its indexes and the other binding's rows standing — and, from probe 4, its own rows too, which is why the row deletion is the app's act above.
- **The object store is read with the worker's own S3 client**, pinned per `[DEPS1]`; the flow is handed bytes the worker already holds and cocoindex's own S3 source is not used. The landed copy is read by the document's original key; the normalised redacted text is written back under the document's normalised key, once, outside the memo.

### The one memoised function and the converter

- **`landed(document) → RedactedDocument`** is one `@coco.fn(memo=True)` whose body is conversion then S0's seam, versioned `rule_version:detector_pin` from S0's constants, taking the binding's rules in force and the document's applicable suppressions as arguments and never as a `detect_change` key, so no memo ever holds an unredacted span and a suppression changes one document's key alone (gate §4 probe 3). Nothing beneath it is memoised; the chunk step is not memoised either — splitting redacted text is cheap and a second memo is a second copy.
- **Conversion in v0.1 is pure Python**: markdown and plain text pass through as the normalised text; `.docx` through a pure-Python converter; PDF through text extraction with no OCR and no layout model. Docling is a written trigger for S4 — the first SharePoint library whose PDFs need layout — with its own memory measurement, because torch inside the worker process segfaulted under the engine's runtime in prototype 52 and the box's cap is 1.5 GB. A document the converter cannot read is *quarantined* on its catalogue row with the error's name and never a run failure; per-document isolation is `mount_each`'s.
- **The torch risk is this block's first act.** S0's detector runs GLiNER on CPU, which is torch in the worker process; prototype 52 saw that segfault under the cocoindex runtime. The first ticket that wraps the seam in the memoised function runs it on the worker image and records the result; if it reproduces, the seam runs in a spawned subprocess called from inside the memoised function — plain types cross, `[PIPE1]` holds, the memo still holds only the redacted return — and that is the fallback taken without a new decision. A model host is not the answer (ADR 0024's precondition).

## Testing Decisions

A good test drives external behaviour through the interface a caller uses and asserts what that caller can observe — rows, a refusal, a passage, invisibility, a screen — never internals (`[TEST1]`, `[DESIGN2]`). Real Postgres always (`[TEST2]`); our own code never mocked (`[TEST3]`); setup through factories (`[TEST4]`); a pair checked both ways (`[TEST7]`); an expected value written down (`[TEST9]`) — the passage is a literal in the test, never the fixture's text interpolated.
