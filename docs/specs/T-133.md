**`passageAt(principal, tx, wire)` → `Result<Passage, LocatorRefusal | Error>`.** `parseLocator` first, its refusal returned as it stands. Then one statement for the covering rows of `index.chunk` (`char_start < :end AND char_end > :start`) under `readableClause("c", 2)`, joined to `source_document` for the title, ordered by ordinal. **Coverage is checked, not assumed**: the span is answered only when the rows run contiguously across it, which is what makes a well-formed span past the end of a 165-code-point text answer *not found* from the read rather than the parser. The text is cut through `spanText` by code points, offset by the first covering row's `char_start`; the class is the narrowest of the covering rows, folded with `narrower`. `Passage = { locator, title, text, sensitivity }`.

**`findPassages(principal, tx, query, limit)` → `Result<readonly PassageHit[], Error>`.** One statement. `$1` workspace, `$2` query, `$3`/`$4` the chunk's predicate via `readableClause("c", 3)`, `$5`/`$6` the concept's via `readableClause("ci", 5)`, `$7` the limit — `readableParameters(principal)` spread twice, in that order. `websearch_to_tsquery('english', $2)` cross-joined, matched `c.search @@ q`; the predicate ahead of the ranking; the ADR 0016 exclusion as a `NOT EXISTS` over `concept_evidence` joined to `concept_index`; `ts_rank(c.search, q) DESC` tie-broken by `c.source_document_id, c.char_start`; limit clamped into `[0, MAX_PASSAGE_HITS = 20]`. `PassageHit = { sourceDocumentId, title, locator, sensitivity }`, no excerpt, no count, no total.

**`previewChunks(principal, tx, { bindingId, limit? })` → `Result<readonly PreviewedChunk[], RoleRefusal | "malformed" | Error>`.** `requireAdmin` before the id is parsed and before a row is read, through `adminOnBinding`. One statement under **`sensitivityAndAudienceClause("c", 3)` — the class and audience arms without the published arm**, the only read anywhere that omits it, with the reason and the ticket named in a comment beside the SQL. Ordered by document then ordinal.

In all three, a hit's or a row's wire locator is **composed** from `source_document_id`, `char_start` and `char_end`, never parsed out of the `locator` text column.

### The rulings taken — do not reopen these

1. **`passageAt` returns `Result` with `"not-found"`**, the fixture's own word and the one `parseLocator` already refuses with, rather than `conceptByIri`'s `ok(undefined)`. Coverage is checked so an uncovered well-formed span answers it too.

A suite assertion holds the stored column equal to the locator composed from the row's three columns, so the two cannot drift.
4. **The concept exclusion is one statement with `NOT EXISTS`**, its predicate from the same `readableClause` builder as the chunk's. Never a second query — that would be a second round trip and a race against a concept landing between them. The concept *arm* of `find` stays the concepts slice's own read.

It does carry one — *entry points in v0.1 are full-text over the concept index* — but that amendment says nothing about `open` by locator or a document under a citing concept, which is what the ticket's Notes attribute to it. The rule the code implements is the ADR's **body** sentence, *a document or a section stands alone only when no concept covers it*, plus the 2026-08-28 amendment's *the same predicate, once, from the same builder*, and both are implemented faithfully. The hygiene item should be re-worded from *no amendment of that date* to *the amendment of that date carries other words*, so a later ticket citing the line is not sent looking for something that is not there.
