# T-307 — The bundle loader: the reviewed client bundle landed through the governed write, its checks imported, its links minted

## Problem Statement

The first client's four bid libraries are now one OKF bundle of 243 concepts (241 `Answer`, 2 `Tier`) on disk, verbatim-checked against the libraries and reviewed concept by concept (`.planning/client-bundle/`, branch `bundle-draft`). Nothing can read it. The MCP surface's `find` and `open` answer from the concept index, and the only door into a workspace's bundle is the governed write, one concept at a time, minting an IRI as it goes. An operator who wants the client's writers to find an approved answer in Claude today has no command to run.

The files also carry three things the platform does not allow to stand: a relative link where ADR 0002 wants an HTTPS IRI; a verifier named by email where ADR 0014 and ADR 0035 want an opaque person id; and no manifest at the bundle's root, which ADR 0002 (amended 2026-08-30) requires.

## Solution

One ops command, `import-bundle`, run by the operator on the api service against a provisioned workspace with the bundle directory beside it. It validates the whole tree before it writes anything; writes the manifest as the bundle's first commit; lands every concept as a governed write with the file's own `sources[]` as its projection and no evidence; records each file's `verified` event as an imported check on the concept, which readers see as *Checked by Matthew Burgess · 16 April 2026 · imported*; and in a second pass rewrites every relative link to the IRI the first pass minted, each rewrite a governed write with a base precondition. A rerun skips what already landed. After it, `find` returns the client's answers with their trust words and tags, `open` shows one, and the route's C1 import is a command rather than a plan.

## User Stories

### Running the import

1. As an operator, I want one `pnpm ops import-bundle` command taking a workspace, a bundle directory and the member it runs as, so that the client's bundle lands without me touching the repository or the database by hand.
2. As an operator, I want the command to refuse before writing anything when the tree is not sound — a file that does not parse, a link to a file not in the tree, a verifier who is not a member, a reserved path, two files deriving one merge key — so that a half-landed bundle never exists.
3. As an operator, I want every refusal to name the file and the reason in one line, so that I can fix the bundle and rerun.
4. As an operator, I want a rerun to skip every concept already landed at its path and do only what is left, so that a crash mid-run is recovered by running again.
5. As an operator, I want a closing summary (landed, skipped, checks recorded, links rewritten, seconds taken), so that the number goes in the runbook and the estate-size record C1 asks for.
6. As an operator, I want the command to run as a named Admin or Editor of the workspace, so that every commit and audit row carries a real actor and never a platform principal.
7. As an operator, I want a dry run that validates and reports without writing, so that I can check a bundle on staging before the real run.

### What lands

8. As a bid writer, I want every approved answer to be a concept in my workspace with its title, body and sections exactly as the reviewed bundle has them, so that what I quote is the approved wording.
9. As a bid writer, I want each concept's tags and description carried over, so that `find` ranks and labels them as the bundle intended.
10. As a bid writer, I want the two Tier concepts and the tier-specific answers to land with their links intact, so that a Standard-module answer and an Advanced-module answer are told apart.
11. As a reader, I want an imported answer to read *Checked by Matthew Burgess · 16 April 2026 · imported*, so that I know a person approved it and that the check predates the platform.
12. As a reader, I want an imported answer that is later edited to read *Changed since checked* with the earlier check kept, so that the import's check behaves like any other check.
13. As a reader, I want a concept's cross-references to open the concept they name, so that "the print restrictions are in …" leads somewhere.
14. As a Viewer of the workspace, I want the imported answers visible to me, so that a bid writer without Admin rights can use them.
15. As an Admin, I want the import's sensitivity to be a flag with *Internal* as the default, so that a bundle that should start *Restricted* can.

### The bundle's own shape

16. As the platform, I want the bundle to carry a manifest at its root (id, origin, ref, owner, content version) written before any concept, so that the bundle self-describes from its first commit.
17. As the platform, I want no email in any concept file after the import — the file's `verified.by` becomes `human:<person id>` — so that ADR 0014 and ADR 0035 hold and an erasure finds every mention by id.
18. As the platform, I want every concept-to-concept link in a file to be an HTTPS IRI after the import, so that ADR 0002 holds and a rename never breaks a link.
19. As the platform, I want the reconciler to replay the import's commits, the manifest's included, without stopping, so that a restore lands the same rows the import did.
20. As the platform, I want `index.md` and `log.md` left out of the write, so that the derived index and the ledger stay the platform's.

### Proving it

21. As a developer, I want the whole path proved through the ops runner against a small fixture bundle in the client bundle's shape, so that the wiring, the flags and the exit codes are held by a test.
22. As a developer, I want each refusal proved at the core act, so that the refusal table is cheap to extend.
23. As a developer, I want the fixture to hold one split tier pair with its two Tier concepts, one cross-domain link, one link between split concepts and one file with two `verified` events, so that the rewrite pass and the checks are proved on the shapes the real bundle has.
24. As the owner, I want the real bundle rehearsed on staging with the synthetic seed before production, so that the seam sketch's promise ("rehearsed on staging, then run against production by the operator") holds.

## Implementation Decisions

### One command, one core act

- `import-bundle` joins the ops commands beside `erasure-rehearsal` and `reconcile-watermark`. Flags: `--workspace <id>`, `--from <directory>`, `--as <member email>`, `--sensitivity <Restricted|Internal|Public>` defaulting to Internal, `--dry-run`. Exit codes are the runner's: done, refused, usage, not built.
- The ops io gains a reader for a directory tree (relative path to text), injected as the runner's other doors are, so the test hands it a fixture and the operator's run reads the box.
- The work is one core act, `importBundle`, in the concepts slice, taking a UserPrincipal, the git, postgres and clock doors and the tree. The command is a thin shell: flags, doors, the principal resolved from the member's email, lines said. No new seam: every concept lands through `writeConcept`.

### Validation before any write

- The whole tree is read and checked first: frontmatter parses (the bundle's files are YAML with flow mappings, so the loader parses with a YAML parser and hands `writeConcept` a Frontmatter object, which the platform renders in its own canonical form); `type` and `title` present; every relative `.md` link resolves inside the tree; every `verified` event carries `human:<email>` of a member of the workspace; no file sits at a reserved path; no two files derive the same merge key. Any failure refuses the run naming the file and the reason, and nothing has been written.
- `index.md` and `log.md` at any level are skipped, never refused.

### The manifest, first

- `knowledge/manifest.yaml` is written as the bundle's first commit through a new governed act, `writeManifest`, in the concepts slice: the repository lock, one commit, one audit event, one `bundle_commit` row, so the watermark advances. The reconciler learns to recognise a manifest commit and land its commit row without a concept; today it would stop on it as unreadable.
- The manifest's shape is a zod schema in the schema package carrying ADR 0002's keys: `id` (minted once for the bundle, a ULID), `origin` (`company`), `ref` (what the bundle was made from — the four library titles and versions and the review date, from the bundle's log), `owner` (the company's name), `content_version` (a date-stamped version). The loader refuses a tree whose manifest already stands with a different id.
- ADR 0014's `bundle` record, derived from the manifest, does not exist yet and is not built here.

### Pass one: concepts

- Files land in path order so a rerun and a replay agree. For each: kind from `type`; title from `title`; merge key derived as the reconciler derives it (kind and folded title); path as in the tree under `knowledge/`; frontmatter as parsed, with `verified[].by` rewritten from `human:<email>` to `human:<person id>` and `sources[]` kept as the file's projection; body verbatim; status `stable`; sensitivity from the flag; evidence empty, because the libraries are not source documents of the workspace; author the running member; message naming the path and the library entry.
- A `path-taken` refusal is a skip, counted, not an error. Any other refusal stops the run at that file with the reason; what landed stays, since each write is its own commit and audit row, and a rerun continues from there.
- After each landed concept the file's `verified` events are recorded as imported checks: one verification row per event with actor `human:<person id>`, `checked_at` the event's `at`, `content_hash` null and origin `imported` — the shape the trust words already read as *Checked by … · imported*. One audit event per check, `knowledge.check.imported`, under the run's batch id. A rerun does not duplicate a check the concept already holds for that actor and instant.

### Pass two: links

- With every path's IRI known, each concept whose body carries a relative link is rewritten: the link's target becomes the IRI, its text untouched. The rewrite is a governed write with the IRI set and `expects: { base: <pass one's content hash> }`, the same path, kind, title and frontmatter; a stale precondition stops the run naming the file.
- The graph resolves link targets by IRI already; its path resolution stays so a bundle written by hand still maps.
- Pass two is idempotent: a body with no relative link left is skipped.

### Principal and actor

- The member named by `--as` must be an Admin or Editor; a Viewer refuses with `role-forbids`. The commit author is that member's name and email; the trailer actor is their person id. The verifier need not be the running member: each `verified.by` email is looked up among the workspace's members and refused if absent, the line telling the operator to invite them first.

### Words and docs

- CONTEXT.md gains no term: *imported bundle* is a vendor's read-only bundle and stays; this is the company's own bundle brought in through the ordinary write. The ops runbook under `docs/operations/` gains the command. The route table's C1 row gains a line naming this ticket when it lands.

## Testing Decisions

### Seams, highest first

- **The ops runner.** `runOps` with a served app, a throwaway git store and a provisioned workspace, as the ops suite does today. Run `import-bundle` over a fixture bundle in the client bundle's shape (two domains; a split tier pair with its two Tier concepts; one cross-domain link; one link between split concepts; one file with two `verified` events), then read back what the operator and the reader see: the lines and exit code; the concept index rows (kind, title, path, sensitivity, status); the files in the repository (no email anywhere, an IRI in every link, the manifest present and first); the verification rows (origin imported, null hash); the ledger (one commit act per concept, one check act per event, the manifest's act); `find` and `open` over the concepts with the trust words and the rider. Then the rerun: the same command lands nothing and says so. Then `reconcile-watermark`: replays nothing and stops nowhere.
- **The core act.** `importBundle` in the core suite, beside the erasure rehearsal's test, for the refusal table: a verifier who is not a member; a link outside the tree; a reserved path; two files with one merge key; a Viewer running it; a manifest already present with another id; a stale precondition in pass two; a dry run. Each proves nothing was written past the refusal.
- A good test here reads only what the operator and the reader see — lines, exit codes, rows, files, trust words — never the loader's internals.

### Infrastructure

- The fixture bundle lives with the api's test fixtures, small, its files in the client bundle's shapes with invented text; the real bundle never enters the tree.
- No mutation-gate change; the ops slice already runs under the same `check`.

### Prior art

- The ops suite (the erasure rehearsal seeds a concept through `writeConcept` and reads the ledger; reconcile-watermark restores rows from commits); the erasure rehearsal's core test for the act's shape; the suggestions test for reading verification rows.
