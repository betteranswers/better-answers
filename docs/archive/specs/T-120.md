
## Known hazards

**H1 — ADR 0031 does change. Settled by the orchestrator, 10/09/2026.** The ticket's *No ADR changes here* refers to the S0 spec's own ADRs (0020 and 0022, T-124's and T-125's). **H2 — the rules-in-force column's shape. Settled by the orchestrator, 10/09/2026.** The unit is the **tier**, not the category: `rules_in_force jsonb NOT NULL DEFAULT '{"default_on": true, "default_off": false}'::jsonb`, bounded at the boundary to exactly those two boolean keys the way `job.outcome` is refined. The **always** tier has no key because no binding switches it off. The default is then literally the safe set the ticket names, and the category list stays out of the migration. S1's HR-shaped seeding is one flip of `default_off`.

**H3 — the retention tail's type. Settled by the orchestrator, 10/09/2026:** `retention_tail` nullable `text`, as proposed.

**H4 — migration ordering.** `suppression` keys to `erasure_request`, which keys to `subject_request`; `finding` keys to `source_document`. The four `generate` runs therefore go `finding`, `subject_request`, `erasure_request`, `suppression` — not the ticket's descriptive order.

**H5 — `worker_rt` holds default DML on every new `public` table.** Verified: `packages/schema/migrations/0000_substrate.sql:36` reads `ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO app_rt, worker_rt;` — which is why `0011_groups-substrate.sql` has to `REVOKE ALL … FROM worker_rt` for two ordinary new tables. So all four substrates **revoke explicitly**, and `finding`'s then re-grants `INSERT` alone. A missing revoke is a silent full-DML grant to the worker, and acceptance 3 is the only thing that would catch it.

**H6 — `FORCE ROW LEVEL SECURITY` has no Drizzle API.** Every table needs its hand-written substrate line or the RLS coverage test fails; `withRLS()`'s docblock says so.

**H7 — the two document scans** (`apps/api/tests/coding-rules-tags.test.ts`, `apps/api/tests/adr-index.test.ts`) run after **any** documentation edit, including C1's and the route row's.

**H8 — `contract_version` and the manifest do not merge.** This ticket runs alone until it lands (`docs/agents/build-loop.md`, *Migrations serialise*). Both `SPOKEN_CONTRACT_VERSION` constants are hardcoded per tier deliberately; changing one and not the other is the mechanism working, not a bug to route around.
